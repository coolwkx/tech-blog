# 面向对象编程
> **一句话总结**：类是"模板 + 行为"的封装单位，对象是按模板造出的实例；掌握封装 / 继承 / 多态这三条主线，再理解"赋值是别名、浅拷贝一层、深拷贝到底"，就能读懂绝大多数 Python 工程代码。
> **前置知识**：函数与参数传递（02 篇）、可变 vs 不可变类型与对象身份 `id`（01 篇）、元组拆包。

> 1. 用 `class` 写出带构造、属性、方法、`__str__` 的完整类，并说清 `self` 到底是什么；
> 2. 正确使用单继承 / 多继承 / `super` / 方法重写，能读懂 `__mro__` 并解释多继承时"用哪个父类的方法"；
> 3. 区分"赋值 / 浅拷贝 / 深拷贝"三种数据共享方式，并知道什么时候必须用 `copy.deepcopy`。

## 1. 核心概念
### 1.1 面向过程 vs 面向对象
| 维度 | 面向过程 | 面向对象 |
| --- | --- | --- |
| 关注点 | 步骤/流程 | 对象及其职责 |
| 代码组织 | 一串函数互相调用 | 数据 + 操作数据的方法打包成类 |
| 扩展方式 | 改流程、加分支 | 加子类、重写方法 |
| 适合 | 简单的线性任务 | 需求复杂、会长期演化的系统 |

Python 两种都支持。**面向对象不是"更高级"，而是当"数据"和"操作数据的行为"需要长期绑在一起时才更划算**。

### 1.2 类与对象：模板与实例
| 概念 | 说明 | 代码 |
| --- | --- | --- |
| 类 class | 抽象模板，描述"这类事物有什么" | `class Car: ...` |
| 对象 / 实例 object | 按模板造出的具体实体 | `car = Car` |
| 属性 attribute | 对象的固有特征（用变量表示） | `self.color = "red"` |
| 方法 method | 对象的行为（定义在类里的函数） | `def run(self): ...` |
| 实例化 | 调用类名创建对象的过程 | `Car` 内部会调用 `__init__` |

`self` 是**第一个形参**，Python 在调用 `obj.method(...)` 时自动把 `obj` 作为第一个实参传进去。所以：

- 类外部访问属性：`对象名.属性名`；
- 类内部访问属性/方法：`self.属性名` / `self.方法名`；
- `self` 的名字是约定，不是关键字，但**强烈建议不要改**。

### 1.3 `__init__` / `__str__` / `__del__` 三个最常用的魔法方法
魔法方法（magic method / dunder method）以双下划线包围，**由解释器在特定时机自动调用**，不需要手动写。

| 魔法方法 | 触发时机 | 典型用途 |
| --- | --- | --- |
| `__init__(self, ...)` | 对象创建后立即调用 | 初始化实例属性 |
| `__new__(cls, ...)` | 更早，负责"创建"对象本体 | 单例、不可变类型子类化（进阶） |
| `__str__(self)` | `print(obj)` / `str(obj)` / f-string | 给人看的可读表示 |
| `__repr__(self)` | 交互式环境直接输入对象、`repr(obj)` | 给开发者看的、尽量能重建对象 |
| `__del__(self)` | 对象引用计数归零、程序退出时 | 释放外部资源（但**不要依赖它**） |
| `__eq__` / `__hash__` | `==` / `hash` | 值语义比较、放进 set |
| `__len__` / `__getitem__` | `len(obj)` / `obj[i]` | 让自定义对象"像序列" |
```python
class Car:
    def __init__(self, color, number): # 创建对象时自动调用
        self.color = color
        self.number = number

        def __str__(self): # print(car) 时自动调用
            return f"车的颜色:{self.color},轮胎个数:{self.number}"

        print(Car("Red", 4)) # 车的颜色:Red,轮胎个数:4
```
> `__del__` 的定位：它由**垃圾回收**触发，触发时机不确定（循环引用时甚至可能不触发）。真正要"确保释放"的资源（文件、连接）请用 `with` 上下文管理器（04 篇），不要写 `__del__`。

### 1.4 属性：类属性 vs 实例属性
| 维度 | 类属性 | 实例属性 |
| --- | --- | --- |
| 定义位置 | 类体里、方法外 | 通常在 `__init__` 中用 `self.x = ...` |
| 存放位置 | `类.__dict__` | `实例.__dict__` |
| 共享性 | 所有实例共享一份 | 每个实例各一份 |
| 读取顺序 | 先查实例 `__dict__`，没有才查类 | 同上 |
| 写入 | `类名.属性 = v` 改的是类 | `self.属性 = v` **新建**实例属性 |
```python
class Person:
    count = 0 # 类属性
    def __init__(self, name):
        self.name = name
        Person.count += 1

        a, b = Person("A"), Person("B")
        a.count = 99 # 注意：这是在实例上新建属性，没有改类属性
        print(Person.count, a.count, b.count) # 2 99 2
```
**结论**：想改"共享的"值必须写 `类名.属性 = v`；`self.属性 = v` 永远只影响当前实例。这一条也是"可变类属性"风险最大的地方（见常见坑）。

### 1.5 三大特性一览
| 特性 | 一句话 | 实现手段 | 好处 |
| --- | --- | --- | --- |
| 封装 encapsulation | 把数据和行为打包，隐藏实现细节 | `_x` 约定私有、`__x` 名称改写、`@property` | 简化调用、防止误改、便于重构 |
| 继承 inheritance | 子类复用父类的属性和方法 | `class Son(Father)` | 减少重复代码（is-a 关系） |
| 多态 polymorphism | 同一调用形式，不同对象给出不同行为 | 方法重写 + 父类"接口" | 解耦、可扩展 |

### 1.6 继承：单继承、多继承、MRO
```python
class Father(object): ... # Python 3 中 (object) 可省略，所有类默认继承 object
class Son(Father): ... # 单继承
class Son(Father, Mother): ... # 多继承
```
| 术语 | 含义 |
| --- | --- |
| 父类 / 基类 base class | 被继承的类 |
| 子类 / 派生类 derived class | 继承得到的类 |
| 重写 override | 子类定义了与父类同名的方法/属性 |
| 多层继承 | 类 → 子类 → 孙子类 的链条 |
| MRO | Method Resolution Order，方法解析顺序 |

**多继承时用哪个父类的同名方法？** 按 **MRO** 顺序，即"深度优先 + 从左到右"再经过 C3 线性化：
```python
class School: ...
class Master: ...
class Prentice(School, Master): ...

print(Prentice.__mro__)
# (<class 'Prentice'>, <class 'School'>, <class 'Master'>, <class 'object'>)
```
所以 `Prentice` 会优先用 `School` 的实现。**不要靠猜测，用 `类名.__mro__` 或 `类名.mro` 打印出来看。**

**调用父类方法的两条路：**

| 方式 | 写法 | 特点 |
| --- | --- | --- |
| 显式指父类 | `Father.__init__(self)` / `Father.make_cake(self)` | 直观，但硬编码父类名，改继承结构要一起改 |
| `super` | `super.__init__` | 沿 MRO 找**下一个**类，配合多继承/菱形继承才正确 |
```python
class Prentice(School):
    def __init__(self):
        self.kongfu = "[独创煎饼果子技术]"
        def make_old_cake(self):
            super.__init__ # 让父类初始化（会覆盖 self.kongfu）
            super.make_cake # 调用父类的同名方法
```
> 注意 `super.__init__` 可能**覆盖子类刚设好的属性** —— 上面的例子里 `self.kongfu` 最终会变成 `[煎饼果子配方]`。这是初学阶段一个真实存在的"结果与预期不符"的来源：先用 `super.__init__`，再设置子类自己的属性。

### 1.7 封装：私有属性与私有方法的真相
Python **没有真正的私有**，只有两个约定：

| 写法 | 名称 | 外部能访问吗 | 机制 |
| --- | --- | --- | --- |
| `name` | 公有 | ✅ | 普通属性 |
| `_name` | 单下划线"受保护" | ✅（但约定别碰） | 仅约定，提示"内部使用" |
| `__name` | 双下划线 | ⚠️ 不能按原名访问 | **名称改写**为 `_类名__name` |
| `__name__` | 双下划线且结尾也双 | ✅ | 系统保留名，不要自造 |
```python
class Wallet:
    def __init__(self, money):
        self.__money = money # 实际存成 _Wallet__money
        def get_money(self):
            return self.__money

        w = Wallet(100)
        print(w.get_money) # 100
        # print(w.__money) # AttributeError
        print(w._Wallet__money) # 100 ← "私有"只是改了名字，并非访问不到
```
名称改写的**真正目的**不是安全，而是防止子类意外覆盖父类的内部属性。子类里写 `self.__money = x` 会变成 `_子类名__money`，与父类的 `_父类名__money` 是两个不同的属性，互不干扰。

标准的读写接口是 `get_xx` / `set_xx`，Pythonic 的写法是 `@property`（见 06 篇）。

### 1.8 多态：同一接口，不同实现
多态的成立条件（的三条）：

1. 有继承（定义父类与子类）；
2. 有方法重写（子类重写父类方法）；
3. 父类引用指向子类对象（把子类实例传给以父类为"接口"的调用者）。
```python
def object_play(hero, enemy): # 平台/框架：只依赖 power 与 attack 两个约定
    if hero.power > enemy.attack:
        print("英雄战机胜利,敌机失败")
    else:
        print("英雄战机失败,敌机胜利")

        object_play(HeroFighter, EnemyFighter) # 一代战机：失败
        object_play(AdvHeroFighter, EnemyFighter) # 二代战机：胜利
```
**多态的价值**：`object_play` 一行都不用改，就能接纳未来任何人写的"英雄战机"。这就是"**对扩展开放、对修改关闭**"，也是反复强调的"解耦合"。

**抽象类（接口）**：父类里把方法体写成 `pass`，只规定"必须有什么方法"，由子类实现。工业级写法用 `abc` 模块强制约束：
```python
from abc import ABC, abstractmethod

class Hero(ABC):
    @abstractmethod
    def power(self): ...

    # Hero # TypeError: 抽象类不能实例化
    class AdvHero(Hero):
        def power(self):
            return 80
```
用 `abc` 的好处：**忘记实现抽象方法的子类在实例化时就直接报错**，而不是等到运行时才炸。

### 1.9 实例方法 / 类方法 / 静态方法
| 类型 | 定义 | 第一个参数 | 调用方式 | 典型用途 |
| --- | --- | --- | --- | --- |
| 实例方法 | `def m(self, ...)` | `self`（实例） | `obj.m` | 绝大多数业务方法 |
| 类方法 classmethod | `@classmethod` + `def m(cls, ...)` | `cls`（类） | `Cls.m` / `obj.m` | 工厂方法、替代构造函数 |
| 静态方法 staticmethod | `@staticmethod` + `def m(...)` | 无 | `Cls.m` / `obj.m` | 与类相关的工具函数 |
```text
class Dog:
 species = "犬科"
 def __init__(self, name):
 self.name = name

 @classmethod
 def create(cls, name):
 return cls(name) # 写 cls 而不是 Dog，子类调用时才能拿到子类

 @staticmethod
 def bark:
 return "汪汪"

print(Dog.create("旺财"), Dog.species, Dog.bark) # Dog(旺财) 犬科 汪汪
```
判断标准：**要不要用到实例数据（`self`）→ 实例方法；要不要用到类数据或需要返回本类实例 → 类方法；两者都不需要 → 静态方法。**

### 1.10 赋值 / 浅拷贝 / 深拷贝
三种"复制"的差别只在一件事上：**内层子对象是否也被复制**。

| 操作 | 代码 | 第 1 层 | 第 2 层及更深 | 内存开销 |
| --- | --- | --- | --- | --- |
| 赋值（别名） | `b = a` | 同一个对象 | 共享 | 0 |
| 浅拷贝 | `copy.copy(a)` / `a.copy` / `a[:]` | 新对象 | **共享** | 小 |
| 深拷贝 | `copy.deepcopy(a)` | 新对象 | **递归新建** | 大 |
```python
import copy

inner = [1, 2, 3]
c = [6, 7, inner]

shallow = copy.copy(c)
deep = copy.deepcopy(c)

print(c is shallow, c is deep) # False False 第 1 层都是新对象
print(c[2] is shallow[2], c[2] is deep[2]) # True False 第 2 层：浅拷贝共享，深拷贝独立

inner[0] = 99
print(c, shallow, deep)
# [6, 7, [99, 2, 3]] [6, 7, [99, 2, 3]] [6, 7, [1, 2, 3]]
```
**一个容易被忽略的细节**：`copy.copy` 对**不可变对象**（如 `tuple`、`str`、`int`）通常直接返回原对象本身，因为既然不可变就没有复制的必要 —— 所以 `copy.copy((1,2,3)) is (1,2,3)` 往往为 `True`。深拷贝对不可变对象同样"就地引用"。这说明拷贝函数的策略是"**只对可能被改动的部分下功夫**"。

## 2. 最小可运行示例
一段综合了继承、多态、类属性、`__str__`、深浅拷贝的完整示例：
```python
import copy
from abc import ABC, abstractmethod

# ---------- 1) 抽象基类：定义"接口标准" ----------
class Fighter(ABC):
    """所有战机的抽象父类，只规定'必须能报出战斗力'"""

    total = 0 # 类属性：所有子类共享

    def __init__(self, name, power):
        self.name = name # 实例属性
        self.__power = power # 私有属性，外部读不到原名
        Fighter.total += 1

        # 供子类/外部读取私有属性的公共接口
        def power(self):
            return self.__power

        @abstractmethod
        def attack(self):
            """子类必须实现"""

            def __str__(self):
                return f"{self.name}(战斗力={self.power})"

            # ---------- 2) 子类继承 + 重写 ----------
            class HeroFighter(Fighter):
                def attack(self):
                    return self.power

                class AdvHeroFighter(HeroFighter):
                    def attack(self):
                        return self.power * 2 # 重写：二代机攻击翻倍

                    class EnemyFighter(Fighter):
                        def attack(self):
                            return self.power

                        # ---------- 3) 多态：平台代码只依赖抽象接口 ----------
                        def object_play(hero: Fighter, enemy: Fighter):
                            print(f"{hero} VS {enemy} -> ", end="")
                            if hero.attack > enemy.attack:
                                print("英雄胜")
                            else:
                                print("英雄败")

                                if __name__ == "__main__":
                                    enemy = EnemyFighter("敌机", 70)
                                    object_play(HeroFighter("一代机", 60), enemy) # 英雄败
                                    object_play(AdvHeroFighter("二代机", 80), enemy) # 英雄胜

                                    print("战机总数:", Fighter.total) # 3
                                    print("MRO:", [c.__name__ for c in AdvHeroFighter.__mro__])
                                    # ['AdvHeroFighter', 'HeroFighter', 'Fighter', 'ABC', 'object']

                                    # ---------- 4) 深浅拷贝 ----------
                                    squad = [["一代机"], ["二代机"]]
                                    shallow = copy.copy(squad)
                                    deep = copy.deepcopy(squad)
                                    squad[0].append("坠毁")
                                    print("原:", squad) # [['一代机', '坠毁'], ['二代机']]
                                    print("浅:", shallow) # [['一代机', '坠毁'], ['二代机']] ← 受影响
                                    print("深:", deep) # [['一代机'], ['二代机']] ← 不受影响
```
真实运行输出：
```text
一代机(战斗力=60) VS 敌机(战斗力=70) -> 英雄败
二代机(战斗力=80) VS 敌机(战斗力=70) -> 英雄胜
战机总数: 3
MRO: ['AdvHeroFighter', 'HeroFighter', 'Fighter', 'ABC', 'object']
原: [['一代机', '坠毁'], ['二代机']]
浅: [['一代机', '坠毁'], ['二代机']]
深: [['一代机'], ['二代机']]
```
**关键点说明**

| 位置 | 关键点 |
| --- | --- |
| `class Fighter(ABC)` | 抽象基类不能直接实例化，`@abstractmethod` 强制子类实现 |
| `self.__power` | 被改写为 `self._Fighter__power`，子类同名属性互不冲突 |
| `Fighter.total += 1` | 改类属性必须用**类名**，用 `self.total += 1` 会新建实例属性 |
| `hero: Fighter` 类型注解 | 只是提示，不是强制；多态真正依赖的是"有没有 `attack`" |
| `AdvHeroFighter.__mro__` | 打印出来才知道方法查找顺序，含 `ABC` 说明元类参与 |
| `copy.copy` vs `deepcopy` | 浅拷贝只复制外层容器，内层列表仍共享 |

## 3. 常见坑
| 坑 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| 忘记写 `self` | `TypeError: run takes 0 positional arguments but 1 was given` | 实例方法第一个参数必须是 `self` | `def run(self):` |
| 定义方法时漏了 `self` 参数但用到了属性 | `NameError: name 'color' is not defined` | 属性必须通过 `self.` 访问 | 统一写 `self.color` |
| 在 `__init__` 里用可变类属性 | 多个实例"共享"了同一个列表 | 类属性只有一份，`self.lst.append()` 改的是共享对象 | 在 `__init__` 里 `self.lst = []` 新建实例属性 |
| `self.count += 1` 想改类属性 | 类属性没变，反而多了实例属性 | `+=` 对不可变类型等价于 `self.count = self.count + 1` | 写 `类名.count += 1` |
| 私有属性外部访问 | `AttributeError: 'Wallet' object has no attribute '__money'` | 名称已被改写为 `_Wallet__money` | 通过 `get_xx` / `@property` 访问 |
| 子类 `__init__` 忘了调父类 | 父类定义的属性不存在，报 `AttributeError` | 子类 `__init__` 覆盖了父类的 | 在子类 `__init__` 里先 `super.__init__(...)` |
| `super.__init__` 位置放错 | 子类自己的属性被父类初始化覆盖 | 父类 `__init__` 也在写同名属性 | 先 `super.__init__`，再设置子类属性 |
| 多继承找不到预期的方法 | 调用到了"不是想的那个"父类实现 | 按 MRO 顺序查找第一个同名方法 | `print(Cls.__mro__)` 确认顺序，或用 `super` |
| 用 `is` 比较对象值 | 两个内容相同的对象 `is` 为 `False` | 默认 `__eq__` 比较身份 | 自定义 `__eq__`（同时记得写 `__hash__`） |
| 只重写 `__eq__` 没重写 `__hash__` | 对象放进 set/dict 行为异常 | `__hash__` 被隐式设为 `None` | 值对象要么整体不可变并同时实现两者，要么用 `@dataclass(frozen=True)` |
| `b = a` 以为是拷贝 | 改 `b` 的属性影响 `a` | 赋值只是绑定同一个对象 | 要独立副本用 `copy.copy` / `deepcopy` |
| 浅拷贝当深拷贝用 | 改了嵌套列表，原数据也变了 | `copy` 只复制第一层 | 嵌套结构一律 `copy.deepcopy` |
| `__del__` 里做清理 | 有时执行有时不执行 | 依赖 GC 时机，循环引用时不可靠 | 用 `with` 上下文管理器 / `try...finally` |
| 类名与方法参数同名混淆 | `Prentice.make_cake(self)` 报参数错 | 用类名直接调方法必须手动传 `self` | 优先用 `super.make_cake` |
| 用类属性当"默认值缓存" | 所有实例互相污染 | 可变类属性是共享状态 | 实例级数据放 `__init__`，真正共享的放类属性并只读 |

## 4. 面试问答
<details markdown="1">
<summary markdown="1"><strong>Q1：Python 的"私有属性"是真的私有吗？`self.__x` 和 `self._x` 有什么区别？</strong></summary>

不是真的私有。

- `self._x`（单下划线）只是**团队约定**，表示"内部使用，请勿直接访问"，解释器不做任何限制；
- `self.__x`（双下划线，且结尾不超过一个下划线）会触发**名称改写（name mangling）**：在类 `Wallet` 里写成 `self._Wallet__x`。所以外部仍能用 `obj._Wallet__x` 访问到，只是不能再写 `obj.__x`。

改写的真正目的**不是安全，而是避免继承冲突**：父类用 `self.__x`、子类也用 `self.__x` 时，两者会变成 `_Father__x` 和 `_Son__x`，互不覆盖。如果需要"必须实现某接口"的强约束，应该用 `abc.ABC` + `@abstractmethod`，或 `typing.Protocol`。

</details>

<details markdown="1">
<summary markdown="1"><strong>Q2：多继承时 Python 如何决定用哪个父类的方法？`super` 到底做了什么？</strong></summary>

按 **MRO（Method Resolution Order）** 决定，计算规则是 **C3 线性化**，效果近似"从左到右的深度优先，但每个类的共享祖先只保留最后一次出现"。可以直接打印：`Cls.__mro__` 或 `Cls.mro`。对 `class P(School, Master)`，顺序是 `P → School → Master → object`，因此同名方法优先用 `School` 的。

`super` 不是"父类对象"，而是"**在实例的 MRO 上，从当前类往后找下一个类**"。它有两个关键性质：① 依赖运行时的实例类型，因此在多继承/菱形继承下能正确地把调用链传递下去（协作式多继承）；② 在类方法里写 `super` 不需要参数，Python 会自动补上当前类和 `self`/`cls`。

实践建议：单继承下 `super.__init__` 是标准写法；多继承时所有参与类都应当调用 `super.__init__` 才能把链条走完。用"类名.方法(self)"的硬编码方式在多继承里很容易重复或漏调。

</details>

<details markdown="1">
<summary markdown="1"><strong>Q3：`a = [1, [2, 3]]`，`b = a`、`c = copy.copy(a)`、`d = copy.deepcopy(a)` 三者有什么区别？改 `a[1].append(4)` 之后谁受影响？</strong></summary>

- `b = a`：只是给同一个列表起了第二个名字，`b is a` 为 `True`；
- `c = copy.copy(a)`：新建了外层列表，但元素仍是原引用，`c is a` 为 `False`、`c[1] is a[1]` 为 `True`；
- `d = copy.deepcopy(a)`：递归创建所有层级的副本，`d[1] is a[1]` 为 `False`。

执行 `a[1].append(4)` 后：`b` 和 `c` 都能看到 `4`（它们共享同一个内层列表），`d` 看不到。

补充：`deepcopy` 用 memo 字典处理循环引用，所以能安全复制自引用结构；但它会调用对象的 `__deepcopy__` / `__reduce__`，对文件句柄、socket、锁这类"不可复制"的对象会失败，需要在自定义类里实现 `__deepcopy__`。

</details>

## 5. 自测题
<details markdown="1">
<summary markdown="1">1. 下面代码输出什么？为什么？</summary>

```python
class A:
    items = []

    def add(self, x):
        self.items.append(x)

        a, b = A, A
        a.add(1)
        print(b.items())
```
输出 `[1]`。`items` 是**类属性**，`A.items()` 只有一份列表，`a` 和 `b` 都指向它。`self.items.append(x)` 是对"取到的那个列表对象"做原地修改，并没有在实例上新建属性，所以 `b` 也看得见。正确做法是在 `__init__` 里写 `self.items() = []`。

</details>

<details markdown="1">
<summary markdown="1">2. `super.__init__` 和 `Father.__init__(self)` 有什么区别？各在什么场景下用？</summary>

`Father.__init__(self)` 是**硬编码**：直接调用指定类的实现，绕过 MRO，只能沿着一条确定的链条走。`super.__init__` 是**动态**的：从当前类在实例 MRO 上的下一个类开始查找，因此：

- 单继承时两者效果相同，但 `super` 改继承结构时不用改代码；
- 多继承（尤其菱形继承）时必须用 `super` 才能保证每个父类的 `__init__` 恰好被调用一次，形成协作链；
- 类方法/静态方法中也要用 `super`。

**不推荐**用"类名.方法(self)"，除非你**明确**只想调用某一个特定父类的实现（例如 `make_master_cake` 那种"我要师傅的配方"的刻意选择）。

</details>

<details markdown="1">
<summary markdown="1">3. 什么时候必须用深拷贝？</summary>

当"被复制的对象内部还嵌套着可变对象，且你希望副本与原件完全独立"时必须用 `copy.deepcopy`。典型场景：① 配置模板初始化（模板里有嵌套的 list/dict，浅拷贝会让所有实例共享子对象）；② 保存函数/方法入口的快照以便回滚；③ 把一份数据同时交给多个会修改它的模块处理。

反之，如果对象只包含不可变元素（如 `[1, 2, 3]`），`copy` 就够了，`deepcopy` 只是白白多花时间。深拷贝的开销是 O(整个对象图)，在热路径上要谨慎。

</details>

<details markdown="1">
<summary markdown="1">4. 类方法和静态方法都能用类名调用，为什么还要区分？</summary>

区别在**参数与语义**：

- `@classmethod` 的第一个参数是 `cls`，因此**知道自己是哪个类**，可以 `return cls(...)` 造出正确的子类实例 —— 这是"替代构造函数/工厂方法"的标准做法（如 `dict.fromkeys`、`datetime.now`）；
- `@staticmethod` 没有隐式参数，本质就是"放在类命名空间里的普通函数"，既不用实例也不用类，放进来只是为了**归类和便于发现**（如 `Game.show_menu`）。

选择标准：需要 cls → 类方法；只是逻辑上属于这个类 → 静态方法；需要 self → 实例方法。

</details>
