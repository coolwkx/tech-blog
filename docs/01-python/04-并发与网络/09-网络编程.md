# 网络编程
> **一句话总结**：TCP 编程就是"三要素（IP / 端口 / 协议）找到对方，用 socket 的固定流程建立连接，然后在**字节流**上收发 `bytes`"；由于 TCP 没有消息边界，要传结构化数据就必须自己设计协议（长度前缀 / 分隔符）。
> **前置知识**：函数与异常（02、04 篇）、`with` 与文件读写（04 篇）、多线程（08 篇，用于多客户端）。

> 1. 独立写出 TCP 服务端与客户端程序，说清 `bind` / `listen` / `accept` / `connect` 各自的作用与返回值；
> 2. 解释三次握手、四次挥手，以及"为什么连接需要三次、断开需要四次"；
> 3. 诊断并解决粘包问题，实现一个带文件名和长度头的文件上传协议；
> 4. 用多线程让服务端同时服务多个客户端，并正确处理客户端下线（`recv` 返回 `b''`）。

## 1. 核心概念
### 1.1 网络编程三要素
| 要素 | 作用 | 类比 | 查看/命令 |
| --- | --- | --- | --- |
| IP 地址 | 网络中**设备**的唯一标识 | 小区门牌号 | `ipconfig`（Windows）/ `ifconfig`（Linux/macOS） |
| 端口号 | 设备上**进程**的标识，0~65535 | 教室的门 | `netstat -ano`（Windows）/ `netstat -anp`（Linux） |
| 协议 | 通信双方遵守的规则 | 都说普通话 | — |

**端口号分区**：

| 区段 | 名称 | 说明 |
| --- | --- | --- |
| 0 ~ 1023 | 知名端口 / 特权端口 | 已被系统或标准服务占用（80 HTTP、443 HTTPS、22 SSH），普通程序不加权限用不了 |
| 1024 ~ 49151 | 注册端口 | 常见第三方服务 |
| 49152 ~ 65535 | 动态/私有端口 | 客户端临时端口通常从这里分配，自己练习推荐用这一段或直接用 8000+ |

**IP 的特殊地址**：`127.0.0.1` 是本地回环（loopback），永远指向本机，用来做本机测试；`0.0.0.0` 在 `bind` 时表示"监听所有网卡"；`bind` 时传空字符串 `""` 等价于 `0.0.0.0`。

### 1.2 TCP vs UDP
| 维度 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠：确认、重传、去重、按序 | 不可靠：可能丢包、乱序、重复 |
| 传输形式 | 字节流（IO 流），无大小上限 | 数据报包，单包 ≤ 64 KB |
| 效率 | 相对低（有握手、确认、拥塞控制） | 相对高 |
| 角色 | 区分客户端 / 服务端 | 只有发送端 / 接收端 |
| 生活类比 | 打电话 | 群聊/发短信 |
| 典型应用 | 网页、文件下载、数据库、SSH | 直播、音视频通话、DNS、游戏 |

**判断用哪个**：能容忍偶尔丢一帧但要求低延迟 → UDP；不能丢数据（转账、下载、配置下发）→ TCP。

### 1.3 三次握手与四次挥手
**三次握手（建立连接）**：

| 步骤 | 方向 | 内容 | 目的 |
| --- | --- | --- | --- |
| 1 | 客户端 → 服务端 | `SYN`（随机序号 x） | 我要建立连接 |
| 2 | 服务端 → 客户端 | `SYN + ACK`（x+1, 随机序号 y） | 收到你的，我也准备好了 |
| 3 | 客户端 → 服务端 | `ACK`（y+1） | 收到你的确认，开始传输 |

**为什么是三次而不是两次？** 两次的话，服务端无法确认"客户端收到了我的 SYN/ACK"：如果客户端早已关闭，服务端却已建立连接，就会白白占用资源（且历史失效连接请求可能造成脏连接）。第三次让**双方都确认了对方的收发能力**。

**四次挥手（断开连接）**：TCP 是全双工的，两个方向要分别关闭。

| 步骤 | 方向 | 内容 |
| --- | --- | --- |
| 1 | A → B | `FIN`：我这边没有数据要发了 |
| 2 | B → A | `ACK`：收到（此时 A→B 已关闭，B→A 仍可发数据，叫**半关闭**） |
| 3 | B → A | `FIN`：我这边也没数据了 |
| 4 | A → B | `ACK`：收到，连接彻底关闭 |

**为什么是四次？** 因为 A 发 `FIN` 后，B 可能还有数据没发完，所以"确认"和"我也关闭"不能合并，必须分两次。主动关闭方会进入 `TIME_WAIT` 状态等待 2MSL，这也是**服务端重启后端口被占用 1~2 分钟**的原因。

### 1.4 str 与 bytes：网络只认字节
网络上传输的一切都是 `bytes`。

| 方向 | 方法 | 示例 |
| --- | --- | --- |
| `str` → `bytes` | `s.encode("utf-8")` | `"你好".encode` → `b'\xe4\xbd\xa0\xe5\xa5\xbd'` |
| `bytes` → `str` | `b.decode("utf-8")` | `b'\xe4\xbd\xa0\xe5\xa5\xbd'.decode` → `"你好"` |
| 字面量 | `b"hello"` | `b` 前缀表示 bytes |

**编码必须两端一致**，推荐统一 `utf-8`。一边用 `gbk` 一边用 `utf-8` 就会 `UnicodeDecodeError` 或乱码。

### 1.5 TCP 开发流程
**服务端（固定 7 步）**：

| 步骤 | 代码 | 关键点 |
| --- | --- | --- |
| 1 创建套接字 | `srv = socket.socket(AF_INET, SOCK_STREAM)` | `AF_INET`=IPv4，`SOCK_STREAM`=TCP |
| 2 端口复用 | `srv.setsockopt(SOL_SOCKET, SO_REUSEADDR, True)` | **必须在 bind 之前**，解决"Address already in use" |
| 3 绑定 | `srv.bind(("0.0.0.0", 8888))` | 参数是**一个元组**，不是两个参数 |
| 4 监听 | `srv.listen(128)` | 128 是等待队列长度（backlog），不是最大连接数 |
| 5 接受连接 | `conn, addr = srv.accept` | **阻塞**；返回一个**新套接字** `conn` 专门跟这个客户端通信 |
| 6 收发 | `conn.recv(1024)` / `conn.sendall(b"...")` | `recv` 阻塞，返回 `bytes` |
| 7 关闭 | `conn.close()`；`srv` 服务端一般不主动关 | 只关交互套接字 |

**客户端（固定 5 步）**：

| 步骤 | 代码 |
| --- | --- |
| 1 创建套接字 | `cli = socket.socket(AF_INET, SOCK_STREAM)` |
| 2 连接 | `cli.connect(("127.0.0.1", 8888))` |
| 3 发送 | `cli.sendall("你好".encode("utf-8"))` |
| 4 接收 | `data = cli.recv(1024)` |
| 5 关闭 | `cli.close()` |

**"被动套接字"与"交互套接字"的区别**（强调的重点）：

- `srv`（`accept` 之前的套接字）只负责**接收新连接**，不能收发业务消息；
- `conn`（`accept` 返回的套接字）才是**跟某个具体客户端**通信的通道；
- 关掉 `conn` 表示"和这个客户端聊完了"，关掉 `srv` 表示"整个服务不再接受新连接"。

### 1.6 关键 API 细节
| API | 语义与坑 |
| --- | --- |
| `recv(bufsize)` | 返回**至多** bufsize 字节，**不保证一次收完一条消息**；返回 `b''` 表示对端已关闭连接（这是判断下线的标准方式） |
| `send(data)` | 返回实际发送的字节数，**可能小于 len(data)**（发送缓冲区满），不保证发完 |
| `sendall(data)` | 循环发送直到全部发完，**推荐用这个** |
| `accept` | 返回 `(conn, addr)`，`addr` 是 `(ip, port)` 元组 |
| `settimeout(t)` | 设置阻塞超时，超时抛 `socket.timeout`（3.10+ 是 `TimeoutError` 的子类） |
| `SO_REUSEADDR` | 允许重用处于 `TIME_WAIT` 的地址，服务端调试必备 |
| `shutdown(SHUT_WR)` | 半关闭：只关闭写方向，仍可读（优雅结束"我发完了"） |
| `socket.timeout` | 超时异常；生产代码应该总是设置超时，避免永久阻塞 |

### 1.7 粘包：TCP 是字节流，没有"消息边界"
`send` 一次不代表 `recv` 一次。实测：
```text
客户端: cli.sendall(b"AAA"); cli.sendall(b"BBB")
服务端: recv(1024) -> b'AAABBB' ← 两条消息被合并
```
原因：TCP 只保证**字节顺序**，不保留应用层的消息边界。合并（粘包）与拆分（拆包）都可能发生，取决于发送缓冲区、Nagle 算法、MTU、接收窗口。

**三种解决方案**：

| 方案 | 做法 | 优缺点 |
| --- | --- | --- |
| 固定长度 | 每条消息定长，不足补齐 | 简单；浪费带宽，不适合变长文本 |
| 分隔符 | 用 `\n` 或自定义分隔符切分 | 简单；消息内容不能含分隔符，需要转义 |
| **长度前缀** | 先发 4 字节长度，再发正文 | **推荐**：通用、无歧义，二进制也适用 |

长度前缀实现（本机实测可正确拆分三条变长消息）：
```python
import struct

def send_msg(sock, payload: bytes):
    sock.sendall(struct.pack("!I", len(payload)) + payload) # !I = 4 字节大端无符号整数

    def recv_exact(sock, n):
        buf = b""
        while len(buf) < n: # recv 可能收不满，必须循环
            chunk = sock.recv(n - len(buf))
            if not chunk:
                return None # 对端关闭
            buf += chunk
            return buf

        def recv_msg(sock):
            header = recv_exact(sock, 4)
            if header is None:
                return None
            (length,) = struct.unpack("!I", header)
            return recv_exact(sock, length)
```
### 1.8 短连接、长连接与多客户端
| 模式 | 说明 | 适用 |
| --- | --- | --- |
| 短连接 | 一次请求-响应后就关闭 socket | HTTP/1.0、简单查询 |
| 长连接 | 一个连接上多次交互，自行决定何时关闭 | 数据库连接、聊天、推送 |

**多客户端**：`accept` 循环一次只能服务一个客户端，且处理期间无法接受新连接。解决方案：

| 方案 | 说明 |
| --- | --- |
| 多线程（`threading.Thread`） | 每个 `conn` 起一个线程处理，简单直接（做法） |
| 多进程（`multiprocessing`） | 隔离性好，开销大 |
| `socketserver` / `asyncio` | 标准库封装好的服务端框架 |

**判断客户端下线**：`conn.recv` 返回 `b''`（长度为 0）就说明对端调用了 `close`。这是明确点出的注意点，也是写"在线用户列表"的基础。

## 2. 最小可运行示例

下面这段代码在**一个脚本**里同时跑服务端线程和客户端，可直接复制运行，覆盖最小 C/S、粘包现象、长度前缀协议、文件上传协议。

```python
import json
import os
import socket
import struct
import threading
import time

HOST = "127.0.0.1"

# ==================== A. 最小 C/S ====================
def server_once(port, results):
    srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, True) # 端口复用，必须在 bind 前
    srv.bind((HOST, port)) # 注意：一个元组参数
    srv.listen(5) # backlog
    conn, addr = srv.accept # 阻塞，返回交互套接字
    with conn:
        data = conn.recv(1024) # 最多 1024 字节
        results["recv"] = data.decode("utf-8")
        conn.sendall("服务端收到啦".encode("utf-8")) # sendall 保证发完
        srv.close()

        def demo_basic(port):
            results = {}
            threading.Thread(target=server_once, args=(port, results)).start()
            time.sleep(0.2)
            cli = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
            cli.connect((HOST, port))
            cli.sendall("你好，服务端".encode("utf-8"))
            print("客户端收到:", cli.recv(1024).decode("utf-8"))
            cli.close()
            time.sleep(0.2)
            print("服务端收到:", results["recv"])

            # ==================== B. 粘包现象 ====================
            def server_sticky(port, results):
                srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
                srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, True)
                srv.bind((HOST, port)); srv.listen(5)
                conn, _ = srv.accept
                with conn:
                    time.sleep(0.3) # 等两次 send 的数据都到达
                    results["raw"] = conn.recv(1024)
                    srv.close()

                    def demo_sticky(port):
                        results = {}
                        threading.Thread(target=server_sticky, args=(port, results)).start()
                        time.sleep(0.2)
                        cli = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
                        cli.connect((HOST, port))
                        cli.sendall(b"AAA") # 两次独立的 send
                        cli.sendall(b"BBB")
                        time.sleep(0.6)
                        cli.close()
                        time.sleep(0.2)
                        print("一次 recv 收到:", results["raw"]) # b'AAABBB' —— 粘包了

                        # ==================== C. 长度前缀协议（解决粘包的正解） ====================
                        def send_msg(sock, payload: bytes):
                            sock.sendall(struct.pack("!I", len(payload)) + payload) # !I = 4 字节大端无符号整数

                            def recv_exact(sock, n):
                                buf = b""
                                while len(buf) < n: # recv 可能收不满，必须循环
                                    chunk = sock.recv(n - len(buf))
                                    if not chunk:
                                        return None # b'' 表示对端已关闭
                                    buf += chunk
                                    return buf

                                def recv_msg(sock):
                                    header = recv_exact(sock, 4)
                                    if header is None:
                                        return None
                                    (length,) = struct.unpack("!I", header)
                                    return recv_exact(sock, length)

                                def server_framed(port, results):
                                    srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
                                    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, True)
                                    srv.bind((HOST, port)); srv.listen(5)
                                    conn, _ = srv.accept
                                    got = []
                                    with conn:
                                        for _ in range(3):
                                            msg = recv_msg(conn)
                                            if msg is None:
                                                break
                                            got.append(msg.decode("utf-8"))
                                            results["msgs"] = got
                                            srv.close()

                                            def demo_framed(port):
                                                results = {}
                                                threading.Thread(target=server_framed, args=(port, results)).start()
                                                time.sleep(0.2)
                                                cli = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
                                                cli.connect((HOST, port))
                                                for text in ["第一条", "第二条很长很长很长很长很长很长很长", "第三条"]:
                                                    send_msg(cli, text.encode("utf-8"))
                                                    cli.close()
                                                    time.sleep(0.3)
                                                    print("服务端完整收到:", results["msgs"])

                                                    # ==================== D. 文件上传：先发元信息，再发内容 ====================
                                                    def server_upload(port, save_dir, results):
                                                        srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
                                                        srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, True)
                                                        srv.bind((HOST, port)); srv.listen(5)
                                                        conn, _ = srv.accept
                                                        with conn:
                                                            meta = json.loads(recv_msg(conn).decode("utf-8")) # {"name": ..., "size": ...}
                                                            remaining = meta["size"] # 先知道该收多少字节
                                                            saved = os.path.join(save_dir, "uploaded_" + meta["name"])
                                                            with open(saved, "wb") as f: # 二进制写
                                                                while remaining > 0:
                                                                    chunk = conn.recv(min(1024, remaining))
                                                                    if not chunk:
                                                                        break
                                                                    f.write(chunk)
                                                                    remaining -= len(chunk)
                                                                    results["size"] = os.path.getsize(saved)
                                                                    conn.sendall(b"OK") # 回执
                                                                    srv.close()

                                                                    def demo_upload(port, save_dir):
                                                                        src = os.path.join(save_dir, "source.bin")
                                                                        with open(src, "wb") as f:
                                                                            f.write(os.urandom(3000)) # 造一个 3000 字节的文件

                                                                            results = {}
                                                                            threading.Thread(target=server_upload, args=(port, save_dir, results)).start()
                                                                            time.sleep(0.2)
                                                                            cli = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
                                                                            cli.connect((HOST, port))
                                                                            size = os.path.getsize(src)
                                                                            send_msg(cli, json.dumps({"name": "source.bin", "size": size}).encode("utf-8"))
                                                                            with open(src, "rb") as f:
                                                                                while True:
                                                                                    chunk = f.read(1024)
                                                                                    if not chunk:
                                                                                        break
                                                                                    cli.sendall(chunk)
                                                                                    print("服务端回执:", cli.recv(1024).decode) # OK
                                                                                    cli.close()
                                                                                    time.sleep(0.3)
                                                                                    print(f"源 {size} 字节 -> 落盘 {results['size']} 字节")

                                                                                    # ==================== E. 长连接 + 下线检测 + 超时 ====================
                                                                                    def server_echo(port, results):
                                                                                        srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
                                                                                        srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, True)
                                                                                        srv.bind((HOST, port)); srv.listen(5)
                                                                                        conn, _ = srv.accept
                                                                                        conn.settimeout(2.0) # 避免永久阻塞
                                                                                        lines = []
                                                                                        with conn:
                                                                                            while True:
                                                                                                try:
                                                                                                    data = conn.recv(1024)
                                                                                                except socket.timeout:
                                                                                                    lines.append("<超时>"); break
                                                                                                    if not data: # b'' 表示客户端已 close
                                                                                                        lines.append("<客户端已下线>"); break
                                                                                                        text = data.decode("utf-8").strip()
                                                                                                        if text == "886":
                                                                                                            lines.append("<收到 886，主动结束>"); break
                                                                                                            conn.sendall(f"echo: {text}".encode("utf-8"))
                                                                                                            lines.append(text)
                                                                                                            results["lines"] = lines
                                                                                                            srv.close()

                                                                                                            if __name__ == "__main__":
                                                                                                                base = "./_tmp09"
                                                                                                                os.makedirs(base, exist_ok=True)
                                                                                                                demo_basic(20101)
                                                                                                                demo_sticky(20102)
                                                                                                                demo_framed(20103)
                                                                                                                demo_upload(20104, base)
```

本机实测输出：

```text
客户端收到: 服务端收到啦
服务端收到: 你好，服务端
一次 recv 收到: b'AAABBB'
服务端完整收到: ['第一条', '第二条很长很长很长很长很长很长很长', '第三条']
服务端回执: OK
源 3000 字节 -> 落盘 3000 字节
```

**关键点说明**

| 位置 | 关键点 |
| --- | --- |
| `setsockopt(SO_REUSEADDR)` | 必须在 `bind` **之前**，否则重启服务端会 `Address already in use` |
| `bind((HOST, port))` | 参数是**一个元组**；写成 `bind(HOST, port)` 直接 `TypeError` |
| `listen(5)` | 5 是等待队列长度，不是"最多允许 5 个客户端" |
| `accept` 返回 `(conn, addr)` | `conn` 是**新的**套接字，只服务这一个客户端 |
| 用 `with conn:` | 套接字支持上下文管理器，退出时自动 `close` |
| `sendall` 而非 `send` | `send` 可能只发出去一部分，必须自己循环 |
| `recv` 返回 `b''` | 对端已关闭，这是判断客户端下线的标准信号 |
| `struct.pack("!I", n)` | `!` 表示网络字节序（大端），`I` 是 4 字节无符号整数 |
| `recv_exact` 循环 | `recv` 可能只收到一部分，必须循环凑满期望长度 |
| 先发 `json` 元信息再发内容 | 服务端才知道"该收多少字节、存成什么文件名" |
| 文件用 `"wb"` / `"rb"` | 二进制模式，避免换行符转换与编码问题 |
| `settimeout(2.0)` | 生产代码必须设超时，否则一个卡住的客户端会永久占住服务线程 |

## 3. 常见坑
| 坑 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| `bind("localhost", 8888)` | `TypeError: bind takes exactly one argument (2 given)` | `bind` 只接收一个地址元组 | `bind(("localhost", 8888))` |
| 服务端重启报地址被占用 | `OSError: [Errno 10048]` / `Address already in use` | 上一次的连接处于 `TIME_WAIT`，端口未释放 | 在 `bind` 前 `setsockopt(SOL_SOCKET, SO_REUSEADDR, True)` |
| 用 `send` 发长数据 | 对端数据不完整 | `send` 返回实际发送字节数，可能小于请求值 | 用 `sendall`，或循环发送直到发完 |
| 以为 `recv(1024)` 一次收完一条消息 | 数据被截断或两条粘在一起 | TCP 是字节流，没有消息边界 | 设计协议（长度前缀/分隔符），并用循环 `recv` 凑满 |
| 直接 `send("字符串")` | `TypeError: a bytes-like object is required, not 'str'` | 网络只传 `bytes` | `"文本".encode("utf-8")` |
| 两端编码不一致 | 乱码或 `UnicodeDecodeError` | 一端 utf-8、一端 gbk | 统一 utf-8，并在协议里写明 |
| `recv` 卡死不动 | 程序挂住没有输出 | 阻塞等待数据（对端没发或已断但没检测） | `settimeout` + 捕获 `socket.timeout`，或先发"心跳" |
| 用 `recv` 返回值判断"收到空消息" | 死循环 | 对端关闭时 `recv` 返回 `b''`，与"收到空数据"不同 | `if not data: break`，把它当**下线信号** |
| 服务端只用一次 `accept` | 只能服务一个客户端，第二个连不上 | `accept` 是一次性的 | 把 `accept` + 处理放进 `while True` + 每连接一线程 |
| 客户端和服务端 IP/端口写错 | `ConnectionRefusedError: [WinError 10061]` | 服务端没启动或端口不对 | 先确认服务端已 `listen`，用 `127.0.0.1` 本机联调 |
| `bind` 到局域网 IP 后本机连不上 | `connect` 超时 | 绑的是具体网卡地址，不包含 loopback | 本机测试绑 `127.0.0.1`，对外服务绑 `0.0.0.0` |
| 关闭了 `srv` 却继续 `accept` | `OSError: [WinError 10038]` 在非套接字上操作 | 套接字已关闭 | 关 `srv` 前先结束 `accept` 循环 |
| 拿 `accept` 返回的 `conn` 反复当新连接 | 消息串到别人会话里 | `conn` 是与**单个**客户端绑定的 | 每个 `conn` 用一个变量/线程独立处理 |
| 文件上传用文本模式 | 图片/压缩包损坏 | 文本模式会转换换行符、做编码 | 一律用 `"rb"` / `"wb"` |
| 上传大文件一次 `read` | 内存爆掉、进度不可见 | 一次性载入 | 分块 `read(1024)` 循环发送 |
| `except:` 裸捕获包住整个循环 | 真实错误被静默吞掉，服务"看起来正常" | 捕获范围过宽 | 只捕获 `ConnectionError` / `OSError` 并记录日志 |
| 忘了关 `conn` | 文件描述符泄漏，最终 `Too many open files` | 套接字也是资源 | 用 `with conn:`，或在 `finally` 里 `close` |
| 测试时端口被别的进程占用 | `Address already in use` 换个端口就好 | 端口是独占资源 | 换端口，或 `netstat -ano` 找到占用进程 |

## 4. 面试问答
<details markdown="1">
<summary markdown="1"><strong>Q1：TCP 为什么要三次握手？为什么断开要四次挥手？</strong></summary>

**三次握手**是为了让双方都确认"自己的发送能力和对方的接收能力都正常"，并同步初始序号：

1. 客户端发 `SYN(x)` —— 服务端由此确认"客户端能发、我能收"；
2. 服务端回 `SYN(y)+ACK(x+1)` —— 客户端由此确认"我能发能收、对方能发能收"；
3. 客户端回 `ACK(y+1)` —— 服务端由此确认"我的发送能力也被对方收到了"。

如果只有两次，服务端在发出 `SYN+ACK` 后就认为连接建立，但万一客户端早已放弃（比如请求在网络里滞留很久才到），服务端就会维护一个无效连接，浪费资源，甚至被利用做 SYN Flood。

**四次挥手**是因为 TCP 是全双工的，两个方向要独立关闭。A 发 `FIN` 只表示"A 不再发数据了"，此时 B 可能还有数据要发，所以 B 只能先回 `ACK`（进入半关闭状态），等自己数据发完再发自己的 `FIN`，A 再回 `ACK`。确认与关闭不能合并，就成了四次。主动关闭方最后进入 `TIME_WAIT` 等待 2MSL，确保最后的 `ACK` 能到达，也避免旧连接的数据包污染新连接 —— 这正是服务端重启后端口被占用 1~2 分钟的原因，也是需要 `SO_REUSEADDR` 的原因。

</details>

<details markdown="1">
<summary markdown="1"><strong>Q2：什么是粘包？怎么解决？</strong></summary>

粘包指发送方多次 `send` 的数据，在接收方一次 `recv` 里被合并读出来（反之，一条消息被拆成多次 `recv` 读出来，叫拆包/半包）。实测 `send(b"AAA")` + `send(b"BBB")`，服务端一次 `recv(1024)` 收到 `b'AAABBB'`。

**根本原因**：TCP 是**面向字节流**的协议，只保证字节的顺序和可靠到达，**不保留应用层的消息边界**。合并与拆分的具体行为取决于发送缓冲区、Nagle 算法、MTU、接收窗口和网络状况。

**解决方案**：

1. **固定长度**：约定每条消息长度固定，不足补位。简单，但浪费带宽，不适合变长内容；
2. **分隔符**：约定 `\n`、`\r\n` 或自定义分隔符，接收方按分隔符切分（HTTP 头、Redis 协议就是这么做的）。内容里不能含分隔符，需要转义；
3. **长度前缀**（推荐）：先发固定字节数的长度字段（如 `struct.pack("!I", len)`），再发正文；接收方先读长度、再按长度循环读满正文。

注意：无论哪种方案，接收侧的 `recv` 都必须**循环凑满**期望字节数，因为 `recv(n)` 只保证"最多 n 字节"。

</details>

<details markdown="1">
<summary markdown="1"><strong>Q3：服务端 `accept` 之前的套接字和返回的套接字有什么区别？为什么要有两个？</strong></summary>

`accept` 之前的套接字（被动套接字）只负责"监听并接受新的连接请求"，它本身**不能收发业务数据**。`accept` 返回的是一个**全新的套接字**，它与刚刚建立连接的那一个客户端一一绑定，之后所有 `recv`/`send` 都通过它进行。

这样设计的原因：TCP 连接是"点对点"的，服务端要同时服务 N 个客户端，就必须为每个客户端维护独立的连接状态（序号、窗口、缓冲区）。被动套接字是"接待处"，交互套接字是"每个客户专属的电话线"。关掉某个交互套接字只结束与那一个客户端的会话，服务端仍可继续 `accept` 新连接；关掉被动套接字则整个服务不再接受新连接。

配套的两个实践要点：① 交互套接字用完必须关闭（用 `with conn:`），否则文件描述符泄漏；② `recv` 返回 `b''` 说明客户端已 `close`，这是判断下线的标准方式。

</details>

## 5. 自测题
<details markdown="1">
<summary markdown="1">1. 下面这段服务端代码有几个问题？</summary>

```python
import socket
server = socket.socket
server.bind('localhost', 8888)
server.listen
client_socket, addr = server.accept
data = client_socket.recv(1024)
print('收到：', data)
client_socket.send(b'hello,Client!')
client_socket.close()
```
问题：

1. `bind('localhost', 8888)` —— **错误**，`bind` 只接收一个地址元组，应为 `server.bind(('localhost', 8888))`，否则直接 `TypeError`；
2. `listen` 未给 backlog，虽然合法（默认值由系统决定），但显式写 `listen(128)` 更清晰；
3. 缺少 `setsockopt(SO_REUSEADDR, True)`，调试期间重启服务端会频繁报端口被占用；
4. `print('收到：', data)` 打印的是 `bytes`（形如 `b'...'`），应 `data.decode('utf-8')`；
5. 只 `accept` 一次，只能服务一个客户端；
6. `recv` 没做 `if not data` 判断，无法识别客户端下线；
7. `server` 没有关闭（这一条按说法是"服务端一般不主动关"，属于设计选择，不算错，但要清楚原因）。

正确版本：
```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, True)
server.bind(('127.0.0.1', 8888))
server.listen(128)

while True:
    client_socket, addr = server.accept
    with client_socket:
        data = client_socket.recv(1024)
        if not data:
            continue
        print('收到：', data.decode('utf-8'))
        client_socket.sendall(b'hello,Client!')
```

</details>

<details markdown="1">
<summary markdown="1">2. `recv(1024)` 里的 1024 是什么意思？改成 10 会怎样？</summary>

`1024` 是**本次调用最多读取的字节数**（缓冲区大小），不是"消息长度"，也不是"必须读满 1024"。

改成 `10` 的影响：一条 30 字节的消息需要连续调用 3 次 `recv(10)` 才能读完。如果代码只调用一次，就会拿到前 10 字节并丢掉剩余数据 —— 这正是"半包"问题的来源。所以：

- 单次 `recv` 的返回值长度是 **1 ~ bufsize 之间任意值**（对端关闭时为 0）；
- 要收完整数据必须**循环 `recv` 直到满足协议约定的长度**；
- 缓冲区越大，系统调用次数越少（更快），但单次内存占用更大。常见折中是 1 KB ~ 64 KB。

</details>

<details markdown="1">
<summary markdown="1">3. 服务端怎么知道客户端已经断开？</summary>

标准做法是判断 `recv` 的返回值：对端正常 `close`（或异常退出）后，服务端 `recv` 会**解除阻塞并返回 `b''`**（长度为 0 的空字节串）。
```python
data = conn.recv(1024)
if not data: # b'' → 对端已关闭
 print("客户端下线")
 break
```
注意区分：`recv` 返回 `b''` 表示"连接关闭"，而**没有返回**（一直阻塞）表示"对端还活着但没发数据"。所以只靠 `recv` 无法发现"客户端机器断电/网线被拔"这类情况，需要配合：

1. `settimeout(t)` —— 超时就认为链路异常；
2. **心跳机制** —— 客户端定期发心跳包，服务端超过 N 个周期没收到就判定离线；
3. TCP Keep-Alive（`SO_KEEPALIVE`）—— 内核层面的探测，默认周期很长（2 小时），一般需要调参。

</details>

<details markdown="1">
<summary markdown="1">4. 为什么文件上传要先发文件名和大小？</summary>

因为 TCP 是字节流，服务端**只看到一串字节，不知道边界在哪里、也不知道该存成什么名字**。如果直接发文件内容：

- 服务端不知道要收多少字节才结束（除非客户端发完就 `close`，但那样不能在一个连接里传多个文件）；
- 无法知道原始文件名和类型；
- 无法区分"两个文件的内容"。

所以要在正文之前发一段**元信息**（文件名、大小、可选校验和），例如用长度前缀发一段 JSON：
```python
send_msg(conn, json.dumps({"name": "a.jpg", "size": 204800}).encode)
# 然后按 size 循环发正文
```
服务端先按协议读元信息，再精确读 `size` 字节写入目的文件，最后回执 `OK`。这也是为什么有了"大小"还要有"长度前缀"：长度前缀解决**元信息本身**的边界，`size` 解决**正文**的边界。如果担心传输损坏，还可以加 MD5/SHA 校验，服务端收完后校验一次。

</details>
