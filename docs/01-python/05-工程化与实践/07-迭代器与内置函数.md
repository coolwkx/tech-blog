# 07 迭代器与内置函数
> **一句话总结**：`for` 循环的本质是"`iter` 取迭代器 → 反复 `next` → 捕获 `StopIteration`"；理解这套协议，就能自己写出可迭代对象、解释"生成器只能遍历一次"，并用好 `enumerate` / `zip` / `map` / `sorted(key=...)` 这批高频内置函数。
> **前置知识**：序列与字典（01 篇）、函数作为参数与 lambda（02 篇）、`yield` 生成器（06 篇）。

> 1. 用 `__iter__` / `__next__` 手写一个可迭代对象，并说清"可迭代对象"和"迭代器"的区别；
> 2. 用 `while` 手动复现 `for` 循环，解释迭代器为什么只能遍历一次；
> 3. 熟练使用 20 个以上常用内置函数，并用 `key` 参数完成单级、多级、自定义排序。

## 1. 核心概念
### 1.1 可迭代对象（iterable）vs 迭代器（iterator）
| 概念 | 需要实现 | 能否被 `for` | 能否 `next` | 例子 |
| --- | --- | --- | --- | --- |
| 可迭代对象 iterable | `__iter__` | ✅ | ❌ | `list`、`dict`、`str`、`set`、`range`、文件对象 |
| 迭代器 iterator | `__iter__` + `__next__` | ✅ | ✅ | `list_iterator`、生成器、`map` / `filter` / `zip` 对象 |

关键事实（实测）：
```text
list 有 __iter__: True | 有 __next__: False
list_iterator 都有: True True
iter(it) is it: True
```
- **列表是可迭代对象但不是迭代器**：它没有 `__next__`，所以 `next([1,2])` 会报 `TypeError: 'list' object is not an iterator`；
- **迭代器一定也是可迭代对象**：它的 `__iter__` 直接返回 `self`（`iter(it) is it` 为 `True`）；
- 内置函数 `iter(x)` 调用 `x.__iter__`，`next(it)` 调用 `it.__next__`。

### 1.2 `for` 循环的完整协议
```python
data = [10, 20, 30]
it = iter(data) # ① 先拿迭代器
while True:
    try:
        value = next(it) # ② 反复取下一个
    except StopIteration: # ③ 用 StopIteration 表示"结束"
        break
    print(value)
```
所以 `for x in obj:` 等价于上面这段。**"循环结束"不是通过返回特殊值，而是通过抛 `StopIteration` 异常** —— 这也是为什么在生成器函数里 `return` 会表现为 `StopIteration`。

| 语句 | 等价操作 |
| --- | --- |
| `for x in obj:` | `it = iter(obj)` + 循环 `next(it)` + 捕获 `StopIteration` |
| `list(obj)` | 内部同样调用 `iter` / `next`，把结果收集成列表 |
| `sum(obj)` / `max(obj)` / `in` 判断 | 全部走同一套迭代协议 |
| 解包 `a, b, *rest = obj` | 也是迭代 |

**推论：任何实现了迭代协议的对象，都能用 `list`、`sum`、拆包、`for` 等所有"消费迭代器"的工具**，这就是迭代器协议的威力 —— 只要实现两个方法，就免费获得整个生态。

### 1.3 迭代器的"耗尽性"
迭代器持有**游标状态**：
```python
gen = (x for x in range(3))
print(sum(gen), sum(gen)) # 3 0 ← 第二次已经耗尽
```
| 写法 | 能否重复遍历 | 原因 |
| --- | --- | --- |
| `for` 遍历 list / dict / str | ✅ | 每次 `iter` 返回一个**新的**迭代器 |
| `for` 遍历生成器 / map / zip / filter | ❌ | 它们本身就是迭代器，返回 `self` |
| 自定义类 `__iter__` 返回 `self` | ❌ | 游标是对象自己的状态 |
| 自定义类 `__iter__` 里 `yield` | ✅ | 每次调用都产生一个**新的**生成器 |

**设计建议**：想让自己写的类可以反复遍历，应该把"可迭代对象"和"迭代器"分开 —— 可迭代对象的 `__iter__` 每次都返回一个**新的**迭代器（或直接用 `yield` 写成生成器方法）；想表达"一次性数据流"（如读文件、读 socket），才让 `__iter__` 返回 `self`。

### 1.4 内置函数分类速查
| 分类 | 函数 | 说明 |
| --- | --- | --- |
| 迭代与序列 | `len` `iter` `next` `enumerate` `zip` `reversed` `sorted` `range` | 遍历与重排 |
| 聚合 | `sum` `min` `max` `any` `all` | 归约统计，`any`/`all` 短路 |
| 函数式 | `map` `filter` | 配合 `functools.reduce` 使用 |
| 类型与判断 | `type` `isinstance` `issubclass` `bool` `int` `float` `str` `list` `dict` `set` `tuple` | 转换与类型检查 |
| 数值 | `abs` `round` `divmod` `pow` `bin` `oct` `hex` | 数学与进制 |
| 自省与调试 | `id` `repr` `vars` `dir` `hasattr` `getattr` `setattr` `callable` `help` | 反射 |
| 输入输出 | `print` `input` `open` | — |
| 其他 | `chr` `ord` `hash` `format` `slice` `frozenset` `object` | — |

**注意：`reduce` 不是内置函数**，Python 3 把它移到了 `functools`（因为大部分场景用 `sum`、`max`、推导式更清晰）：
```python
from functools import reduce
reduce(lambda a, b: a + b, [3, 1, 4, 1, 5], 0) # 14
```
### 1.5 重点函数逐个说清
| 函数 | 签名要点 | 输出示例（`nums = [3,1,4,1,5]`） |
| --- | --- | --- |
| `enumerate(it, start=0)` | 产出 `(下标, 元素)` 元组 | `list(enumerate("abc", 1))` → `[(1,'a'),(2,'b'),(3,'c')]` |
| `zip(*its)` | 按**最短**的截断 | `list(zip([1,2],"abcd"))` → `[(1,'a'),(2,'b')]` |
| `map(f, it)` | 惰性，返回 map 对象 | `list(map(lambda x: x*2, nums))` → `[6,2,8,2,10]` |
| `filter(f, it)` | `f` 返回真值才保留，惰性 | `list(filter(lambda x: x>2, nums))` → `[3,4,5]` |
| `sorted(it, key, reverse)` | 返回**新列表**，稳定排序 | `sorted(nums)` → `[1,1,3,4,5]` |
| `reversed(seq)` | 需要 `__reversed__` 或 `__len__`+`__getitem__` | `list(reversed([1,2,3]))` → `[3,2,1]` |
| `any` / `all` | 短路求值 | `any(x>4 for x in nums)` → `True` |
| `min` / `max` | 支持 `key=` 和 `default=` | `max(nums)` → `5` |
| `divmod(a, b)` | 同时得到商和余 | `divmod(17, 5)` → `(3, 2)` |
| `sum(it, start=0)` | `start` 对字符串无效 | `sum(nums)` → `14` |

> `zip(*its)` 配合拆包能实现"矩阵转置"：`list(zip(*[[1,2],[3,4]]))` → `[(1,3),(2,4)]`。

### 1.6 `key` 参数：Python 排序的核心设计
`sorted` / `list.sort()` / `min` / `max` / `groupby` 都接受 `key`：它对每个元素**调用一次**，用返回值参与比较，最后返回原元素。

| 需求 | 写法 |
| --- | --- |
| 按绝对值 | `sorted(xs, key=abs)` |
| 按长度 | `sorted(words, key=len)` |
| 按字典字段 | `sorted(rows, key=lambda r: r["score"])` |
| 按多个字段 | `sorted(rows, key=lambda r: (r["dept"], -r["score"]))` |
| 用 `operator` 更快更清晰 | `sorted(rows, key=itemgetter("dept", "score"))` |
| 按属性 | `sorted(objs, key=attrgetter("age", "name"))` |

**多级排序技巧**：Python 的 `key` 只能返回一个值，所以把多个排序依据**打包成元组**；元组按元素依次比较，因此"先按 A 升序、再按 B 降序"要写成 `(A, -B)`（数值才能取负；字符串降序需要多次稳定排序或自定义包装类）。

**稳定排序的含义**：`sorted` 是稳定排序 —— 键相同的元素保持原有相对顺序。实测 `sorted` 结果里 `王凯旋`（90 分）排在 `刘浩存`（90 分）之前，与它们在原列表中的顺序一致。这个性质让"多轮排序"成为可行方案：先按次要键排一次，再按主要键排一次，最终结果就是多级排序。

### 1.7 推导式 vs `map` / `filter`
| 写法 | 可读性 | 性能 | 惰性 |
| --- | --- | --- | --- |
| `[x*2 for x in xs if x > 2]` | ⭐ 高 | 快 | ❌ 立即生成列表 |
| `list(map(lambda x: x*2, filter(lambda x: x > 2, xs)))` | 低 | 稍慢（lambda 调用开销） | ❌（被 `list` 消费） |
| `(x*2 for x in xs if x > 2)` | 高 | 快 | ✅ 生成器表达式 |

实测两种写法结果完全一致：`[6, 8, 10]`。

**结论**：功能能用推导式表达的，优先用推导式（更 Pythonic、更快）；`map` / `filter` 适合"已经有一个现成的具名函数"的场景，例如 `map(str.strip(), lines)`、`filter(None, xs)`（过滤掉所有假值）。**不要在 `map` 里塞 `lambda` 去做推导式能干的事。**

| 推导式类型 | 语法 | 结果类型 |
| --- | --- | --- |
| 列表推导 | `[f(x) for x in xs if cond]` | `list` |
| 集合推导 | `{f(x) for x in xs}` | `set`（自动去重） |
| 字典推导 | `{k: v for k, v in pairs}` | `dict` |
| 生成器表达式 | `(f(x) for x in xs)` | `generator`（惰性，**不是元组**） |

> 注意：**没有"元组推导式"**。`(i for i in range(5))` 是生成器表达式，`type` 是 `<class 'generator'>`。

## 2. 最小可运行示例
```python
from functools import reduce
from operator import itemgetter

# ---------- 1) 手动复现 for 循环 ----------
data = [10, 20, 30]
it = iter(data) # ① 取迭代器
while True:
    try:
        print(" next:", next(it)) # ② 反复取
    except StopIteration: # ③ 靠异常判断结束
        print(" 循环结束")
        break

    # ---------- 2) 自定义可迭代对象：每次遍历都产生新迭代器 ----------
    class Sentence:
        """可迭代对象：__iter__ 返回一个全新的迭代器对象"""

        def __init__(self, text):
            self.words = text.split()

            def __iter__(self):
                return SentenceIterator(self.words)

            class SentenceIterator:
                """迭代器：自己维护游标，耗尽即停"""

                def __init__(self, words):
                    self.words = words
                    self.index = 0

                    def __iter__(self):
                        return self # 迭代器的 __iter__ 返回 self

                    def __next__(self):
                        if self.index >= len(self.words):
                            raise StopIteration # 结束信号
                        word = self.words[self.index]
                        self.index += 1
                        return word

                    s = Sentence("hello python world")
                    print("第一次:", list(s)) # ['hello', 'python', 'world']
                    print("第二次:", list(s)) # 仍然完整 → 可重复遍历

                    # ---------- 3) 自定义迭代器：一次性 ----------
                    class OnceRange:
                        """__iter__ 直接返回 self，所以只能遍历一次"""

                        def __init__(self, n):
                            self.n = n
                            self._cur = 0

                            def __iter__(self):
                                return self

                            def __next__(self):
                                if self._cur >= self.n:
                                    raise StopIteration
                                self._cur += 1
                                return self._cur

                            o = OnceRange(3)
                            print("第一次:", list(o), "第二次:", list(o)) # [1, 2, 3] []

                            # ---------- 4) 反向迭代：__reversed__ ----------
                            class Countdown:
                                def __init__(self, n):
                                    self.n = n

                                    def __iter__(self):
                                        for i in range(self.n): # 用 yield 写，自动可重复遍历
                                            yield i

                                            def __reversed__(self):
                                                for i in range(self.n - 1, -1, -1):
                                                    yield i

                                                    print("正向:", list(Countdown(4)), "反向:", list(reversed(Countdown(4))))
                                                    # 正向: [0, 1, 2, 3] 反向: [3, 2, 1, 0]
                                                    # ---------- 5) 常用内置函数 ----------
                                                    nums = [3, 1, 4, 1, 5]
                                                    print("enumerate:", list(enumerate("abc", start=1))) # [(1,'a'),(2,'b'),(3,'c')]
                                                    print("zip 最短截断:", list(zip([1, 2], "abcd"))) # [(1,'a'),(2,'b')]
                                                    print("zip → dict:", dict(zip(["a", "b"], [1, 2]))) # {'a': 1, 'b': 2}
                                                    print("map:", list(map(lambda x: x * 2, nums))) # [6,2,8,2,10]
                                                    print("filter:", list(filter(lambda x: x > 2, nums))) # [3,4,5]
                                                    print("reduce:", reduce(lambda a, b: a + b, nums, 0)) # 14
                                                    print("sorted:", sorted(nums), "| reverse:", sorted(nums, reverse=True))
                                                    print("any/all:", any(x > 4 for x in nums), all(nums)) # True True
                                                    print("divmod:", divmod(17, 5)) # (3, 2)
                                                    print("round:", round(2.567, 2)) # 2.57

                                                    # ---------- 6) key 参数：从单级到多级排序 ----------
                                                    students = [
                                                    {"name": "王凯旋", "score": 90, "age": 21},
                                                    {"name": "刘浩存", "score": 90, "age": 22},
                                                    {"name": "王月半", "score": 10, "age": 20},
                                                    ]

                                                    print("按分数升序:", [s["name"] for s in sorted(students, key=lambda s: s["score"])])
                                                    print("用 itemgetter:", [s["name"] for s in sorted(students, key=itemgetter("score"))])
                                                    print("多级(分数降序, 年龄升序):",
                                                    [s["name"] for s in sorted(students, key=lambda s: (-s["score"], s["age"]))])
                                                    print("按绝对值:", sorted([-3, 1, -2], key=abs)) # [1, -2, -3]
                                                    print("按长度:", sorted(["bb", "a", "ccc"], key=len)) # ['a', 'bb', 'ccc']

                                                    # ---------- 7) 推导式 vs map/filter ----------
                                                    print("列表推导:", [x * 2 for x in nums if x > 2]) # [6, 8, 10]
                                                    print("map+filter:", list(map(lambda x: x * 2, filter(lambda x: x > 2, nums))))
                                                    print("字典推导:", {k: v for k, v in zip("abc", [1, 2, 3])})
                                                    print("生成器表达式类型:", type(x for x in range(3)).__name__) # generator

                                                    # ---------- 8) 迭代器耗尽 ----------
                                                    gen = (x for x in range(3))
                                                    print("sum 第一次:", sum(gen), "第二次:", sum(gen)) # 3 0

                                                    # ---------- 9) 经典案例：按批次产出数据（dataloader 的前身） ----------
                                                    import math

                                                    def dataset_loader(total, batch_size):
                                                        """把 0..total-1 按 batch_size 分批产出，最后一批允许不足"""
                                                        batch_count = math.ceil(total / batch_size) # 向上取整，不足一批也算一批
                                                        for batch_id in range(batch_count):
                                                            start = batch_id * batch_size
                                                            yield list(range(start, min(start + batch_size, total)))

                                                            print("分 3 批:", list(dataset_loader(8, 3)))
                                                            # [[0,1,2], [3,4,5], [6,7]]
```

**关键点说明**

| 位置 | 关键点 |
| --- | --- |
| `iter(data)` | 列表本身不是迭代器，必须先取迭代器才能 `next` |
| `except StopIteration` | 迭代结束的**唯一**信号，不是返回 `None` |
| `Sentence.__iter__` | 每次都 `return SentenceIterator(...)`，所以可重复遍历 |
| `OnceRange.__iter__` | 返回 `self`，游标存在对象里 → 只能遍历一次 |
| `Countdown.__iter__` 用 `yield` | 用生成器方法实现 `__iter__`，天然可重复遍历，代码最短 |
| `zip` 按最短截断 | 长度不等时"多出来的直接丢弃"，容易静默丢数据 |
| `key=lambda s: (-s["score"], s["age"])` | 元组依次比较，负号实现"数值降序" |
| `sum(gen)` 两次结果 3 和 0 | 生成器是迭代器，被消费后耗尽 |
| `math.ceil(total / batch_size)` | 分批必须向上取整，否则最后一批会被丢掉 |

## 3. 常见坑
| 坑 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| 对 list 直接 `next` | `TypeError: 'list' object is not an iterator` | 列表只有 `__iter__`，没有 `__next__` | 先 `it = iter(lst)` |
| 自定义类只实现 `__iter__` 返回 `self` 又想要重复遍历 | 第二次遍历为空 | 游标是对象状态，已被耗尽 | `__iter__` 里返回新的迭代器对象，或改用 `yield` |
| 用 `while True` 手动 `next` 不捕获异常 | 抛 `StopIteration` 中断程序 | 迭代结束信号就是异常 | 用 `for`，或显式 `except StopIteration: break` |
| 在生成器内部手动 `raise StopIteration` | Python 3.7+ 报 `RuntimeError: generator raised StopIteration` | PEP 479：生成器里的 `StopIteration` 会被转成 `RuntimeError` | 直接用 `return` 结束生成器 |
| `zip` 长度不等 | 数据"凭空少了" | `zip` 按最短截断 | 用 `itertools.zip_longest(fillvalue=...)` |
| `map` / `filter` 结果当列表用 | `TypeError: 'map' object is not subscriptable` | 返回的是惰性迭代器，且**只能消费一次** | 需要多次使用就 `list(...)` 固化 |
| 生成器重复使用 | 第二次拿到空 | 迭代器一次性 | 每次重新调用生成函数，或改用列表 |
| 推导式里放复杂逻辑 | 一行 120 字符，难以调试 | 推导式表达力有限 | 超过一个条件就改成普通 `for` 循环 |
| `(x for x in ...)` 当元组用 | `type` 是 `generator`，`len` 报错 | Python 没有元组推导式 | 真要元组写 `tuple(x for x in ...)` |
| `sorted` 想原地排序 | 原列表没变 | `sorted` 返回新列表 | 原地排序用 `lst.sort(key=...)`，注意它返回 `None` |
| `key` 函数有副作用 / 很慢 | 性能骤降、结果不确定 | `key` 对每个元素调用一次，且实现可能多次比较 | `key` 只做取值；必要时预先算好 `key` 缓存 |
| 字符串多级排序想用负号 | `TypeError: bad operand type for unary -: 'str'` | 负号只能用于数值 | 分两轮稳定排序，或用包装类反转比较 |
| `any` / `all` 传生成器后又想复用 | 结果全为 `False` / 空 | 短路求值 + 迭代器耗尽 | 需要复用就先 `list` |
| `filter(None, xs)` 的误用 | 把 `0` / `""` 也过滤掉了 | `None` 作为函数表示"按真值过滤" | 明确要过滤什么值，写清楚条件 |
| 手写 `for i in range(len(lst))` | 代码冗长易越界 | 忘了 `enumerate` | 需要下标用 `enumerate(lst)` |
| 迭代中修改被遍历的容器 | 元素被跳过或抛 `RuntimeError: dictionary changed size during iteration` | 迭代器基于容器状态 | 先固化 `list(d)`，或用推导式生成新容器 |
| `items` / `keys` 视图的误用 | 报 `RuntimeError: dictionary changed size` | 视图是动态的 | 遍历前 `list(d.items())` |

**Q1：可迭代对象和迭代器有什么区别？为什么要有两个协议？**

**可迭代对象**只需实现 `__iter__`，它表示"我可以被迭代"，每次调用 `__iter__` 都应该返回一个**迭代器**。**迭代器**必须同时实现 `__iter__` 和 `__next__`：`__next__` 每次返回下一个值，没有更多元素时抛 `StopIteration`；`__iter__` 通常 `return self`。

区分两者是为了**把"数据"和"遍历状态"解耦**。列表、字典、字符串是"数据容器"，可以被反复遍历，因为每次 `iter` 都会造一个新的迭代器（`list_iterator`）；而生成器、文件对象、socket 流是"一次性数据流"，状态就长在对象自身，所以只能消费一次。

统一的好处是：只要实现这两个方法（或写个 `yield`），你的对象就自动支持 `for`、`list`、`sum`、`in`、拆包、`zip` 等所有消费迭代器的工具，零成本接入整个标准库生态。

</details>

<details><summary>参考答案</summary>

**Q2：`for x in obj` 内部到底发生了什么？**

三步：
```text
_iterator = iter(obj) # 调用 obj.__iter__，拿到迭代器
while True:
 try:
 x = next(_iterator) # 调用 _iterator.__next__
 except StopIteration:
 break # 用异常表示"结束"
 <循环体>
```
要点有三个：① `for` 只调用一次 `iter`，然后反复 `next`；② 结束条件是**捕获 `StopIteration`**，不是返回哨兵值（这也是 PEP 479 要把生成器内的 `StopIteration` 转成 `RuntimeError` 的原因 —— 否则一个意外抛出的 `StopIteration` 会静默终止外层循环）；③ 循环变量 `x` 在循环结束后仍然存在，保留最后一个值。

</details>

<details><summary>参考答案</summary>

**Q3：`sorted(xs, key=f)` 里的 `key` 是怎么工作的？为什么不直接传比较函数？**

`sorted` 是"装饰-排序-去装饰"（decorate-sort-undecorate）的实现：先对每个元素调用一次 `key` 得到排序依据，把所有元素按这个依据排序，最后返回**原元素**组成的列表。所以 `key` 应该返回"用来比较的值"，而不是布尔值或元素本身。

好处：① `key` 对每个元素**只调用一次**（n 次），而比较函数在排序过程中要被调用 O(n log n) 次 —— 对昂贵的取值操作（如解析日期字符串、访问属性链）差别巨大；② 排序只需实现"小于"一种比较，Python 用 `<` 比较 key 即可，接口更简单；③ 配合 `operator.itemgetter` / `attrgetter` 在 C 层实现取值，比 `lambda` 更快。

对多级排序，`key` 返回元组即可（元组按元素依次比较）；需要"某列降序"时对数值取负号 `(-score, age)`，字符串则需多轮稳定排序或其他技巧。

</details>

## 5. 自测题
<details><summary>1. `xs = [1, 2, 3]`，下面代码输出什么？为什么？</summary>
```python
it = iter(xs)
print(list(it))
print(list(it))
```
输出 `[1, 2, 3]` 然后 `[]`。因为 `iter(xs)` 返回的是**一个**迭代器对象，它的游标在一次 `list` 消费后就到了末尾；第二次 `list` 调用 `next` 立刻得到 `StopIteration`，所以收集到空列表。

注意对比：`list(xs)` 连续调用两次都得到 `[1,2,3]`，因为 `list` 内部每次都自己调 `iter(xs)` 拿新迭代器。

</details>

<details><summary>2. 写一个类，让它既是可迭代对象、又支持 `reversed`。</summary>
```python
class Countdown:
    def __init__(self, n):
        self.n = n

        def __iter__(self):
            for i in range(self.n):
                yield i

                def __reversed__(self):
                    for i in range(self.n - 1, -1, -1):
                        yield i

                        print(list(Countdown(4))) # [0, 1, 2, 3]
                        print(list(reversed(Countdown(4)))) # [3, 2, 1, 0]
```
要点：`__iter__` 用 `yield` 写成生成器方法，因此每次遍历都是独立的生成器，可以重复遍历；`reversed` 内置函数优先调用 `__reversed__`，如果没有则退化为 `__len__` + `__getitem__` 从后往前索引。

</details>

<details><summary>3. `zip` 在处理不等长序列时有什么陷阱？怎么解决？</summary>

陷阱是 `zip` **按最短序列截断**：`list(zip([1, 2], "abcd"))` 得到 `[(1, 'a'), (2, 'b')]`，`"cd"` 被静默丢弃。在数据对齐场景（如把两个表按行拼起来）这会导致数据无声变少。

解决：① 明确长度一致，或在 `zip` 前断言 `len(a) == len(b)`；② 需要保留所有数据时用 `itertools.zip_longest(a, b, fillvalue=None)`，缺失位置补 `None`；③ 需要按"更长的那个"迭代时先 `zip_longest` 再过滤。

另外 `zip` 返回的是迭代器，只能消费一次；要重复用就先 `list(zip(...))`。

</details>

<details><summary>4. 下面两种写法哪个更好？为什么？</summary>
```python
# A
result = [x * 2 for x in nums if x > 2]
# B
result = list(map(lambda x: x * 2, filter(lambda x: x > 2, nums)))
```
结果相同（都是 `[6, 8, 10]`，以 `nums = [3,1,4,1,5]` 为例），但 **A 更好**：

① 可读性：A 的顺序就是"先过滤、再变换"的思维顺序；B 要**从里往外**读（`filter` 在内，`map` 在外），与直觉相反；
② 性能：B 多了两次函数调用（lambda 每次都要走 Python 函数调用开销），实测通常慢 20%~50%；
③ 调试：A 里的表达式可以直接打断点看 `x`，B 的 lambda 不方便；
④ 可扩展性：A 想加条件、加嵌套变换都是顺手改；B 一变复杂可读性就崩了。

`map` / `filter` 真正合适的场景是"已经有具名函数"，例如 `map(str.strip(), lines)`、`filter(os.path.exists, paths)` —— 这时省略 lambda，反而比推导式更短更清晰。

</details>
