# 10 数据结构与算法基础

> **一句话总结**：数据结构决定"数据怎么放"，算法决定"数据怎么算"；两者统一用**时间复杂度**这把尺子衡量，而链表、栈队列、排序、查找、树本质上都在做"用空间换时间""用有序换速度"的取舍。
> **前置知识**：列表与字典的复杂度直觉（01 篇）、函数与递归（02 篇）、类与对象（03 篇）。
> **学完能做到**：1. 读一段代码就能推出时间复杂度，并区分最优/最坏/平均情况；2. 手写单链表的增删查改、冒泡/选择/插入/快速排序、二分查找与二叉树遍历；3. 说出常见排序算法的稳定性差异，并能在顺序表与链表之间做出选择。

## 1. 核心概念

### 1.1 两个定义与算法的五大特性

| 概念 | 定义 | 例子 |
| --- | --- | --- |
| 数据结构 | **存储、组织数据的方式**，是存在特定关系的数据元素集合 | 同一份班级信息：用 list 查找 `O(n)`，用 dict `O(1)` |
| 算法 | 为了满足业务目的而采取的**方法和思路** | 求 5 个 2 的和：`2+2+2+2+2` 还是 `2*5` |
| 二者关系 | 数据结构是算法处理问题的**载体**，选对结构能带来数量级的效率差异 | `数据结构 + 算法 = 程序` |

数据的 5 种基本运算：**插入、删除、修改、查找、排序**。
算法的**独立性**：算法是与语言无关的思想（穷举法用 C 或 Python 都能写），所以面试考算法而不考语法。

| 五大特性 | 含义 |
| --- | --- |
| 有输入 | 0 个或多个输入 |
| 有输出 | **至少 1 个**输出 |
| 有穷性 | 有限步骤后自动结束，且每步都在可接受时间内完成 |
| 确定性 | 每一步含义唯一，不存在二义性 |
| 可行性 | 每一步都能通过有限次执行完成 |

### 1.2 时间复杂度：大 O 记法

`时间 = 操作步骤数量 × 单步执行时间`。单步时间受机器/编译器/负载影响，所以**直接比秒数不客观**；于是假设"每个基本操作耗时 1 个时间单位"，只数**操作步骤数量**得到 `T(n)`。

例题（`a+b+c=1000` 且 `a²+b²=c²`）：

| 算法 | 循环层数 | 每次循环步骤 | T(n) | 大 O |
| --- | --- | --- | --- | --- |
| 三重循环穷举 | `1001³` | 3+5+2 = 10 | `n³ × 10` | `O(n³)` |
| `c = 1000-a-b` 代入 | `1001²` | 3+5+2 = 10 | `n² × 10` | `O(n²)` |

**大 O 记法**：只保留最高次项、去掉系数与常数项。它的物理含义是"**算法随问题规模变化的最主要趋势**"，也就是"量级"（文件是 KB 级还是 MB 级）。

| 计算规则 | 内容 | 例子 |
| --- | --- | --- |
| ① 基本操作 | 复杂度为 `O(1)` | `a = 100` |
| ② 顺序结构 | 按**加法**计算 | 三步各 `O(1)` → `O(3)` → 化简 `O(1)` |
| ③ 循环结构 | 按**乘法**计算 | 循环 n 次、体内 `O(1)` → `O(n)` |
| ④ 分支结构 | 取**最大值** | `if` 是 `O(n)`、`else` 是 `O(n²)` → `O(n²)` |
| ⑤ 只留最高次项 | 次要项与常数项忽略 | `T(n)=2n+n²+n³ → O(n³)` |
| ⑥ 默认看最坏 | 无特殊说明时指最坏情况 | 查找类算法 |

| 执行次数函数 | 阶 | 术语 | | 执行次数函数 | 阶 | 术语 |
| --- | --- | --- | --- | --- | --- | --- |
| `12` | `O(1)` | 常数阶 | | `5log₂n+20` | `O(log n)` | 对数阶 |
| `2n+3` | `O(n)` | 线性阶 | | `n log n` | `O(n log n)` | 线性对数阶 |
| `3n²+2n+1` | `O(n²)` | 平方阶 | | `6n³+2n²+3n+4` | `O(n³)` | 立方阶 |

量级排序（越小越快）：`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)`

**两个容易被判错的"栗子"**：`sum = 2002 + 10002` 虽然出现 2002，但执行次数恒定、与 n 无关 → `O(1)`（不是 `O(n²)`）；`for i in range(n): a += 1` 执行 n 次 → `O(n)`（不是 `O(2n)`，系数省略）。

### 1.3 最优 / 最坏 / 平均情况

以"在列表里找 10"为例（`[1,5,6,...,10]` vs `[10,5,6,...]`）：

| 类型 | 定义 | 价值 |
| --- | --- | --- |
| 最优 | 完成工作**最少**的基本操作 | 最乐观，**参考价值低** |
| 最坏 | 完成工作**最多**的基本操作 | 是一种**保证**：算法在此程度内一定完成 |
| 平均 | 期望的基本操作数 | 评价全面，但需知道输入分布，**难以计算** |

**结论：默认关注最坏时间复杂度。** 空间复杂度 `S(n)` 同理，衡量算法运行中**临时占用**的存储空间；容易忽略的一点是**递归的空间复杂度至少等于递归深度**（每层栈帧都占空间），所以快排最坏空间是 `O(n)`、平均 `O(log n)`。

### 1.4 线性结构 vs 非线性结构

| 类型 | 特点 | 典型结构 |
| --- | --- | --- |
| 线性结构 | 非空集；每个结点**最多一个**直接前驱和一个直接后继；有唯一"第一个/最后一个" | 顺序表、链表、栈、队列 |
| 非线性结构 | 非空集；一个结点**可能有多个**直接前驱和多个直接后继 | 树、图 |

### 1.5 顺序表 vs 链表

| 维度 | 顺序表（数组 / list） | 链表 |
| --- | --- | --- |
| 存储空间 | **连续** | **非连续**，靠链接串起存储块 |
| 随机访问 | `O(1)`（首地址 + 下标偏移） | `O(n)`（必须从头遍历） |
| 头部插入/删除 | `O(n)`（后续元素整体搬家） | `O(1)`（改指针） |
| 尾部插入 | 平摊 `O(1)` | 单链表 `O(n)`（要走到尾） |
| 扩容 | 需连续空间，可能整体搬迁 | 无需扩容，按需申请结点 |
| 额外开销 / 缓存 | 无额外指针；内存连续、缓存友好 | 每结点多指针域；内存跳跃、缓存不友好 |

**顺序表的两种存储方式**：

| 方式 | 结构 | 扩容 |
| --- | --- | --- |
| 一体式 | 信息区 + 数据区**连续**存放 | 只能**整体搬迁** |
| 分离式 | 信息区存"容量 + 数据区地址"，数据区另行分配 | 只更换数据区，**更新链接即可** |

**扩容策略**：每次增加固定数目（如 +10）→ 省空间但扩充频繁、次数多；每次**容量加倍** → 扩充次数少、平摊 `O(1)`，但可能浪费空间（**推荐**，空间换时间）。Python 的 `list` 正是"分离式 + 容量倍增（约 1.125 倍）"，所以 `append` 平摊 `O(1)`，而 `insert(0, x)` 是 `O(n)`。

**顺序表增删元素的复杂度**：尾端增删 `O(1)`；非保序增删（把末尾元素挪到被删位置）`O(1)`；保序增删（中间插入/删除，后续元素整体移动）`O(n)`。

### 1.6 排序算法对比与稳定性

| 算法 | 思路一句话 | 最好 | 最坏 | 平均 | 空间 | 稳定性 |
| --- | --- | --- | --- | --- | --- | --- |
| 冒泡排序 | 相邻两两比较，大的往后"冒" | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | ✅ 稳定 |
| 选择排序 | 每轮从未排序区选出最小值放到前面 | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | ❌ 不稳定 |
| 插入排序 | 把无序区第一个元素插入有序区合适位置 | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | ✅ 稳定 |
| 快速排序 | 选基准值分区，再对左右子区间递归 | `O(n log n)` | `O(n²)` | `O(n log n)` | `O(log n)` | ❌ 不稳定 |

**稳定性**：待排序序列中存在多个相同关键字的记录时，若排序后它们的**相对次序保持不变**，则该算法稳定。作用是支持**多关键字排序**：先按次要键排一遍、再按主要键排一遍，只要第二轮算法稳定，最终结果就正确。

| 类别 | 算法 |
| --- | --- |
| 稳定 | 冒泡排序、插入排序、归并排序、基数排序 |
| 不稳定 | 选择排序、快速排序、希尔排序、堆排序 |

**选择排序为什么不稳定？** 它把远端选出的最小值与当前位置**长距离交换**，这个交换可能把前面相同 key 的元素甩到后面去。

### 1.7 二分查找

**前提缺一不可**：① 必须**顺序存储**（能直接地址偏移定位，`O(1)` 随机访问）；② 必须按关键字**有序排列**。

**思路**：把数组分成"中值前 / 中值 / 中值后"，待查找值与中值比较：小于去前半部分，大于去后半部分，等于则返回。

| 版本 | 关键代码 | 复杂度 |
| --- | --- | --- |
| 非递归 | `while start <= end:` + `mid=(start+end)//2` + 调整 `start/end` | 时间 `O(log n)`，空间 `O(1)` |
| 递归 | `binary_search(alist[:mid], item)` | 时间 `O(log n)`，但**切片每次复制 `O(n)`**，实际退化，空间 `O(n)` |

两个细节：循环条件必须是 `start <= end`（用 `<` 会漏掉"区间只剩一个元素"）；教材的递归版写 `alist[0:mid]` 只为讲清思路，生产代码应传下标区间。

### 1.8 树与二叉树

| 术语 | 含义 | | 术语 | 含义 |
| --- | --- | --- | --- | --- |
| 节点的度 | 该节点的子节点个数 | | 节点的层次 | 根为第 1 层，依次递增 |
| 树的度 | 树中最大的节点度 | | 树的高度/深度 | 节点的最大层次 |
| 叶节点 | 度为 0 的节点 | | 森林 | m（m≥0）棵互不相交的树的集合 |

| 树的种类 | 特点 / 用途 |
| --- | --- |
| 哈夫曼树 | 带权路径最短的二叉树，用于信息编码 |
| B 树 | 读写优化的自平衡多路查找树（数据库索引） |
| 完全二叉树 | 除最后一层外都满，最后一层从左到右紧密排列 |
| 满二叉树 | 所有叶节点都在最底层的完全二叉树 |
| 平衡二叉树（AVL） | 任何节点两棵子树高度差 ≤ 1；**防止树退化成链表** |
| 排序二叉树（BST） | 左子树全部小于根、右子树全部大于根；**中序遍历得到有序序列** |

**应用场景**：XML/HTML 解析器、路由协议、MySQL 索引、文件系统目录结构、AI 搜索、决策树。

| 二叉树的 5 条性质 |
| --- |
| 1. 第 `i` 层至多有 `2^(i-1)` 个结点 |
| 2. 深度为 `k` 的二叉树至多有 `2^k - 1` 个结点 |
| 3. 叶结点数 `N0` 与度为 2 的结点数 `N2` 满足 `N0 = N2 + 1` |
| 4. `n` 个结点的完全二叉树深度为 `⌊log₂n⌋ + 1` |
| 5. 完全二叉树按层编号（从 1 起），结点 `i` 的左孩子 `2i`、右孩子 `2i+1`、父节点 `i//2` |

> 性质 5 是"完全二叉树可用数组存储"的理论基础（若从 0 开始编号：左 `2i+1`、右 `2i+2`、父 `(i-1)//2`）。存储方式上，顺序存储遍历快但浪费空间（非主流），链式存储（左右指针）便于找父子关系，是常见做法。

| 遍历 | 顺序 | 口诀 |
| --- | --- | --- |
| 先序（前序） | 根 → 左 → 右 | 根左右 |
| 中序 | 左 → 根 → 右 | 左根右 |
| 后序 | 左 → 右 → 根 | 左右根 |
| 层序（广度优先） | 逐层从左到右，用**队列**实现 | — |

先序/中序/后序属于**深度优先**（递归或栈），层序属于**广度优先**（队列，能找到最短路径）。**由遍历结果还原二叉树必须给出中序 + (先序或后序)**：先序定根、中序分左右子树，再递归；只给先序和后序无法唯一确定。

## 2. 最小可运行示例

```text
import time

# ---------- 1) 复杂度实测：三层循环 O(n^3) vs 代入法 O(n^2) ----------
def brute_force_triple(n):
 cnt = 0
 for a in range(1, n + 1):
 for b in range(1, n + 1):
 for c in range(1, n + 1):
 if a + b + c == n and a * a + b * b == c * c:
 cnt += 1
 return cnt

def brute_force(n):
 cnt = 0
 for a in range(1, n + 1):
 for b in range(1, n + 1):
 c = n - a - b # 用已知关系消掉一层循环
 if c > 0 and a * a + b * b == c * c:
 cnt += 1
 return cnt

# ---------- 2) 单链表：结点 + 链表两个类 ----------
class SingleNode:
 def __init__(self, item):
 self.item = item
 self.next = None

class SingleLinkList:
 def __init__(self, node=None):
 self.head = node

 def is_empty(self):
 return self.head is None

 def length(self):
 cur, count = self.head, 0
 while cur is not None: # 注意：不是 cur.next
 count += 1
 cur = cur.next
 return count

 def travel(self):
 out, cur = [], self.head
 while cur is not None:
 out.append(cur.item)
 cur = cur.next
 return out

 def add(self, item): # 头插 O(1)
 node = SingleNode(item)
 node.next = self.head # 顺序绝不能反
 self.head = node

 def append(self, item): # 尾插 O(n)
 node = SingleNode(item)
 if self.is_empty:
 self.head = node
 return
 cur = self.head
 while cur.next is not None:
 cur = cur.next
 cur.next = node

 def insert(self, pos, item):
 if pos <= 0:
 self.add(item)
 elif pos >= self.length:
 self.append(item)
 else:
 node, cur = SingleNode(item), self.head
 for _ in range(pos - 1):
 cur = cur.next
 node.next, cur.next = cur.next, node

 def search(self, item):
 cur = self.head
 while cur is not None:
 if cur.item == item:
 return True
 cur = cur.next
 return False

 def remove(self, item):
 cur, pre = self.head, None
 while cur is not None:
 if cur.item == item:
 if pre is None: # 删头结点要单独处理
 self.head = cur.next
 else:
 pre.next = cur.next
 return True
 pre, cur = cur, cur.next
 return False

# ---------- 3) 排序：冒泡（带提前退出）与快速 ----------
def bubble_sort(alist):
 n = len(alist)
 for j in range(n - 1):
 count = 0
 for i in range(n - j - 1):
 if alist[i] > alist[i + 1]:
 alist[i], alist[i + 1] = alist[i + 1], alist[i]
 count += 1
 if count == 0: # 一轮无交换 → 已有序，最优 O(n)
 break
 return alist

def quick_sort(alist):
 if len(alist) <= 1:
 return alist
 pivot = alist[len(alist) // 2]
 return (quick_sort([x for x in alist if x < pivot])
 + [x for x in alist if x == pivot]
 + quick_sort([x for x in alist if x > pivot]))

# ---------- 4) 二分查找（非递归版，教材写法） ----------
def binary_search(alist, item):
 start, end = 0, len(alist) - 1
 while start <= end: # 必须含等号
 mid = (start + end) // 2
 if item == alist[mid]:
 return True
 elif item < alist[mid]:
 end = mid - 1
 else:
 start = mid + 1
 return False

def linear_search(alist, item):
 for x in alist:
 if x == item:
 return True
 return False

# ---------- 5) 二叉树：层序插入 + 遍历 + 由先序中序还原 ----------
class Node:
 def __init__(self, item):
 self.item = item
 self.lchild = None
 self.rchild = None

class BinaryTree:
 def __init__(self, node=None):
 self.root = node

 def add(self, item):
 """用队列找第一个空位，保证得到完全二叉树"""
 node = Node(item)
 if self.root is None:
 self.root = node
 return
 queue = [self.root]
 while queue:
 cur = queue.pop(0)
 if cur.lchild is None:
 cur.lchild = node
 return
 queue.append(cur.lchild)
 if cur.rchild is None:
 cur.rchild = node
 return
 queue.append(cur.rchild)

 def breadth_travel(self):
 if self.root is None:
 return []
 out, queue = [], [self.root]
 while queue: # 层序 = 队列 + 广度优先
 cur = queue.pop(0)
 out.append(cur.item)
 if cur.lchild is not None:
 queue.append(cur.lchild)
 if cur.rchild is not None:
 queue.append(cur.rchild)
 return out

 def preorder(self, root): # 根左右
 if root is None:
 return []
 return [root.item] + self.preorder(root.lchild) + self.preorder(root.rchild)

 def inorder(self, root): # 左根右
 if root is None:
 return []
 return self.inorder(root.lchild) + [root.item] + self.inorder(root.rchild)

def build_from_pre_in(preorder, inorder):
 """由先序 + 中序还原二叉树"""
 if not preorder:
 return None
 node = Node(preorder[0]) # 先序第一个是根
 idx = inorder.index(preorder[0]) # 中序里根的位置划分左右子树
 node.lchild = build_from_pre_in(preorder[1:1 + idx], inorder[:idx])
 node.rchild = build_from_pre_in(preorder[1 + idx:], inorder[idx + 1:])
 return node

if __name__ == "__main__":
 for n in (150, 300):
 t = time.perf_counter; brute_force_triple(n); t3 = time.perf_counter - t
 t = time.perf_counter; brute_force(n); t2 = time.perf_counter - t
 print(f"n={n}: O(n^3) {t3:.3f}s | O(n^2) {t2:.3f}s")

 print("排序:", bubble_sort([5, 3, 4, 7, 2]), quick_sort([5, 3, 4, 7, 2]))

 arr = list(range(0, 100, 2))
 print("二分找 70:", binary_search(arr, 70), "| 找 71:", binary_search(arr, 71))
 big = list(range(1_000_000))
 t = time.perf_counter; binary_search(big, 999_999); tb = time.perf_counter - t
 t = time.perf_counter; linear_search(big, 999_999); tl = time.perf_counter - t
 print(f"100 万元素: 二分 {tb*1000:.4f} ms | 线性 {tl*1000:.3f} ms")

 ll = SingleLinkList
 for x in [1, 2, 3]:
 ll.append(x)
 ll.add(0); ll.insert(2, 99)
 print("链表:", ll.travel, "长度:", ll.length, "search(99):", ll.search(99))

 tree = BinaryTree
 for ch in "ABCDEFGHIJK":
 tree.add(ch)
 print("层序:", tree.breadth_travel)
 print("先序:", tree.preorder(tree.root))
 print("中序:", tree.inorder(tree.root))
 rebuilt = BinaryTree(build_from_pre_in("0137849256", "7381940526"))
 print("还原后中序:", "".join(rebuilt.inorder(rebuilt.root)))
```

```text
链表: [0, 1, 99, 2, 3] 长度: 4 search(99): True
层序: ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H', 'I', 'J', 'K']
先序: ['A', 'B', 'D', 'H', 'I', 'E', 'J', 'K', 'C', 'F', 'G']
中序: ['H', 'D', 'I', 'B', 'J', 'E', 'K', 'A', 'F', 'C', 'G']
还原后中序: 7381940526
```

**关键点说明**

| 位置 | 关键点 |
| --- | --- |
| n 从 150 翻倍到 300 | `O(n³)` 耗时 0.103 → 1.012s（约 10 倍），`O(n²)` 只从 0.001 → 0.007s。**复杂度可预测，运行时间不可预测** |
| `count` 提前退出 | 冒泡"最优 `O(n)`"的唯一来源；不加这个优化最优也是 `O(n²)` |
| 快排用推导式分区 | 可读性最好，但每层新建列表，空间是 `O(n log n)`；原地分区版空间 `O(log n)` |
| `while start <= end` | 二分必须含等号，否则漏查"区间只剩一个元素"的情况 |
| 100 万元素：二分 `0.0078ms` vs 线性 `15.763ms` | 约 2000 倍差距，直观印证 `O(log n)` 与 `O(n)` 的量级差 |
| `node.next = self.head` 先执行 | 头插两行顺序绝不能反，反了就丢掉整条链表 |
| 链表遍历用 `while cur is not None` | 用 `while cur.next` 会漏掉最后一个结点 |
| 二叉树 `add` 用队列 | 层序插入才能得到完全二叉树 |
| `build_from_pre_in` | 先序定根、中序分左右，再递归；**只有先序+后序无法唯一还原** |

## 3. 常见坑

| 坑 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| 用运行秒数比较算法 | 换台机器结论就变 | 单步时间受机器/负载影响 | 数"操作步骤数量"，比量级 |
| 看到常数就写成对应阶 | `sum = 2002 + 10002` 判成 `O(n²)` | 常量与规模 n 无关 | 执行次数恒定 → `O(1)` |
| 忘了省略系数 | 写成 `O(2n)`、`O(3n²)` | 大 O 只留最高次项且不带系数 | `O(n)`、`O(n²)` |
| 顺序与循环结构混淆 | 复杂度判错 | 顺序相加、循环相乘、分支取最大 | 背住 6 条计算规则 |
| 递归版二分用切片 | 看着是 `O(log n)`，实测慢很多 | `alist[:mid]` 每次复制 `O(n)` | 传下标 `start/end`，或用非递归版 |
| 二分用 `while start < end` | 某些目标找不到 | 漏掉区间只剩一个元素的情况 | 用 `start <= end` |
| 二分用在无序数据上 | 结果随机正确或错误 | 二分依赖"有序 + 随机访问" | 先排序；链表不能二分 |
| 冒泡少了提前退出 | 已有序数组仍跑满 `O(n²)` | 没检测"本轮无交换" | 加 `count` 标记并 `break` |
| 以为选择排序稳定 | 多级排序结果错乱 | 选择排序会把同 key 的相对次序打乱 | 记住：冒泡/插入/归并稳定，选择/快排/希尔/堆不稳定 |
| 链表头插两行写反 | 链表只剩一个结点 | `self.head = node` 提前执行导致旧头丢失 | 先 `node.next = self.head`，再 `self.head = node` |
| 链表遍历用 `while cur.next` | 最后一个结点被漏掉 | 循环条件没考虑自身 | 用 `while cur is not None` |
| 频繁头插用 `list.insert(0, x)` | 数据量大时很慢 | 顺序表头插是 `O(n)` | 用 `collections.deque.appendleft`（`O(1)`） |
| 二叉树递归没写终止条件 | `RecursionError` | 忘了 `if root is None: return` | 先写基线条件 |
| 用"先序 + 后序"还原二叉树 | 结果不唯一 | 无法确定左右子树边界 | 必须「中序 + 先序」或「中序 + 后序」 |
| 层序遍历用栈 | 变成深度优先，顺序错 | 层序需要"先进先出" | 用队列 |

## 4. 面试问答

<details>
<summary><strong>Q1：什么是时间复杂度？大 O 记法是怎么来的？</strong></summary>

时间复杂度刻画的是"**算法执行时间随问题规模 n 变化的增长趋势**"，而非具体秒数。推导过程：设每个基本操作耗时为 1 个时间单位，数出操作总数得到 `T(n)`；再只保留最高次项、去掉系数与常数，写成 `O(f(n))`。

为什么可以忽略常数和低次项？因为 n 足够大时最高次项支配一切：`T(n)=3n²+2n+1` 在 n=10000 时，`3n²` 是 `3×10⁸`，而 `2n+1` 只有 `2×10⁴`，占比 0.007%。

**一个必须补的提醒**：大 O 只描述趋势，**不描述常数因子**。本机实测中 `O(n log n)` 的 `sorted`（C 实现 + 已排序检测）比 `O(n)` 的 Python 循环求和还快（0.0074s vs 0.0231s）。所以"量级更优"不等于"一定更快"——小数据量、不同语言实现之间都可能反转，工程上应先测量再优化。

</details>

<details>
<summary><strong>Q2：顺序表和链表各有什么优缺点？分别适合什么场景？</strong></summary>

**顺序表**（数组 / Python list）：元素在**连续**内存中，靠"首地址 + 下标 × 元素大小"直接定位。优点：随机访问 `O(1)`、内存连续缓存命中率高、无额外指针开销。缺点：中间插入/删除要搬移后续元素（`O(n)`）、需要连续大块内存、扩容时可能整体搬迁。

**链表**：结点分散存放，靠指针串联。优点：头部插入/删除 `O(1)`、不需要连续空间、天然动态增长。缺点：随机访问 `O(n)`、每结点多出指针域、内存不连续导致缓存不友好。

**选型规则**：以**随机读**为主、很少在中间增删 → 顺序表（Python 里就是 `list`）；以**频繁在头部/中间插入删除**为主、几乎不按下标访问 → 链表（Python 里更常用 `collections.deque`，两头都是 `O(1)`）。另外 Python 的 `list` 是"分离式 + 容量倍增"实现，`append` 平摊 `O(1)`，但 `insert(0, x)` 是 `O(n)`。

</details>

<details>
<summary><strong>Q3：什么是排序算法的稳定性？为什么重要？哪些稳定哪些不稳定？</strong></summary>

**定义**：待排序序列中存在多个关键字相同的记录时，若排序后它们的**相对次序保持不变**，该算法稳定；否则不稳定。

**为什么重要**——主要用于**多关键字排序**。例如要先按"班级"排、同班内按"成绩"排：做法是"先按成绩排一遍，再按班级排一遍"。只要第二轮算法**稳定**，同班内就会保持上一轮的成绩顺序，一次得到正确结果；若第二轮不稳定，第一轮建立的次序会被打乱，只能改用"两个关键字打包成元组一起比较"（`key=lambda r: (r.班级, -r.成绩)`）。

**分类**：稳定——冒泡、插入、归并、基数排序；不稳定——选择、快速、希尔、堆排序。实测佐证：对 `[(1,'a'),(0,'b'),(1,'c'),(0,'d'),(1,'e')]` 按 key 排序，插入排序输出 `b d a c e`（保持 `a` 在 `c` 前、`b` 在 `d` 前），选择排序输出 `b d c a e`（次序被打乱）。选择排序不稳定的原因很直观：它把远端最小值与当前位置交换，这个长距离交换可能把前面相同 key 的元素甩到后面。

</details>

## 5. 自测题

<details>
<summary>1. 计算下面代码的时间复杂度。</summary>

```python
def f(n):
    total = 0
    for i in range(n): # (1) O(n)
        total += i
        for i in range(n): # (2)(3) 嵌套 → O(n) × O(n) = O(n²)
            for j in range(n):
                total += i * j
                if n > 100: # (4) 分支取最大
                    return total
            else:
                for i in range(n): # (5) O(n)
                    total -= i
                    return total
```

答案 **`O(n²)`**。按规则拆解：`O(n) + O(n²) + max(O(1), O(n))` = `O(n²)`（忽略系数与低次项）。

</details>

<details>
<summary>2. 写一个函数判断单链表是否有环，说明复杂度。</summary>

**快慢指针（Floyd 判圈）**：

```python
def has_cycle(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next # 每次 1 步
        fast = fast.next.next # 每次 2 步
        if slow is fast:
            return True
        return False
```

原理：有环时快指针先入环绕圈，慢指针随后进入，两者在环内距离每轮缩小 1，必然相遇；无环时快指针先到 `None`。

- 时间 `O(n)`：快指针最多走 n 步；空间 `O(1)`：只用两个指针。
- 对比"用 set 记录访问过的结点"（`O(n)` 时间、`O(n)` 空间），快慢指针是空间最优。推论：相遇后把一个指针放回头部、两者同速前进，再次相遇处就是**环的入口**。

</details>

<details>
<summary>3. 已知先序遍历 `ABDECF`、中序遍历 `DBEAFC`，求后序遍历。</summary>

还原步骤：① 先序第一个 `A` 是根；② 中序 `DBEAFC` 中 `A` 左边 `DBE` 是左子树、右边 `FC` 是右子树；③ 左子树先序 `BDE` + 中序 `DBE` → 根 `B`，`D` 在左 `E` 在右；④ 右子树先序 `CF` + 中序 `FC` → 根 `C`，`F` 在左。

```text
 A
 / \
 B C
 / \ /
 D E F
```

后序遍历（左右根）：**`D E B F C A`**。验证：该树的中序为 `D B E A F C`，与题目一致。

</details>

<details>
<summary>4. 为什么二分查找要求"顺序存储 + 有序"？链表为什么不行？</summary>

两个要求各对应一个必要条件：① **有序**——二分靠"用中值比较排除一半区间"工作，无序时比较结果无法推出目标在哪半边，排除逻辑不成立；② **顺序存储（随机访问 `O(1)`）**——二分要反复按下标访问 `alist[mid]`，顺序表能用"首地址 + mid × 元素大小"直接算出地址；链表访问第 `mid` 个结点必须从头遍历，单次就是 `O(n)`，总复杂度退化到 `O(n log n)` 甚至更差，还不如直接线性查找。

如果非要在链表上做"跳跃"查找，需要额外索引结构 —— 这就是**跳表（skip list）** 的思路（Redis 有序集合用到它），它用多层索引 + 概率平衡在链表上实现期望 `O(log n)` 的查找。

</details>

<details>
<summary>5. `O(log n)` 和 `O(n log n)` 分别对应什么样的代码结构？</summary>

- **`O(log n)`**：每次操作把问题规模**缩小固定倍数**（通常 2）。典型写法是"变量每次乘 2 或除以 2"，如二分折半、`i *= 2`。
- **`O(n log n)`**：外层 `O(n)` × 内层 `O(log n)`。的说法是"一个 for 循环是 n，另一个 for 循环是二分法，组合在一起"。代表是快速排序、归并排序、堆排序以及 `sorted`。

```python
i = 1
while i < n: # O(log n)
 i *= 2

for x in range(n): # O(n log n)
 binary_search(x)
```

记忆技巧：**`log n` 来自"每次减半"，`n log n` 来自"对每个元素做一次减半操作"**。这也解释了为什么基于比较的排序算法下界是 `O(n log n)`。

</details>
