> **一句话总结**：RFM 用三个交易行为指标给用户打分——**R**（Recency，最近一次消费距今多久）、**F**（Frequency，消费频率）、**M**（Monetary，消费金额），再组合成分群把用户分为 3×3×3=27 组，从而对不同群体做差异化运营；技术难点不在算法，而在**分箱边界怎么定**与**分数怎么组合**。
> **前置知识**：[06-Pandas数据清洗](../02-NumPy与Pandas/06-Pandas数据清洗.md)（`dropna`、`concat`、`dt` 时间属性）；[07-Pandas分组聚合与透视](../02-NumPy与Pandas/07-Pandas分组聚合与透视.md)（`groupby + agg`）；[09-统计分析基础](../03-可视化与统计/09-统计分析基础.md)（`describe` 与分位数）。
> **学完能做到**：1. 独立完成从原始订单表到 RFM 分群结果的完整流水线（清洗 → 聚合 → 分箱 → 组合 → 出图 → 落库）；2. 依据 `describe` 与业务经验合理确定 R/F/M 分箱边界，并解释每个边界值从哪来；3. 针对不同 RFM 群体给出可落地的运营策略。

## 1. 核心概念

### 1.1 RFM 是什么

会员价值度模型用于评估用户价值、区分会员价值，也是衡量营销效果的关键指标之一；价值度模型一般基于**交易行为**产生。最常用的就是 RFM：

| 指标 | 全称 | 含义 | 方向 |
| --- | --- | --- | --- |
| **R** | Recency | 最近一次购买时间（距某个截止时间节点的间隔天数） | **越小越好**（越近越高分） |
| **F** | Frequency | 购买频率（固定时间范围内的订单次数） | **越大越好** |
| **M** | Monetary | 购买金额（固定时间范围内的消费总额） | **越大越好** |

三条重要性质：① RFM 基于**一个固定时间点**做分析，不同时间计算的结果可能不一样；② 三个维度的**区间和对应得分由我们自己定义**，没有唯一正确答案；③ 变更截止节点等于换了分析口径，跨期结果不可直接比较（除非都基于同一节点）。

### 1.2 八个用户类别

把每个维度二分为"高/低"（以中位数或某阈值为界），得 2×2×2 = 8 类：

| R | F | M | 用户类别 | 特征速记 |
| --- | --- | --- | --- | --- |
| 高 | 高 | 高 | **重要价值用户** | 最近买、常买、买得多——最优质客户 |
| 高 | 低 | 高 | **重要发展用户** | 最近买、金额高，但频率低——提频即可增值 |
| 低 | 高 | 高 | **重要保持用户** | 曾经常买且金额高，但最近没来——有流失风险 |
| 低 | 低 | 高 | **重要挽留用户** | 金额高但久未购买且频率低——重点挽回 |
| 高 | 高 | 低 | **一般价值用户** | 活跃但消费低——提升客单价 |
| 高 | 低 | 低 | **一般发展用户** | 新客或低频低额——培育 |
| 低 | 高 | 低 | **一般保持用户** | 频次尚可但已沉默——激活 |
| 低 | 低 | 低 | **一般挽留用户** | 各维度都差——最后考虑 |

### 1.3 完整实现流程

| 步骤 | 做什么 | 关键 API / 要点 |
| --- | --- | --- |
| ① 设置截止时间节点 | 选定基准日期（如 `2024-05-01`） | `pd.to_datetime('2024-05-01')` |
| ② 获取原始数据集 | 取固定周期（如近 1 年）的会员 ID、订单时间、订单金额 | 一个会员可能有多条订单 |
| ③ 数据预处理 | 删缺失值、去异常（金额过小） | `dropna`、布尔筛选 |
| ④ 计算 R/F/M 原始值 | R = 距截止节点的**最近**订单间隔；F = 订单**条数**；M = 金额**求和** | 一次 `groupby.agg({'日期':'max','订单号':'count','金额':'sum'})` |
| ⑤ 看数据分布 | 用 `describe` 观察 R/F/M 分布，为定边界做准备 | 关注 `mean` 与 `50%` 的差距、`min`/`max` 的极端性 |
| ⑥ 离散化打分 | 用 `pd.cut` 按边界切成 1~5 分或 1~3 分 | R 的 labels 要**倒序** |
| ⑦ 组合得分 | 加权求和 或 三维度字符串拼接 | `w = R*0.2 + F*0.2 + M*0.6`；`"312"` 这种组合 |
| ⑧ 结果应用 | 导出 Excel / 写入数据库 / 出图分析 | `to_excel`、`to_sql`、`plot`/`pyecharts` |

### 1.4 两种组合策略对比

| 策略 | 做法 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| **加权得分** | `rfm_wscore = r*0.2 + f*0.2 + m*0.6`，再按阈值分层（如 <2 低、2~4 中、>4 高） | 一个数字即可排序、分层、作为模型输入 | 权重靠业务主观确定，且压缩三维会丢细节 | 需要**总体排名**或作为建模特征 |
| **组合得分** | 把三个分数拼成字符串，如 `312`、`555` | 保留三个维度的完整信息，可精确解读 | 组合多（3³=27 或 5³=125 种），策略数量爆炸 | 需要**精细化分群与定制策略** |

### 1.5 确定分箱边界的三种套路

| 套路 | 做法 | 前提 |
| --- | --- | --- |
| **业务实际判断** | 由业务经验给出阈值，例如"新用户 1 周内交易、日用品采购周期 1 个月"→ R 的 7 天、30 天是重要值；F 的"1 次/2 次/3 次/4~10 次/10 次以上" | 需要业务深度参与 |
| **平均值或中位数** | 用中位数把用户分为"高于中值/低于中值"两半 | 分布较均匀时可用 |
| **分位数 / 二八法则** | 取 25%、75% 分位数作为两个内部边界 | 分布相对分散、样本量足够 |

本案例**综合使用了这三者**：R 和 M 用 25%/75% 分位数定边界（分布较离散），F 因为"从 min 到 75% 都是 1、均值仅 1.365"而无法用统计量区分，改由**业务经验**给出 2 和 5。

### 1.6 区间边界的三条基本原则

| 原则 | 说明 |
| --- | --- |
| **最小值边界要小于数据最小值** | `pd.cut` 默认是**左开右闭** `(a, b]`，最左侧的点落不进任何区间会被判为 NaN，所以边界必须取 `-1` 这种比 `min` 更小的值 |
| **最大值边界要 ≥ 数据最大值** | 保证最大的记录也能被分进最后一档 |
| **中间边界** | R/M 取 25%、75% 分位数；F 取业务经验值 |
| **n 个边界切出 n−1 个区间** | 因此 `labels` 的个数必须是 `len(bins) - 1` |

### 1.7 结果如何应用

① **基于三维度组合做用户群体划分与解读**：例如 RFM = `212` 的会员 F=1，说明购买频率低，应定期推送促销活动；`321` 的会员频率高但金额低，说明购买黏性强，可通过关联销售/搭配销售提升订单金额。② **基于汇总得分评估价值度并排名**：加权总分可作为**新特征**输入到其他分析与挖掘模型，为建模提供基础。

## 2. 可运行示例

> 真实数据集 `sales.xlsx` 含 5 个 sheet（2015~2018 四个年份 + 会员等级），共约 15.4 万行订单。下面用**等价的示意数据**复现完整流程，代码结构与一致，可直接替换为真实数据。

```python
import time
import numpy as np
import pandas as pd

# ================= 0. 构造示意数据 =================
np.random.seed(42)
n = 2000
raw = pd.DataFrame({
'会员ID': np.random.choice([1001, 1002, 1003, 1004, 1005, 1006, 1007, 1008], n),
'订单号': np.arange(3000000000, 3000000000 + n),
'提交日期': pd.to_datetime('2019-01-01') + pd.to_timedelta(np.random.randint(0, 730, n), unit='D'),
'订单金额': np.round(np.random.lognormal(mean=5, sigma=1.2, size=n), 1),
})
raw.loc[raw.sample(30, random_state=1).index, '订单金额'] = np.nan # 造缺失
raw.loc[raw.sample(40, random_state=2).index, '订单金额'] = 0.1 # 造无意义小额
# 真实场景读多 sheet（返回 dict：键=sheet 名，值=该表 df）
# sheet_names = ['2015','2016','2017','2018','会员等级']
# sheet_datas = pd.read_excel('./data/sales.xlsx', sheet_name=sheet_names)

# ================= 1. 预处理：删缺失 + 去异常 =================
data = raw.copy
data = data.dropna # 丢弃含缺失值的行
data = data[data['订单金额'] > 1] # 丢弃金额 <= 1 的无意义记录（优惠券订单）
data['max_year_date'] = data['提交日期'].max# 记录最后一笔消费时间，作为截止节点
print('清洗后条数:', len(data), data.isnull.sum.sum)

# ================= 2. 计算 R/F/M 原始值 =================
data['year'] = data['提交日期'].dt.year
data['date_interval'] = (data['max_year_date'] - data['提交日期']).dt.days # timedelta -> 天数

rfm_gb = data.groupby(['year', '会员ID'], as_index=False).agg({
'date_interval': 'min', # R：最近一次消费距截止日的间隔天数
'订单号': 'count', # F：订单条数
'订单金额': 'sum', # M：消费总额
})
rfm_gb.columns = ['year', '会员ID', 'r', 'f', 'm']
print(rfm_gb.describe)

# ================= 3. 观察分布，确定分箱边界 =================
dist = rfm_gb[['r', 'f', 'm']].describe.T
print(dist)
# 真实案例的分布（供对照）：
# r: count=148591 mean=165.52 std=101.99 min=0 25%=79 50%=156 75%=255 max=365
# f: count=148591 mean=1.365 std=2.627 min=1 25%=1 50%=1 75%=1 max=130
# m: count=148591 mean=1323.7 std=3753.9 min=1.5 25%=69 50%=189 75%=1199 max=206251.8
# 边界来源：R、M 分布较离散 -> 取 25% 与 75% 分位数；
# F 从 min 到 75% 都是 1、均值仅 1.365，统计量无法区分用户 -> 用业务经验值 2 和 5
r_bins = [-1, dist.loc['r', '25%'], dist.loc['r', '75%'], dist.loc['r', 'max'] + 1]
f_bins = [0, 2, 5, dist.loc['f', 'max'] + 1]
m_bins = [0, dist.loc['m', '25%'], dist.loc['m', '75%'], dist.loc['m', 'max'] + 1]
print('r_bins:', r_bins, 'f_bins:', f_bins, 'm_bins:', m_bins)

# ================= 4. 离散化打分：R 倒序，F/M 正序 =================
# pd.cut 默认左开右闭 (a, b]，labels 个数必须 = len(bins) - 1
rfm_gb['r_label'] = pd.cut(rfm_gb['r'], bins=r_bins, labels=[3, 2, 1]) # 间隔越小分越高
rfm_gb['f_label'] = pd.cut(rfm_gb['f'], bins=f_bins, labels=[1, 2, 3]) # 频次越高分越高
rfm_gb['m_label'] = pd.cut(rfm_gb['m'], bins=m_bins, labels=[1, 2, 3]) # 金额越高分越高
print(rfm_gb['r_label'].value_counts, rfm_gb['r_label'].isnull.sum) # 后者应为 0

# ================= 5. 组合得分 =================
# 策略一：加权得分
rfm_gb['rfm_wscore'] = (rfm_gb['r_label'].astype(int) * 0.2
+ rfm_gb['f_label'].astype(int) * 0.2
+ rfm_gb['m_label'].astype(int) * 0.6)
rfm_gb['segment'] = pd.cut(rfm_gb['rfm_wscore'], bins=[0, 2, 4, 5],
labels=['Low', 'Medium', 'High'])
# 策略二：三维度字符串组合
tmp = rfm_gb[['r_label', 'f_label', 'm_label']].astype(str)
rfm_gb['rfm_group'] = tmp['r_label'] + tmp['f_label'] + tmp['m_label']
print(rfm_gb['rfm_group'].value_counts.head(10))
print(rfm_gb.groupby(['year', 'rfm_group'])['会员ID'].count.head(20))

# ================= 6. 可视化 =================
import matplotlib.pyplot as plt
from pylab import mpl
mpl.rcParams['font.sans-serif'] = ['SimHei']; mpl.rcParams['axes.unicode_minus'] = False

rfm_gb['segment'].value_counts.reindex(['High', 'Medium', 'Low']) \
.plot(kind='bar', color=['green', 'orange', 'red'], title='按加权得分的客户分层')
plt.xlabel('客群'); plt.ylabel('人数'); plt.show

rfm_gb['segment'].value_counts.plot(kind='pie', autopct='%1.1f%%',
startangle=90, counterclock=False)
plt.ylabel(''); plt.title('客群占比'); plt.show

# ================= 7. 结果落地 =================
rfm_gb.to_excel('sales_rfm_score.xlsx', index=False) # 给业务做二次加工
# from sqlalchemy import create_engine # 供其他模型取用
# engine = create_engine('mysql+pymysql://root:123456@localhost:3306/rfm_db?charset=utf8')
# rfm_gb.to_sql('rfm_table', engine, index=False, if_exists='append')
# 校验：USE rfm_db; SELECT COUNT(*) FROM rfm_table;
print(rfm_gb.info)
```

### 简化版：五分位法（ 04-扩展 的写法）

只需要一个快速分群结论时，可用固定 5 档的写法，代码更短：

```python
import numpy as np, pandas as pd
df_raw = raw.set_index('会员ID') # 真实场景：pd.read_excel(..., index_col='USERID')

sales_data = df_raw.dropna # 缺失值处理
sales_data = sales_data[sales_data['订单金额'] > 1] # 去异常

recency_value = sales_data['提交日期'].groupby(sales_data.index).max # 最近一次订单时间
frequency_value = sales_data['提交日期'].groupby(sales_data.index).count # 订单频率
monetary_value = sales_data['订单金额'].groupby(sales_data.index).sum # 订单总金额

deadline_date = pd.to_datetime('2020-05-01') # 指定时间节点
r_interval = (deadline_date - recency_value).dt.days
r_score = pd.cut(r_interval, 5, labels=[5, 4, 3, 2, 1]) # R 五分位，倒序
f_score = pd.cut(frequency_value, 5, labels=[1, 2, 3, 4, 5]) # F 五分位
m_score = pd.cut(monetary_value, 5, labels=[1, 2, 3, 4, 5]) # M 五分位

rfm_list = [r_score, f_score, m_score]
rfm_cols = ['r_score', 'f_score', 'm_score']
rfm_pd = pd.DataFrame(np.array(rfm_list).transpose, dtype=np.int32,
columns=rfm_cols, index=frequency_value.index) # 3 x N 转置成 N x 3

rfm_pd['rfm_wscore'] = (rfm_pd['r_score'] * 0.2 + rfm_pd['f_score'] * 0.2
+ rfm_pd['m_score'] * 0.6) # 加权得分
tmp = rfm_pd[rfm_cols].astype(str)
rfm_pd['rfm_comb'] = tmp['r_score'].str.cat(tmp['f_score']).str.cat(tmp['m_score'])
rfm_pd.to_csv('rfm_result.csv')
print(rfm_pd.head)
```

## 3. 常见坑

| 坑 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| `pd.cut` 后出现 NaN | 部分用户分不到组，组内计数与总数对不上 | 最左侧边界**大于等于**数据最小值，而 `cut` 默认左开右闭 `(a, b]` | 最小值边界取比 `min` 更小的值（如 `-1`）；或用 `include_lowest=True` |
| `labels` 个数写错 | 报 `Bin labels must be one fewer than the number of bin edges` | `n` 个边界只能切出 `n-1` 个区间 | `labels` 长度必须等于 `len(bins) - 1` |
| R 的分数方向反了 | "最近买过"的用户反而得分低 | R 越小越好，而 `cut` 默认从左到右递增 | R 的 `labels` 写**倒序**，如 `[3,2,1]` 或 `[5,4,3,2,1]` |
| 用 `cut` 结果直接做算术 | 报 `TypeError: unsupported operand` | `cut` 的结果是 **category 类型** | 先 `.astype(int)` 再算加权分 |
| 忘记取 `.dt.days` | 间隔列是 `364 days` 这样的 `timedelta64[ns]`，无法分箱 | 日期相减得到的是时间差对象 | `(截止日 - 订单日).dt.days` 转成整数天数 |
| `groupby` 后 `sum` 报错 | `No numeric types to aggregate` | 该列被留成了 object 类型（如 `'?'` 字符串混入） | 先 `pd.to_numeric(errors='coerce')` 或 `astype(float)` |
| 用 `for` 循环按年份分别算 | 代码冗长、易错、难维护 | 分成 4 个 DataFrame 各算一遍 | `pd.concat` 合并成一张表，用 `groupby(['year','会员ID'])` 一次算完 |
| 拼接时报 dtype 错误 | 字符串与数值列拼接失败 | `rfm_group` 需要三个维度都是字符串 | 先对三列 `astype(str)` 再相加或用 `str.cat` |
| 组合分组的成员数对不上 | `value_counts.sum` 少于总用户数 | 分箱产生了 NaN（同第一条） | 先检查 `rfm_gb['r_label'].isnull.sum` 是否为 0 |
| 直接删掉所有极值 | 损失高价值客户 | 极值不一定是错误数据 | **先与业务确认**：案例中 174900 是有效大额采购，0.1 元优惠券订单才无效 |
| 用均值描述偏态分布 | 分箱边界全挤在高位，多数用户落到最低档 | 分布右偏，均值被极值拉高（m 的 mean 1323.7 而 median 仅 189） | 用 **25%/75% 分位数**定边界 |
| 区间划分过多 | 产出 27 组甚至 125 组，业务无法落地 | 分组多意味着要配套十几套策略 | 与业务确认资源：划 3 档得 27 组、划 2 档得 8 组；**资源有限优先 2 档** |
| `to_sql` 重复跑导致数据翻倍 | 表里条数变成 2 倍 | `if_exists='append'` 只追加不覆盖 | 调试用 `'replace'`；生产增量用 `'append'` 并配套去重逻辑 |

## 4. 面试问答

### Q1：RFM 三个维度的含义是什么？如果只能保留两个维度，你会保留哪两个？

<details><summary>参考答案</summary>

- **R（Recency）**：最近一次消费距截止时间节点的**间隔天数**，值越小越好——衡量用户的**活跃度与新鲜度**，反映"还会不会来"；
- **F（Frequency）**：固定时间范围内的**购买次数**，值越大越好——衡量**忠诚度与黏性**，反映"来得勤不勤"；
- **M（Monetary）**：固定时间范围内的**消费总额**，值越大越好——衡量**贡献价值**，反映"值不值钱"。

**保留哪两个取决于行业特性**（案例明确讨论过）：

| 行业特征 | 更重要的维度 | 原因 |
| --- | --- | --- |
| 大家电等**消费周期长**的行业 | **R 和 M** | 复购周期本来就很长（几年一次），F 天然很低、区分度差；"买得贵不贵"和"最近有没有关注"才是关键 |
| 快消等**消费周期短且快**的行业 | **R 和 F** | 购买频繁，F 能有效区分高频与低频用户；客单价差异相对较小，M 信息量不如前两者 |

补充：① 即使同一公司，**不同发展阶段三维度优先级也会调整**（扩张期重视 F 拉复购，成熟期重视 M 提客单）；② 取舍必须**与业务部门沟通**，不能纯靠数据；③ 若要量化权重，除"业务经验赋权"（如 R 0.2/F 0.2/M 0.6）外还可结合 **AHP 层次分析法**等专家打分方法，使权重更严谨。

</details>

### Q2：RFM 的分箱边界怎么确定？为什么本案例中 R 和 M 用分位数，而 F 用业务经验值？

<details><summary>参考答案</summary>

**通用三种套路**（案例三者都用到）：① **业务实际判断**——业务给出有意义的阈值，如"新用户注册 1 周内交易，7 天是重要的值；日用品采购周期 1 个月，30 天是重要的值"；② **平均值或中位数**——用中心位置把用户一分为二；③ **分位数/二八法则**——取 25%、75% 分位数把用户切成低/中/高三档。

**为什么 R 和 M 用分位数**：案例中 R 和 M 分布相对离散——`describe` 显示 R 的 `min/25%/50%/75%/max` 是 `0/79/156/255/365`，M 是 `1.5/69/189/1199/206251.8`，各分位点之间有明显间隔，说明数据能较好区分用户特征。因此直接取 **25% 和 75%** 作为两个内部边界，配合"比最小值小"和"大于等于最大值"的外边界：

```python
r_bins = [-1, 79, 255, 365]
m_bins = [0, 69, 1199, 206252]
```

**为什么 F 必须改用业务经验值**：F 的分布**极其极端**——`min` 到 `75%` **全都是 1**，均值只有 1.365。这意味着用任何分位数切分，绝大多数用户都会落在同一档，等于**没有区分度**。统计方法在此失效，只能回到业务：业务认为**当年购买 ≥ 2 次**才算复购用户（口径是"当年内"，不是累计订单数），且**普通用户购买 5 次已是非常高的次数**，超过即属非常高价值群体。于是得 `f_bins = [0, 2, 5, 130]`。

**核心考点**：分箱边界不是纯技术问题。**统计方法提供候选，业务知识做最终裁定**；当统计量在某维度失去区分力时，必须依靠业务经验，并确认口径（如"复购"看当年还是累计）。

</details>

### Q3：拿到 RFM 结果后，如何判断哪些群体值得重点运营，并给出策略？

<details><summary>参考答案</summary>

**第一步：按规模分层，因为规模决定落地方式。**

| 类别 | 规模特征 | 落地方式 |
| --- | --- | --- |
| 第 1 类 | 用户占比 **> 10%** | 基数大，**必须靠系统或产品实现批量运营**，无法依赖人工。如 `212`、`211`、`312`、`112`、`213` |
| 第 2 类 | 占比 **1%~10%** | 数量适中，**产品或人工都可采用**。如 `311`、`111`、`313`、`113` |
| 第 3 类 | 占比**极少**但单人价值极高 | 倾斜资源，可人工精细服务。如 `333`、`233/223/133`、`322/323/332` |

**第二步：用"三维度定位"找短板，短板就是策略抓手。** `212` 短板在频率低 → 礼品兑换/签到/免运费维持状态；`211` 金额更差 → 组合商品优惠券、积分购；`312` 频率低、金额中等 → 基于最近购买商品定制推荐、向上销售；`112` **新近度低（可能已流失）** → 邮件短信多渠道召回 + 流失用户专享券；`213` 金额高频率低 → 节日活动、每周新品推送、高价值客户专享商品；`111` 全面偏弱 → 排在其他群体之后，用大额折扣 + 热销商品先促成一次消费；`333` 无短板 → VIP 服务、专享服务、绿色通道。

**第三步：用可视化找"变化最大的群体"作为切入点。** 案例用 pyecharts 3D 柱形图（X = RFM 分组、Y = 年份、Z = 会员数量），发现 `212` 群体最集中、变化最大——2015 到 2017 变化不大，但 2018 年增长近一倍，因此列为重点；同时发现 `312`、`213`、`211`、`112` 各自规模不大但**合计超过 `212` 本身**，也要重点分析。

**第四步：落地与复评。** 案例中会员部门按三类群体分别制定排期，并把 RFM 得分写入数据库作为其他模型的关键输入特征。落地后应定期用同一口径重算，观察群体迁移（如 `212` 流向 `312` 还是 `112`），以此评估运营效果。

</details>

## 5. 自测题

### 1. 说明 R、F、M 的含义和方向，并解释为什么 R 的 `labels` 要倒序。

<details><summary>参考答案</summary>

**R**：最近一次消费距截止节点的间隔天数，**值越小越好**（越近越活跃）。**F**：固定周期内的购买次数，**值越大越好**（次数越多黏性越强）。**M**：固定周期内的消费总额，**值越大越好**（金额越高贡献越大）。

`pd.cut` 的分箱**从左到右依次对应 `labels`**，即第一个（值最小的）区间对应 `labels` 的第一个元素。对 F 和 M，区间从左到右值越来越大，正好对应 `[1, 2, 3]` 递增；但 R 的逻辑相反——间隔越小（越靠左）分数应越高，所以必须写**倒序**：

```python
rfm_gb['r_label'] = pd.cut(rfm_gb['r'], bins=r_bins, labels=[3, 2, 1])
# ↑ 左（间隔小）= 3 分
rfm_gb['f_label'] = pd.cut(rfm_gb['f'], bins=f_bins, labels=[1, 2, 3])
rfm_gb['m_label'] = pd.cut(rfm_gb['m'], bins=m_bins, labels=[1, 2, 3])
```

若 R 也写 `[1, 2, 3]`，就会出现"最近刚买过的用户得分最低"的严重逻辑错误，整个分群结论都会反过来。

</details>

### 2. 为什么 `r_bins = [-1, 79, 255, 365]` 的左边界是 `-1` 而不是 `0`？

<details><summary>参考答案</summary>

因为 `pd.cut` 对自定义边界默认遵循**左开右闭** `(a, b]` 原则：`(-1, 79]` 表示大于 −1 且小于等于 79。若写成 `bins=[0, 79, 255, 365]`，第一个区间是 `(0, 79]`，那么 **R = 0 的用户（当天购买）将无法落进任何区间**，会被判为 `NaN`。一旦出现 NaN，`value_counts` 的总和就与用户总数对不上，后续字符串拼接组合得分时也会出错（`astype(str)` 会把 NaN 变成 `'nan'` 字符串）。

案例数据中 R 的最小值确实是 **0**（有用户在截止日当天购买），所以左边界必须取比 0 更小的值（`-1`）；右边界取 `365`（等于最大值）是安全的，因为右端是**闭区间**。

**三条边界设置原则**：最小值边界 **< 数据最小值**（或改用 `include_lowest=True`）；最大值边界 **≥ 数据最大值**；`labels` 个数必须等于 `len(bins) - 1`。验证方法：分箱后立刻检查 `rfm_gb['r_label'].isnull.sum == 0`。

</details>

### 3. 为什么案例中没有对 4 年数据分别写 4 段代码计算 RFM，而是先 `concat` 再分组？

<details><summary>参考答案</summary>

因为 `groupby` 支持**多字段分组**，可以把"年份"作为一个分组维度一次性算完：

```python
data_merge = pd.concat(list(sheet_datas.values)[0:-1]) # 合并 4 年数据（去掉会员等级表）
rfm_gb = data_merge.groupby(['year', '会员ID'], as_index=False).agg({
'date_interval': 'min', '订单号': 'count', '订单金额': 'sum'})
```

好处：① **代码短且不易错**——不用写循环、不用管理临时变量、不会漏年份；② **口径完全一致**——四年用同一套聚合逻辑与分箱边界，结果**可比**（这正是案例"从不同年份对比各分组绝对值变化"的前提）；③ **性能更好**——`groupby` 底层用哈希表一次完成分组，比 Python 循环里反复切片快得多；④ **便于后续分析**——结果仍是长表（`year` 是普通列），可直接对 `rfm_group` 做跨年透视与 3D 可视化。

反过来，四年分别算再手工拼，很容易出现"某年漏了一列""某年边界不同"的问题，导致跨年对比失去意义。

</details>

### 4. 加权得分和组合得分两种策略各有什么优缺点？实际项目里怎么选？

<details><summary>参考答案</summary>

| 维度 | 加权得分 `rfm_wscore` | 组合得分 `rfm_group`（如 `"312"`） |
| --- | --- | --- |
| 形式 | 一个连续数值，如 `R*0.2 + F*0.2 + M*0.6` | 三维度字符串拼接，3 档时共 27 种 |
| 优点 | 可直接**排序、分层、排名**；能作为其他模型的输入特征 | 保留三维度**完整信息**，可精确解读每个群体的短板 |
| 缺点 | 权重靠主观确定，压缩成一个数会**丢细节**（`311` 与 `131` 可能得分相同） | 组合数多（5 档时 125 种），业务要配套的策略数量爆炸 |
| 适合 | 需要**总体价值排名**或作为建模输入特征 | 需要**精细化分群与定制化运营策略** |

案例中两者**同时输出**：`rfm_wscore` 用于整体价值评估与分层（并可作为其他模型的输入维度），`rfm_group` 用于精确分群与策略制定。

实际选择的建议：① **先问业务侧有多少资源**——案例明确讨论过，划 3 个区间已意味业务方要制定十几套策略，**若资源有限，划 2 个区间（最多 8 组）策略会简单得多**；② **对外汇报总体结论**（如"高价值客户占比 15%"）用加权得分分层；③ **给运营团队下发具体动作**用组合得分分群；④ **两者都产出、各自服务不同消费方**是常见且推荐的做法；⑤ 权重若不想拍脑袋，可结合 **AHP 层次分析法**做专家打分。

</details>
