# 模型评估与调优

> **一句话总结**：建模的成败由"**能否在没见过的数据上表现好**"决定——所以要用**独立的测试集 / 交叉验证**衡量，用**回归指标（MAE/MSE/RMSE）**、**分类指标（混淆矩阵/Precision/Recall/F1/AUC）**、**聚类指标（SSE/SC/CH）**分别度量不同任务，再用**超参数搜索 + 正则化 + 早停**逼近那个"偏差-方差最平衡"的点。

## 1. 核心思想

### 1.1 为什么必须"评估"

训练误差小**完全不能**说明模型好。有一个非常有说服力的实验（[03-线性回归](../02-经典算法/03-线性回归.md) 的过拟合演示）：

| 模型 | 特征 | **训练集 MSE** | 曲线形态 |
| --- | --- | --- | --- |
| 只用 $x$ | 1 维 | 3.0750 | 一条直线，明显欠拟合 |
| $x, x^2$ | 2 维 | 1.0987 | 贴合抛物线，比较合理 |
| $x,\dots,x^{10}$ | 10 维 | **1.0508（最小！）** | 剧烈抖动，明显过拟合 |

**过拟合模型在训练集上的 MSE 最小，但它最差**。这就说明：**评估必须使用与训练无关的数据**。

### 1.2 评估体系全景

| 任务类型 | 常用指标 | 方向 | 关键前提 |
| --- | --- | --- | --- |
| **回归** | MAE、MSE、RMSE、$R^2$ | MAE/MSE/RMSE **越小越好**；$R^2$ 越大越好 | 量纲要与 $y$ 可比时用 MAE/RMSE |
| **二分类** | 混淆矩阵、Accuracy、Precision、Recall、F1、ROC-AUC | Accuracy/P/R/F1/AUC **越大越好** | 不平衡数据看 F1/AUC，不看 Accuracy |
| **多分类** | 宏平均（macro）、加权平均（weighted）、micro-F1 | 越大越好 | 类别不平衡时用 weighted，均衡时看 macro |
| **聚类** | SSE、轮廓系数 SC、CH 指数、肘部法 | SSE **越小**；SC/CH **越大** | 均不需要标签 |

### 1.3 数据集划分策略

| 策略 | 做法 | 适用 |
| --- | --- | --- |
| 留出法（hold-out） | 训练 : 测试 = 8:2 或 7:3 | 数据量大（十万级以上） |
| 训练 / 验证 / 测试 | 6:2:2 或 8:1:1 | 需要调超参数时 |
| **K 折交叉验证** | 训练集切 $K$ 份，轮流用 1 份做验证 | 数据量小（几百~几千） |
| **分层 K 折（StratifiedKFold）** | 折分时保持各类别比例 | **类别不平衡**时必用 |
| 留一法（LOO） | 每次留 1 个样本做验证 | 数据极少，代价是训练 $n$ 次 |
| 时间序列切分 | 按时间先后切，**不能随机打乱** | 时序预测（见 [10-数据挖掘案例-电力负荷预测](../06-案例与面试/10-数据挖掘案例-电力负荷预测.md)） |

> **最重要的一条纪律**：**测试集只能用来做最终评估，绝不能参与调参**。一旦你根据测试集分数反复调整，测试集就变成了验证集，分数会乐观偏置。

### 1.4 模型调优的四个方向

| 方向 | 手段 | 代表 |
| --- | --- | --- |
| **数据** | 清洗异常值、增加数据量、处理不平衡、特征工程 | `class_weight='balanced'`、`sample_weight` |
| **模型** | 换算法、降低/提升复杂度 | 决策树 → 随机森林 → XGBoost |
| **超参数** | 网格搜索、随机搜索、交叉验证 | `GridSearchCV`、`RandomizedSearchCV` |
| **正则化** | L1/L2、剪枝、Dropout、早停 | `Ridge`/`Lasso`、`ccp_alpha`、`gamma` |

## 2. 算法细节

### 2.1 回归评估指标

设真实值为 $y_i$、预测值为 $\hat y_i$，样本数 $n$。

**（1）MAE（Mean Absolute Error，平均绝对误差）**

$$\text{MAE} = \frac{1}{n}\sum_{i=1}^{n}\lvert y_i - \hat y_i\rvert$$

- 量纲与 $y$ **相同**，最直观；
- 对**大小误差一视同仁**，对异常值**不敏感**；
- 对应**中位数**意义下的最优拟合。

**（2）MSE（Mean Squared Error，均方误差）**

$$\text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat y_i)^2$$

- 量纲是 $y$ 的**平方**，不直观；
- 处处可导、是凸函数，**适合作训练损失**（配合正规方程有解析解）。

**（3）RMSE（Root Mean Squared Error，均方根误差）**

$$\text{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat y_i)^2}$$

- 量纲与 $y$ **相同**，但与 MSE 同源，**对大误差极其敏感**。

**（4）$R^2$（决定系数）**

$$R^2 = 1 - \frac{\sum(y_i-\hat y_i)^2}{\sum(y_i-\bar y)^2}$$

- 表示"模型解释了目标变量多少比例的方差"，$R^2=1$ 完美，$R^2=0$ 等于只用均值预测，$R^2<0$ 还不如均值。

#### MAE vs RMSE 的数学关系（为什么 RMSE ≥ MAE）

对任意实数序列，**均方根 ≥ 算术平均**（柯西-施瓦茨 / 幂平均不等式）：

$$\sqrt{\frac{1}{n}\sum z_i^2}\ \ge\ \frac{1}{n}\sum|z_i|\quad\Longleftrightarrow\quad \text{RMSE}\ge\text{MAE}$$

**等号成立条件**：所有 $|z_i|$ 相等。

**数值例**：两个误差 1 和 3

$$\text{MAE} = \frac{1+3}{2}=2,\qquad \text{RMSE} = \sqrt{\frac{1^2+3^2}{2}}=\sqrt{5}\approx2.236$$

**结论**：
- RMSE 公式里有**平方项**，大误差被平方后放大，所以**大多数情况下 RMSE > MAE**；
- **RMSE 会放大预测误差较大样本的影响，MAE 只给出平均误差**；
- 误差分布越不均匀（有极端大误差），RMSE 与 MAE 的差距就越大。

**第二个例子**：在 $y=2x+5$ 上加一项波动 $\sin(x)e^{x/20}$ 后，所有指标都变大，**RMSE 几乎是 MAE 的两倍**，正是因为它对误差大的点敏感。

#### 一个重要的反问（原题）

> **"一直按 RMSE 指标训练模型，如果 RMSE 降得非常低，说明什么？"**
> 说明模型**对异常点（噪声）也拟合得非常好**——这正是**过拟合**的信号。所以**评价指标要综合看**。

| 场景 | 更该看 |
| --- | --- |
| 数据含少量偏差很大的异常点 | **MAE**（用 RMSE 可能会选出过拟合的模型） |
| 想强调"最坏情况"、想要平滑梯度 | **RMSE / MSE** |
| 两个模型的数据量不同 | **不适合直接比较 RMSE** |

### 2.2 分类评估指标

**混淆矩阵（二分类）**：

| | 预测正例 | 预测反例 |
| --- | --- | --- |
| **真实正例** | TP（真正例） | FN（伪反例，漏报） |
| **真实反例** | FP（伪正例，误报） | TN（真反例） |

$$\text{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN},\quad
\text{Precision}=\frac{TP}{TP+FP}$$

$$\text{Recall}=\frac{TP}{TP+FN},\quad
F_1 = \frac{2\cdot P\cdot R}{P+R},\quad
\text{TPR}=\text{Recall},\quad \text{FPR}=\frac{FP}{FP+TN}$$

**经典对比（6 恶性 + 4 良性）**：

| 指标 | 模型 A（对 3 恶 4 良） | 模型 B（对 6 恶 1 良） |
| --- | --- | --- |
| TP / FN / FP / TN | 3 / 3 / 0 / 4 | 6 / 0 / 3 / 1 |
| Accuracy | 70% | 70% |
| Precision | 100% | 67% |
| Recall | 50% | 100% |
| F1 | 67% | 80% |

**两个模型准确率完全相同，但适用场景完全不同**：医疗筛查选 B（不能漏诊），垃圾邮件过滤选 A（不能误杀）。

**多分类的两种平均方式（ API 说明）**：

| 平均方式 | 计算 | 适用 |
| --- | --- | --- |
| `macro avg`（宏平均） | 各类别指标**直接平均**，不考虑样本数权重 | **数据集比较平衡**时 |
| `weighted avg`（加权平均） | 按各类别**样本数加权**平均 | **数据集不平衡**时 |

**AUC 速查**：$[0,1]$，$1$ 完美，$0.5$ 随机猜测，$<0.5$ 说明方向反了。AUC 只依赖**排序**，与阈值和类别比例无关，因此最适合不平衡数据；但它对正负样本的**绝对概率校准**不敏感。

### 2.3 聚类评估指标（无标签）

| 指标 | 公式 | 方向 | 侧重 |
| --- | --- | --- | --- |
| SSE（`inertia_`） | $\sum_k\sum_{x\in C_k}\|x-\mu_k\|^2$ | 越小越好 | 只有簇内聚 |
| 轮廓系数 SC | $s_i=\dfrac{b_i-a_i}{\max(a_i,b_i)}$，取全体平均 | 越大越好，$[-1,1]$ | 簇内聚 + 簇间分离 |
| CH 指数 | $\dfrac{\text{SSB}/(k-1)}{\text{SSW}/(n-k)}$ | 越大越好 | 簇内聚 + 簇间离 + 质心个数 |
| 肘部法 | SSE 曲线的拐点 | 拐点处取 $K$ | 用 SSE 确定 $K$（不是独立指标） |

**注意**：SSE 随 $K$ 单调下降（$K=n$ 时为 0），**不能单独用于选 $K$**。详细推导见 [07-KMeans聚类](../04-集成与无监督/07-KMeans聚类.md)。

### 2.4 交叉验证（Cross Validation）

**做法**：把**训练集**切成 $n$ 份（$n$ 即折数，常用 5 或 10），每次拿其中 1 份作验证集、其余 $n-1$ 份作训练集，重复 $n$ 次。

以 $n=5$ 为例：

| 轮次 | 训练用 | 验证用 |
| --- | --- | --- |
| 1 | 第 2,3,4,5 份 | 第 1 份 |
| 2 | 第 1,3,4,5 份 | 第 2 份 |
| 3 | 第 1,2,4,5 份 | 第 3 份 |
| 4 | 第 1,2,3,5 份 | 第 4 份 |
| 5 | 第 1,2,3,4 份 | 第 5 份 |

**最终得分 = 5 次验证得分的平均值。**

**描述的完整流程**：
1. 把数据集划分为 `cv=10` 份；
2. 第一次：第一份做验证集，其他做训练；
3. 第二次：第二份做验证集，其他做训练；
4. ……以此类推，总共训练 10 次、评估 10 次；
5. 取 10 次评估的**平均值**作为该超参数组合的交叉验证得分；
6. **若 $k=5$ 模型得分最好，再使用「全部训练集（训练+验证）」对 $k=5$ 的模型重新训练一遍**，最后用测试集评估。

**为什么需要交叉验证**：

| 好处 | 说明 |
| --- | --- |
| 每个样本都参与过验证 | 评估更充分，不浪费数据 |
| 得分更稳定 | 单次留出法的评估方差大，CV 取平均降低了随机性 |
| 能估计模型稳定性 | 各折得分的标准差本身就是"稳不稳"的度量 |

**常见的 CV 变体**：

| 类 | 用途 |
| --- | --- |
| `KFold(n_splits, shuffle)` | 普通 K 折 |
| `StratifiedKFold(n_splits, shuffle)` | **分层** K 折，保持各类别比例（分类/不平衡数据必用） |
| `LeaveOneOut` | 留一法 |
| `TimeSeriesSplit(n_splits)` | 时序数据，**只用过去预测未来**，禁止打乱 |
| `cross_val_score(estimator, X, y, cv)` | 快速得到 CV 得分数组 |

### 2.5 网格搜索（Grid Search）

**做法**：把候选超参数做**笛卡尔积**，对每一组参数做交叉验证评分，取最高分的组合。

**复杂度**：若有两组超参数分别有 $a$、$b$ 个候选值、CV 折数为 $c$，则总共要训练 $a\times b\times c$ 次。

**例（随机森林）**：

```python
param = {"n_estimators": [40, 50, 60, 70],
"max_depth": [2, 4, 6, 8, 10],
"random_state": [9]}
grid_search = GridSearchCV(estimator, param_grid=param, cv=2)
```

一共 $4\times5\times1\times2 = 40$ 次训练。

**关键属性**：

| 属性 | 含义 |
| --- | --- |
| `best_score_` | 交叉验证中所有参数组合的**最高平均验证得分** |
| `best_params_` | 最优超参数字典 |
| `best_estimator_` | 用最优参数在**全部训练集**上重新拟合好的估计器 |
| `cv_results_` | 每组的 `mean_test_score`、`std_test_score`、`rank_test_score` 等详情 |
| `score(X_test, y_test)` | 用最优模型在测试集上评估（**这才是最终成绩**） |

> **注意**：`best_score_` 常常略高于测试集得分，这是正常的（数据量、折数的随机性导致）。学习笔记也提示过："因为数据量和特征的问题，该值可能小于上述的平均测试得分。"

**网格搜索的替代方案**：

| 方法 | 特点 |
| --- | --- |
| `RandomizedSearchCV` | 随机采样参数组合，参数空间大时效率更高 |
| 贝叶斯优化（Optuna、Hyperopt） | 用历史评估结果指导下一次采样，最省算力 |
| 手动调参 | 参数少时更快，但可复现性差 |

### 2.6 过拟合、欠拟合与解决手段

**概念**：

| 状态 | 训练集 | 测试集 | 本质 |
| --- | --- | --- | --- |
| 欠拟合 | 差 | 差 | 偏差大，模型过于简单 |
| 良好 | 好 | 好 | 偏差方差平衡 |
| 过拟合 | 好 | 差 | 方差大，模型过于复杂/数据太脏/数据太少 |

**偏差-方差分解**（完整推导见 [01-机器学习概述与流程](../01-基础与特征工程/01-机器学习概述与流程.md)）：

$$\mathbb{E}\big[(y-\hat f)^2\big] = \text{Bias}^2[\hat f] + \text{Var}[\hat f] + \sigma^2$$

**诊断表**：

| 现象 | 训练误差 | 验证误差 | 二者差距 | 诊断 | 处方 |
| --- | --- | --- | --- | --- | --- |
| A | 高 | 高（≈训练） | 小 | 欠拟合 | 加特征、加复杂度、减小正则化 |
| B | 低 | 高 | **大** | 过拟合 | 加数据、正则化、降复杂度、剪枝、早停 |
| C | 低 | 低 | 小 | 理想 | 可以上线 |

**欠拟合的解决办法**（从数据、模型、算法三个角度）：

| 手段 | 说明 |
| --- | --- |
| 添加其他特征项 | "组合"、"泛化"、"相关性"三类特征是特征添加的重要手段 |
| 添加多项式特征项 | 把线性模型通过二次/三次项变强（如 $X\to[X, X^2]$） |
| 更换更强的模型 | 线性回归 → 决策树 → 集成模型 |
| 减小正则化力度 | $\alpha\downarrow$ / $C\uparrow$ |
| 减少早停的严格程度 | 允许训练更久 |

**过拟合的解决办法**：

| 手段 | 具体做法 | 代表参数 |
| --- | --- | --- |
| 重新清洗数据 | 处理异常点、数据不纯的地方 | —— |
| 增大训练数据量 | 增加数据量会缓解"训练得太过了" | —— |
| **正则化** | L1（Lasso）/ L2（Ridge）/ Dropout | `alpha`、`C`、`penalty` |
| 减少特征维度 | 防维数灾难；特征多、样本少时学习不充分 | PCA、特征选择 |
| 降低模型复杂度 | 决策树剪枝、限制深度、限制叶子样本数 | `max_depth`、`min_samples_leaf` |
| 早停（early stopping） | 验证集误差不再下降就停 | `early_stopping_rounds`（XGBoost） |
| 集成 | Bagging 天然降方差 | 随机森林 |

**早停的定义（原题）**：`Early stopping` 是当模型训练到某个**固定的验证错误率阈值**（或验证误差不再改善）时，及时停止模型训练。

### 2.7 类别不平衡的处理

**危害**：若负样本占 74%，模型全部预测负例就有 74% 准确率，但 F1 为 0。

**处理手段**：

| 层面 | 手段 | API / 做法 |
| --- | --- | --- |
| 数据层 | 过采样少数类（SMOTE） | `imblearn.over_sampling.SMOTE` |
| 数据层 | 欠采样多数类 | `imblearn.under_sampling.RandomUnderSampler` |
| 算法层 | 类别权重 | `class_weight='balanced'` |
| 算法层 | 样本权重 | `class_weight.compute_sample_weight('balanced', y)` 传给 `fit(sample_weight=...)` |
| 评估层 | 换指标 | F1、AUC、PR 曲线、`classification_report` |
| 折分层 | 分层抽样 | `StratifiedKFold` / `train_test_split(stratify=y)` |

**实例（XGBoost 红酒品质分类）**：

```python
classes_weights = class_weight.compute_sample_weight(class_weight='balanced', y=y_train)
estimator.fit(x_train, y_train, sample_weight=classes_weights)
```

**实例（电信客户流失）**：`Churn_Yes` 占比约 26%，属于标签不平衡样本，因此重点关注 Precision、Recall 与 AUC。

## 3. 可运行示例

### 3.1 回归指标：手算与 API 对照，看清 MAE/RMSE 的差异

```python
# -*- coding: utf-8 -*-
"""回归指标：MAE / MSE / RMSE / R2 的手算与 API 对照"""
import numpy as np
from sklearn.metrics import (mean_absolute_error, mean_squared_error, r2_score,
root_mean_squared_error)

y_true = np.array([3.0, -0.5, 2.0, 7.0])
y_pred = np.array([2.5, 0.0, 2.0, 8.0])

mae = np.mean(np.abs(y_true - y_pred))
mse = np.mean((y_true - y_pred) ** 2)
rmse = np.sqrt(mse)

print(f"手算 MAE={mae:.4f} MSE={mse:.4f} RMSE={rmse:.4f}")
print(f"sklearn MAE={mean_absolute_error(y_true, y_pred):.4f} "
f"MSE={mean_squared_error(y_true, y_pred):.4f} "
f"RMSE={root_mean_squared_error(y_true, y_pred):.4f} "
f"R2={r2_score(y_true, y_pred):.4f}")

print("\n--- RMSE 对大误差的放大效应 ---")
for errs in ([1, 1, 1, 1], [1, 3, 0, 0], [1, 20, 0, 0]):
 e = np.array(errs, dtype=float)
 print(f"误差 {errs}: MAE={np.abs(e).mean:6.3f} RMSE={np.sqrt((e**2).mean):6.3f} "
 f"RMSE/MAE={np.sqrt((e**2).mean)/np.abs(e).mean:.3f}")
 # 误差越不均匀，RMSE 与 MAE 的比值越大
```

## 4. 常见坑

| # | 坑 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- | --- |
| 1 | 用测试集调参 | 测试分数虚高，线上掉分 | 测试集信息通过决策泄漏进模型 | `GridSearchCV` 只在训练集；测试集只评一次 |
| 2 | 类别不平衡只看 Accuracy | 99% 准确率却毫无价值 | 全预测多数类就能刷分 | 看 F1/AUC/PR 曲线，或用 `class_weight='balanced'` |
| 3 | `roc_auc_score` 传 0/1 预测值 | AUC 与 Accuracy 几乎相同 | AUC 需要**概率/置信度** | 传 `predict_proba(X)[:, 1]` |
| 4 | 不指定 `pos_label` | P/R 与预期相反 | sklearn 默认把**少数类**当正例 | 显式传 `pos_label` |
| 5 | 只用 SSE 选 $K$ | 永远选最大的 $K$ | $K=n$ 时 SSE $=0$ | 用肘部法看拐点，或 SC/CH |
| 6 | 用普通 `KFold` 做分类 | 某折中某类样本极少 | 类别不均衡 + 随机折分 | 用 `StratifiedKFold` |
| 7 | 时序数据随机划分 | 离线指标好、线上崩溃 | **未来信息泄漏**到训练集 | 用 `TimeSeriesSplit` 或按时间切分 |
| 8 | 标准化在划分之前做 | 指标虚高 | 测试集统计量泄漏 | 先划分，训练集 `fit_transform`、测试集 `transform` |
| 9 | 把 `best_score_` 当最终成绩 | 报出的分数偏乐观 | `best_score_` 是训练集内 CV 的最优值 | 最终报告 `grid.score(X_test, y_test)` |
| 10 | 网格搜索参数范围过大 | 训练时间爆炸 | 组合数是笛卡尔积 | 先粗后细，或用 `RandomizedSearchCV` |
| 11 | 只看单一指标 | 结论片面 | 每个指标只反映一个侧面 | 回归看 MAE+RMSE，分类看 F1+AUC，聚类看 SC+CH |
| 12 | 用 RMSE 作唯一优化目标 | 模型拟合噪声 → 过拟合 | RMSE 放大异常点 | 综合 MAE 与 RMSE，或先清洗异常点 |
| 13 | 忘记 CV 得分的标准差 | 误以为模型很稳 | 均值高但方差大同样不可靠 | 报告 `mean ± std` |
| 14 | 交叉验证后没在全量训练集上重训 | 浪费了验证折的数据 | 选完超参数应把训练集全部用上 | 用 `best_estimator_`（已自动重训） |

## 5. 面试问答

<details markdown="1"><summary markdown="1">Q1：交叉验证的作用是什么？为什么它比单次留出法更可靠？什么时候必须用 StratifiedKFold？</summary>

**参考答案**

**作用**：
1. **充分利用数据**：每个样本都会在某一折中充当验证样本，避免了单次留出法"20% 数据只用来评估"的浪费；
2. **评估更稳定**：单次留出的得分受划分随机性影响大（换一个 `random_state` 分数可能差好几个点），CV 取 $K$ 次平均显著降低评估方差，同时 `std` 本身就给出了模型的稳定性信息；
3. **支撑超参数选择**：`GridSearchCV` 的评分就是 CV 平均分，是选参数的客观依据；
4. **数据量小时几乎必需**：几百条样本用 8:2 划分，测试集只有几十条，结论不可信。

**相比单次留出法**：
| 维度 | 单次留出 | K 折交叉验证 |
| --- | --- | --- |
| 数据利用 | 测试部分完全不参与训练 | 每折都参与训练 $K-1$ 次 |
| 评估方差 | 大 | 小（$\propto 1/K$） |
| 计算量 | $1\times$ | $K\times$ |
| 适用数据量 | 大（十万级+） | 小到中等 |

**必须用 `StratifiedKFold` 的情况**：
1. **分类任务且类别不平衡**（如欺诈 1%、流失 26%）：普通 KFold 可能让某一折里正样本只剩几个甚至 0 个，导致该折指标剧烈波动甚至报错。分层折保证**每折的类别比例与原数据一致**；
2. 多分类任务中某些类别样本极少时；
3. 与之配套，`train_test_split` 也要加 `stratify=y`。

**注意**：回归任务不能分层（标签连续）；时序任务必须用 `TimeSeriesSplit`，因为随机折分会让"未来"数据出现在训练集里造成泄漏。
</details>

<details markdown="1"><summary markdown="1">Q2：MAE 和 RMSE 有什么区别？应该用哪个？</summary>

**参考答案**

**公式与量纲**：

$$\text{MAE}=\frac1n\sum|y_i-\hat y_i|,\qquad \text{RMSE}=\sqrt{\frac1n\sum(y_i-\hat y_i)^2}$$

两者量纲都与 $y$ 相同，但 RMSE 因含**平方项**而**放大大误差的影响**。

**数学关系**：由幂平均不等式，$\text{RMSE}\ge\text{MAE}$，等号当且仅当所有误差绝对值相等时成立。误差分布越不均匀，两者差距越大。数值例：误差 $\{1,3\}$ 时 MAE $=2$、RMSE $=\sqrt5\approx2.236$；加入强波动项后 RMSE 接近 MAE 的两倍。

**统计意义**：
- **MAE 的最优常数预测是中位数**，对异常值稳健，反映"真实的平均误差"；
- **RMSE 的最优常数预测是均值**，对异常值敏感，反映"大误差被严厉惩罚后的误差"。

**选择建议**：

| 场景 | 选择 | 理由 |
| --- | --- | --- |
| 数据有少量偏差很大的异常点 | **MAE** | 用 RMSE 选模型可能选出过拟合的模型（去硬拟合异常点） |
| 想强调"不能有很差的预测" | **RMSE** | 平方项让大误差无法被平均掉 |
| 需要可导的损失来训练 | **MSE/RMSE** | MAE 在 0 点不可导 |
| 两个模型的数据量不同 | **都不适合直接比** | RMSE/MAE 都受数据分布影响 |

**的重要提醒**：不要只盯着一个指标。**如果 RMSE 被压得非常低，说明模型对异常点（噪声）也拟合得非常好 —— 这往往是过拟合的信号**。所以评价指标要综合看，通常同时报告 MAE 和 RMSE。
</details>

<details markdown="1"><summary markdown="1">Q3：网格搜索、随机搜索、贝叶斯优化如何选择？`GridSearchCV` 的 `best_score_` 和测试集分数为什么不一样？</summary>

**参考答案**

**三种搜索方式的对比**：

| 方法 | 原理 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| 网格搜索 `GridSearchCV` | 笛卡尔积穷举 | 结果可复现、小空间内能找到最优 | 组合数指数增长；高维空间算力爆炸 | 参数少（2~3 个），每个参数候选值少 |
| 随机搜索 `RandomizedSearchCV` | 从分布中随机采样固定次数 | 高维空间效率远高于网格；可控制预算 | 不保证找到最优 | 参数多、范围大 |
| 贝叶斯优化（Optuna/Hyperopt） | 用已评估点建模，指导下一次采样 | 最省算力，能自动聚焦好区域 | 实现复杂、结果有随机性 | 单次训练很贵（如深度学习） |

**`best_score_` 与测试集分数不同的原因**：
1. **数据不同**：`best_score_` 是**训练集内部交叉验证**的平均分，而测试集是**完全独立的另一批数据**。分布差异、采样噪声都会造成差值；
2. **选择偏差**：`best_score_` 是"从很多组参数里挑出的最大值"，本质上是**乐观偏置**——你挑了那一组恰好在该训练集 CV 上表现最好的参数，含有一部分"运气"成分；
3. **折数/数据量**：CV 的每折只用了 $\frac{K-1}{K}$ 的训练数据，而最终的 `best_estimator_` 是在**全部训练集**上重新拟合的，模型容量略有差异；
4. **随机性**：`random_state` 不同、折分不同，分数会有波动。

**正确做法**：
- 报告结果时分清口径：先写"CV 平均分 $0.86\pm0.02$"，再写"独立测试集得分 $0.84$"；
- **不要用测试集去挑参数**，测试集只在最后用一次；
- 若两者差距非常大（如 CV 0.95 / 测试 0.70），说明数据划分有问题（可能发生了泄漏）或数据分布不一致，需要检查流程。
</details>

## 6. 自测题

<details markdown="1"><summary markdown="1">1. 某回归模型在测试集上真实值 $y=[3,-0.5,2,7]$，预测值 $\hat y=[2.5,0,2,8]$，求 MAE、MSE、RMSE，并说明为什么 RMSE > MAE。</summary>

误差 $e = y - \hat y = [0.5,\ -0.5,\ 0,\ -1]$

- $\text{MAE} = \dfrac{0.5+0.5+0+1}{4} = 0.5$
- $\text{MSE} = \dfrac{0.25+0.25+0+1}{4} = \dfrac{1.5}{4} = 0.375$
- $\text{RMSE} = \sqrt{0.375}\approx0.6124$

**为什么 RMSE > MAE**：RMSE 公式含平方项，误差 $0.5$、$0.5$、$0$、$1$ **大小不等**，平方后大误差（$1$）被放大为 $1$，而小误差（$0.5$）被压缩为 $0.25$，导致均方根大于算术平均。只有当所有误差绝对值相等时两者才相等。
</details>

<details markdown="1"><summary markdown="1">2. 混淆矩阵为 TP=40, FN=10, FP=20, TN=130。求 Accuracy、Precision、Recall、F1、TPR、FPR，并说明该模型更适合什么场景。</summary>

- $\text{Accuracy}=\dfrac{40+130}{200}=0.85$
- $\text{Precision}=\dfrac{40}{60}\approx0.667$
- $\text{Recall}=\dfrac{40}{50}=0.80$
- $F_1=\dfrac{2\times0.667\times0.80}{0.667+0.80}\approx0.727$
- $\text{TPR}=\text{Recall}=0.80$
- $\text{FPR}=\dfrac{20}{150}\approx0.133$

**场景判断**：Precision 0.667 偏低（误报较多），Recall 0.80 尚可（漏报较少），FPR 0.133 较低。这说明模型**偏向"宁可多报也不漏报"**，适合**癌症筛查、欺诈预警、地震预警**这类"漏报代价远大于误报"的场景；如果用于"垃圾邮件过滤"（误杀代价高），则需要提高阈值以提升 Precision。
</details>

<details markdown="1"><summary markdown="1">3. 5 折交叉验证的具体流程是什么？为什么必须用验证集（而不是测试集）来选超参数？</summary>

**流程**：把**训练集**平均切成 5 份；第 1 次用第 1 份做验证集、第 2~5 份做训练集；第 2 次用第 2 份做验证集、其余作训练集；以此类推共训练并评估 5 次；取 5 次得分的**平均值**作为该超参数组合的分数。比较所有候选参数的 CV 平均分，选出最优组合，然后用**全部训练集**重新训练该模型，最后在测试集上评估**一次**。

**为什么不能用测试集选超参数**：因为一旦用测试集分数来决定"用哪个参数、要不要加特征"，测试集的信息就通过你的决策链条**泄漏**进了模型选择过程。你会发现"挑来挑去测试集分数越来越高"，但那只是因为你在这批特定数据上过拟合了——**测试集已经变成了验证集**，它给出的分数会系统性乐观偏置，无法代表模型在新数据上的真实泛化能力。

正确做法：训练集 → （CV 选参数）→ 用全部训练集重训 → 测试集一次定论。
</details>

<details markdown="1"><summary markdown="1">4. 训练集准确率 0.99、验证集 0.72，你会怎么处理？如果训练集 0.62、验证集 0.60 呢？</summary>

**第一种（过拟合，差距 0.27）**：
1. 增加训练数据 / 数据增强；
2. 加正则化：L2（Ridge）、L1（Lasso）、树的剪枝 `ccp_alpha`、XGBoost 的 `gamma`/`lambda`；
3. 降低模型复杂度：限制 `max_depth`、`min_samples_leaf`、减少特征数；
4. 特征降维或特征选择；
5. 早停（early stopping）；
6. 检查数据是否有泄漏（特征里混入了标签相关但线上不可得的信息）。

**第二种（欠拟合，两者都低）**：
1. 增加更有判别力的特征（组合、交叉、多项式特征）；
2. 换更强的模型（线性 → 树 → 集成）；
3. 减小正则化强度（`alpha` 降、`C` 升）；
4. 放宽早停条件、增加训练轮数；
5. 检查是否有预处理错误（如标准化用错、类别特征没编码）；
6. 注意：**此时加数据几乎无用**。
</details>

<details markdown="1"><summary markdown="1">5. 类别不平衡（正例 1%）时，应该用哪些指标和手段？</summary>

**指标**：
1. **不要用 Accuracy** —— 全预测负例就有 99%；
2. 用 **F1**（兼顾 Precision 与 Recall）；
3. 用 **AUC**（只依赖排序，与阈值、与类别比例无关）；
4. 极端不平衡（如 1:1000）时 ROC 会偏乐观，改用 **PR 曲线 / Average Precision**；
5. 用 `classification_report` 分别看每个类别的 P/R/F1。

**手段**：

| 层面 | 手段 |
| --- | --- |
| 数据 | 过采样少数类（SMOTE）、欠采样多数类、组合采样 |
| 算法 | `class_weight='balanced'`、`sample_weight=class_weight.compute_sample_weight('balanced', y)` |
| 折分 | `StratifiedKFold`、`train_test_split(stratify=y)` |
| 阈值 | 不用默认 0.5，按业务成本在 PR 曲线上挑最优阈值 |
| 模型 | 集成模型（随机森林/GBDT/XGBoost）通常比单一模型更稳 |
| 评估 | 报告 mean ± std，并做多次随机划分验证稳定性 |
</details>
