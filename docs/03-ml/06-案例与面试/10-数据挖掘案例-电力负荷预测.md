## 1. 核心思想

### 1.1 什么是时间序列预测

**时间序列预测**：根据**历史时间序列数据**来预测未来值的方法。

任务听起来简单，但引用了几句话来提醒难度："预测非常困难，特别是关于未来。—— 尼尔斯·波尔"；"我可以算准天体的运行轨迹，但算不清人性的复杂。—— 牛顿"。

**关键洞察**：不论是传统机器学习还是深度学习，**解决方案主要是把时序数据处理成二维的结构化数据集**，再训练模型。所以这个项目的核心工作量不在模型，而在**特征工程**。

### 1.2 时序预测的四类任务场景

| 任务分类 | 时序变量数量 | 预测时间步 | 实现方案 |
| --- | --- | --- | --- |
| **单变量单步** | 1 个 | 1 个 | 直接建模预测（一个特征） |
| **单变量多步** | 1 个 | 多个 | 方案 1：建模 + **滚动预测**（把预测值作为特征）；方案 2：不同时间步分别建模 |
| **多变量单步** | 多个 | 1 个 | 直接建模预测（多个特征）← **本案例属于这一类** |
| **多变量多步** | 多个 | 多个 | 方案 1：建模（多特征）+ 滚动预测；方案 2：不同时间步分别建模；方案 3：直接建模（深度学习中可实现**序列-序列**建模） |

> **辨析**："单变量/多变量"指的是**输入中用了几个时序变量**，不是指特征工程后有几列特征。本案例只有 `power_load` 一个被预测的时序变量，但它被展开了 39 个派生特征列（24 个小时 one-hot + 12 个月份 one-hot + 3 个滑窗），再加 1 个 `yesterday_load`，**合计 40 列**用于预测下 1 步，因此是**多变量单步**。

### 1.4 三类算法的选择

| 类别 | 代表方法 | 特点 |
| --- | --- | --- |
| **基于统计学的经典时序算法** | 统计朴素法、简单平均法、移动平均法、简单指数平滑法、Holt 线性趋势法、AR、MA、**ARIMA** | 需要**平稳性检验**，模型本身有平稳性与白噪声假设，**存在局限性，准确性通常低于机器学习模型** |
| **传统机器学习算法** | 线性回归、决策树、随机森林、**XGBoost**、LightGBM、SVM 等所有回归模型 | 核心是把时序处理成二维结构化数据集；工程落地最常用 |
| **深度学习算法** | RNN 类（LSTM、GRU）、基于大模型的 iTransformer | 通常使用编解码结构（seq2seq）；适合长序列、大数据量 |

**统计学方法速览（了解即可）**：

| 方法 | 预测值 = | 一句话说明 |
| --- | --- | --- |
| 统计朴素法 | 昨天的值 | 今天等于明天，适用于短期稳定序列 |
| 简单平均法 | 历史上**所有**值的平均 | 适用于"小幅波动但均值稳定" |
| 移动平均法 | 最近**一个时间窗口**内的平均 | 适用于有明显升降趋势、不能全用历史 |
| 简单指数平滑法 | 历史值的**指数加权**平均 | 近期权重更大，远期权重指数下降 |
| Holt 线性趋势法 | 水平方程 $L_t$ + 趋势方程 $B_t$ | 显式建模线性增长/下降趋势 |
| AR 自回归 | 过去值的线性组合 | 假设当前值可由自身过去值线性表示 |
| MA 移动平均（模型） | 均值 + 白噪声项 | 假设当前值可由**过去的白噪声（误差）**线性表示 |
| ARIMA$(p,d,q)$ | 自回归 + 差分 + 移动平均 | $p$ 自回归项数、$d$ 差分阶数、$q$ 滑动平均项数 |

### 2.3 数据预处理（utils/common.py）

```python
def data_preprocessing(path):
 """
 1.获取数据源
 2.时间格式化，转为 2024-12-20 09:00:00 这种格式
 3.按时间升序排序
 4.去重
 """
 data = pd.read_csv(path)
 data['time'] = pd.to_datetime(data['time']).dt.strftime('%Y-%m-%d %H:%M:%S')
 data.sort_values(by='time', inplace=True)
 data.drop_duplicates(inplace=True)
 return data
```

**四步的必要性**：

| 步骤 | 为什么必须做 |
| --- | --- |
| 时间格式化 | 后续要用**字符串切片** `str[11:13]` 取小时、`str[5:7]` 取月份；格式不统一会切成垃圾 |
| 按时间升序 | 滑窗特征 `shift(i)` 的语义依赖"上一行 = 上一小时"，顺序错则特征完全错误 |
| 去重 | 重复的时间戳会让"昨日同时刻"字典出现覆盖，也可能导致数据泄漏 |
| 提前做（在特征工程前） | 保证后续所有特征都在干净、有序的数据上构造 |

**MAPE（平均绝对百分比误差）工具函数**：低版本 sklearn 没有该指标，需自己实现。但要注意这份实现有个**潜在问题**——它是误差率乘 100 **再取算术平均**，而正确口径通常是"先算 $\lvert(y-\hat y)/y\rvert$ 的均值，再乘 100"，若 $y$ 中存在 0 会除零。

$$\text{MAPE} = \frac{1}{n}\sum_{i=1}^{n}\left\lvert\frac{y_i-\hat y_i}{y_i}\right\rvert\times100\%$$

> **分析的结论要落到特征设计上**：如果"各小时平均负荷"呈现明显的峰谷（早高峰、晚高峰），就说明**小时是有判别力的特征**，必须加入；如果"月份均值"差异明显，就说明**月份特征有效**。这正是下一步特征工程的依据。

### 2.5 特征工程（重点）

**目标**：把 `[time, power_load]` 两列展开成机器学习可用的二维宽表。

**三类特征（共 40 列）**：

| 特征类别 | 列名 | 列数 | 构造方法 |
| --- | --- | --- | --- |
| 短期时间特征 | `hour_00` … `hour_23` | 24 | `time.str[11:13]` + `pd.get_dummies` |
| 长期时间特征 | `month_01` … `month_12` | 12 | `time.str[5:7]` + `pd.get_dummies` |
| 相近时间窗口负荷 | `前1小时`、`前2小时`、`前3小时` | 3 | `power_load.shift(i)`（`window_size=3`） |
| 昨日同时刻负荷 | `yesterday_load` | 1 | 时间→负荷字典 + `to_timedelta('1d')` |
| **合计** | —— | **40** | —— |

> **以 `predict.py` 中的 `feature_names` 为准**：24（hour）+ 12（month）+ 3（前 N 小时）+ 1（yesterday_load）= **40 列**。训练端 `feature_engineering` 返回的 `time_feature_names` 与此必须完全一致。

> **原始代码中的一个真实 Bug（必须修正）**： `pred_feature_extract` 用**写死的切片下标**从列名反查取值：
> ```python
> pred_hour = time[11:13] # 两位，如 '00'、'09'、'19'
> for i in range(24):
> if pred_hour == feature_names[i][5:7]: # 'hour_9'[5:7] == '9'；'hour_19'[5:7] == '19'
> ```
> `pd.get_dummies` 生成的列名是 `hour_0`、`hour_9`、`hour_10` 这种**无前导零**的格式，长度在 6~7 之间浮动，于是：
> - **小时 0（`'hour_0'[5:7] == '0'`）** 与预测值 `'00'` **永不相等** → 凌晨 0 点的 `hour` one-hot **恒为全 0**；
> - **月份 1~9（`'month_9'[6:8] == '9'`）** 与预测值 `'09'` **永不相等** → 这些月份的 `month` one-hot **恒为全 0**。
>
> 结果是预测时特征与训练时**分布不一致**（每月前 9 天、每天 0 点的样本都拿不到正确的时间特征），会静默拉低精度且极难排查。**正确做法**：不要用固定下标切片，统一用 `split('_')[1]` 取后缀，并把预测时间的两位数字去掉前导零（见下面示例代码）。

**实现（完整代码）**：

```python
def feature_engineering(data, logger):
 """
 1.提取出时间特征：月份、小时
 2.提取出相近时间窗口中的负荷特征：step 大小窗口的负荷
 3.提取昨日同时刻负荷特征
 4.剔除出现空值的样本
 5.整理时间特征，并返回
 """
 result = data.copy(deep=True)

 # ---- 1. 时间特征 ----
 result['hour'] = result['time'].str[11:13] # 短期时间特征
 result['month'] = result['time'].str[5:7] # 长期时间特征

 # 1.3 对时间特征做 one-hot 编码
 hour_encoding = pd.get_dummies(result['hour'])
 hour_encoding.columns = ['hour_' + str(i) for i in hour_encoding.columns]
 month_encoding = pd.get_dummies(result['month'])
 month_encoding.columns = ['month_' + str(i) for i in month_encoding.columns]
 result = pd.concat([result, hour_encoding, month_encoding], axis=1)

 # ---- 2. 相近时间窗口中的负荷特征 ----
 window_size = 3
 shift_list = [result['power_load'].shift(i) for i in range(1, window_size + 1)]
 shift_data = pd.concat(shift_list, axis=1)
 shift_data.columns = ['前' + str(i) + '小时' for i in range(1, window_size + 1)]
 result = pd.concat([result, shift_data], axis=1)

 # ---- 3. 昨日同时刻负荷特征 ----
 time_load_dict = result.set_index('time')['power_load'].to_dict
 result['yesterday_time'] = result['time'].apply(
 lambda x: (pd.to_datetime(x) - pd.to_timedelta('1d')).strftime('%Y-%m-%d %H:%M:%S'))
 result['yesterday_load'] = result['yesterday_time'].apply(lambda x: time_load_dict.get(x))

 # ---- 4. 剔除出现空值的样本 ----
 result.dropna(axis=0, inplace=True)

 # ---- 5. 整理特征列，并返回 ----
 time_feature_names = (list(hour_encoding.columns) + list(month_encoding.columns)
 + list(shift_data.columns) + ['yesterday_load'])
 return result, time_feature_names
```

**为什么这样设计特征（每个决策的理由）**：

| 设计决策 | 理由 |
| --- | --- |
| 小时/月份用 **one-hot** 而不是直接用 0~23 的数值 | 数值编码下"23 点"与"0 点"相差 23，但实际相邻；one-hot 消除了虚假的距离/大小关系。对树模型而言 one-hot 也让"某些小时"成为独立的可分裂条件 |
| 同时保留 **hour 与 month** | 分别刻画**日内周期**（短期）与**季节周期**（长期） |
| 用 **`shift`** 构造滑窗 | 直接的"上一时刻负荷"是最强的预测因子（负荷具有很强的惯性/自相关） |
| `window_size = 3` | 覆盖最近 3 小时的趋势；窗口越大信息越多但也越容易过拟合、且会删掉更多行 |
| 加 **昨日同时刻** | 捕捉**日周期**；比"前 24 小时"更直接地表达"同一时刻前一天是多少" |
| 最后 **`dropna`** | `shift(1..3)` 会在头部产生 3 行 NaN，"昨日同时刻"在首日产生一整天的 NaN；必须剔除，否则模型训练报错。代价是**损失了前 3 行 + 首日的数据** |

**评价指标的选择**：

| 指标 | 公式 | 为什么用它 |
| --- | --- | --- |
| MSE | $\frac1n\sum(y_i-\hat y_i)^2$ | 放大大误差，敏感于极端偏差 |
| MAE | $\frac1n\sum\lvert y_i-\hat y_i\rvert$ | **量纲与负荷相同**，业务上最直观（"平均错多少 kW"） |

同时输出训练集与测试集的 MSE/MAE，便于对照诊断过拟合（详见 [08-模型评估与调优](../03-评估与调优/08-模型评估与调优.md)）。

> **关于切分方式的重要提示**：完整代码用的是 `train_test_split(test_size=0.3, random_state=22)`，即**随机划分**。对时序数据而言，严格的工程做法应该是**按时间切分**（前 70% 训练、后 30% 测试）。随机划分会把"未来"的数据放进训练集，虽然随机打乱后不存在"用未来预测过去"的严格泄漏（因为特征都来自过去），但会导致测试集里的时间点分布在训练时间范围内部，评估结果比真实上线场景乐观。在 `predict.py` 中通过**滚动推理**弥补了这一点，那才是更接近真实场景的评估。

### 2.7 模型预测（src/predict.py，重点）

**核心思想**：为了**模拟实际场景**，预测某个时刻时，把它以及它之后的所有负荷都"掩盖掉"，只用**该时刻之前**的历史数据构造特征并预测。这是一个**滚动推理（rolling forecast）**过程。

**完整流程 5 步**：

| 步骤 | 内容 | 关键点 |
| --- | --- | --- |
| 1 | 导包、配置绘图字体 | `plt.rcParams['font.family'] = 'SimHei'`，否则中文乱码 |
| 2 | 定义 `PowerLoadPredict` 类 | 配置日志、获取数据源、**历史数据转字典** |
| 3 | 加载模型 | `joblib.load('../model/xgb.pkl')` |
| 4 | **滚动预测** | 确定预测时间段 → 掩盖未来 → 解析特征 → 预测 → 保存真实值与预测值 |
| 5 | 预测结果评价 | 计算 MAE + 绘制真实/预测折线图 |

**为什么把历史数据转成字典**：

```python
self.data_dict = self.data_source.set_index('time')['power_load'].to_dict
```

- 预测时需要对每个时刻反复查询"某一具体时间点的负荷"，如果每次都在 DataFrame 上做条件筛选，开销极大；
- 转成 `dict`（`key: 时间字符串 → value: 负荷`）后查询是 $O(1)$；
- 注释也指出：**实际开发场景中可以使用 Redis 进行缓存**。

**特征解析函数（`pred_feature_extract`）**——预测端必须**手工组装出与训练时列名、列序完全一致的 40 列特征**：

```python
feature_names = ['hour_00', ..., 'hour_23', # 24 列
'month_01', ..., 'month_12', # 12 列
'前1小时', '前2小时', '前3小时', # 3 列
'yesterday_load'] # 1 列

# 1. 小时 one-hot：把预测时间的小时与 hour_00..hour_23 逐一比对
pred_hour = time[11:13]
for i in range(24):
 hour_part.append(1 if pred_hour == feature_names[i][5:7] else 0)

 # 2. 月份 one-hot：注意下标从 24 开始，且切片起点是 [6:8]（"month_01" 的长度差异）
 pred_month = time[5:7]
 for i in range(24, 36):
 month_part.append(1 if pred_month == feature_names[i][6:8] else 0)

 # 3. 历史负荷：前 1/2/3 小时、昨日同时刻；查不到时给默认值 600
 last_1h_load = data_dict.get((pd.to_datetime(time) - pd.to_timedelta('1h')).strftime('%Y-%m-%d %H:%M:%S'), 600)
 last_2h_load = data_dict.get((pd.to_datetime(time) - pd.to_timedelta('2h')).strftime('%Y-%m-%d %H:%M:%S'), 600)
 last_3h_load = data_dict.get((pd.to_datetime(time) - pd.to_timedelta('3h')).strftime('%Y-%m-%d %H:%M:%S'), 600)
 last_day_load = data_dict.get((pd.to_datetime(time) - pd.to_timedelta('1d')).strftime('%Y-%m-%d %H:%M:%S'), 600)
```

**滚动预测主循环**：

```python
# 4.1 确定要预测的时间段：2015-08-01 00:00:00 及以后
pred_times = pred_obj.data_source[pred_obj.data_source['time'] >= '2015-08-01 00:00:00']['time']

evaluate_list = []
for pred_time in pred_times:
 # 4.2 模拟真实场景：只保留预测时间之前的数据（把未来"掩盖"掉）
 data_his_dict = {k: v for k, v in pred_obj.data_dict.items if k < pred_time}

 # 4.3 解析特征并预测
 processed_data, feature_cols = pred_feature_extract(data_his_dict, pred_time, pred_obj.logfile)
 pred_value = model.predict(processed_data[feature_cols])

 # 4.4 取该时刻的真实负荷
 true_value = pred_obj.data_dict.get(pred_time)

 # 4.5 记录【预测时间, 真实值, 预测值】
 evaluate_list.append([pred_time, true_value, pred_value[0]])

 # 4.6 转成 DataFrame
 evaluate_df = pd.DataFrame(evaluate_list, columns=['时间', '真实值', '预测值'])

 # 5.1 计算 MAE
 mae_score = mean_absolute_error(evaluate_df['真实值'], evaluate_df['预测值'])

 # 5.2 画折线图（真实值 vs 预测值），横轴时间太密，用 MultipleLocator(50) 调间隔
```

**为什么这个设计是"最关键的工程点"**：

| 设计 | 意义 |
| --- | --- |
| 每个时刻都重新过滤 `data_his_dict = {k: v for k, v in ... if k < pred_time}` | **严格禁止未来信息泄漏**。注意：这里预测用的是**真实的历史值**（不是把预测值当作下一步的输入），所以预测是"单步预测"而不是"多步自回归滚动" |
| 预测端的 `feature_names` 与训练端完全一致 | 特征列名/列序不一致是时序项目最常见的线上事故 |
| `data_dict.get(key, 600)` 的默认值 | 处理边界情况（如数据缺失），避免 `None` 导致预测崩溃。**注意 600 是硬编码的经验值，稳健做法应改用该小时的历史均值** |
| 逐时刻循环 + 字典查询 | 模拟真实场景（每个小时到来时才有真实数据） |

### 2.8 项目改进方向（总结）

| 角度 | 改进措施 |
| --- | --- |
| **特征工程** | 优化时间窗口大小；提取更有效的历史负荷特征（如多阶差分、滚动均值/方差、同比环比）；扩展**外部特征**：温度、湿度、风速、历史工业用电量、历史居民用电量 |
| **算法** | ① **样本分群然后分别建模**（按地区分组，或先用聚类算法分群，再针对不同分区分别训练模型，提升适用性）；② 寻找更优算法（**LightGBM**、RNN 类、**iTransformer**）；③ 算法组合（**bagging** 或 **stacking**） |
| **预测（推理）速度** | 预测时也需要做特征工程处理，历史负荷可以**缓存到 Redis**，使用时直接查询 |
| **扩展性** | 做**通用工具包**，支持多种数据源（MySQL、PostgreSQL、Oracle、ES、Redis、Hive）；项目**打包成容器**适配各种服务器环境；**预测模块与项目解耦**，封装出接口接收 Web 参数，按参数获取数据并预测 |

### 3.2 特征工程：把时序展开成宽表（可独立运行、含自检）

# -*- coding: utf-8 -*-
"""特征工程：时间 one-hot + 滑窗负荷 + 昨日同时刻负荷
并附一个自检：手动验算某一行特征是否正确对齐
"""
import numpy as np
import pandas as pd

def feature_engineering(data, logger=None, window_size=3):
 result = data.copy(deep=True)

 # ---- 1. 时间特征 ----
 result["hour"] = result["time"].str[11:13]
 result["month"] = result["time"].str[5:7]

 hour_encoding = pd.get_dummies(result["hour"])
 hour_encoding.columns = ["hour_" + str(c) for c in hour_encoding.columns]
 month_encoding = pd.get_dummies(result["month"])
 month_encoding.columns = ["month_" + str(c) for c in month_encoding.columns]
 result = pd.concat([result, hour_encoding, month_encoding], axis=1)

 # ---- 2. 滑窗历史负荷 ----
 shift_list = [result["power_load"].shift(i) for i in range(1, window_size + 1)]
 shift_data = pd.concat(shift_list, axis=1)
 shift_data.columns = ["前%d小时" % i for i in range(1, window_size + 1)]
 result = pd.concat([result, shift_data], axis=1)

 # ---- 3. 昨日同时刻负荷 ----
 time_load_dict = result.set_index("time")["power_load"].to_dict
 result["yesterday_time"] = result["time"].apply(
 lambda x: (pd.to_datetime(x) - pd.to_timedelta("1d")).strftime("%Y-%m-%d %H:%M:%S"))
 result["yesterday_load"] = result["yesterday_time"].apply(lambda x: time_load_dict.get(x))

 # ---- 4. 剔除空值 ----
 result.dropna(axis=0, inplace=True)

 # ---- 5. 特征列清单 ----
 feature_names = (list(hour_encoding.columns) + list(month_encoding.columns)
 + list(shift_data.columns) + ["yesterday_load"])
 return result, feature_names

### 3.4 预测模块：滚动推理 + 评价 + 可视化（可独立运行）

```python
# -*- coding: utf-8 -*-
"""预测模块核心逻辑：解析特征 -> 滚动推理 -> 评价 -> 可视化"""
import joblib
import matplotlib.pyplot as plt
import matplotlib.ticker as mick
import pandas as pd
from sklearn.metrics import mean_absolute_error

plt.rcParams["font.family"] = "SimHei"

# 与训练端完全一致的 40 列特征清单
# 注意：训练端用 pd.get_dummies 生成的小时/月份列名是「无前导零」的（hour_0..hour_9、month_1..month_9），
# 所以这里必须与训练端保持完全相同的命名，否则预测时列名对不上、模型会报 feature_names mismatch。
HOUR_COLS = ["hour_" + str(i) for i in range(24)]
MONTH_COLS = ["month_" + str(i) for i in range(1, 13)]
FEATURE_NAMES = HOUR_COLS + MONTH_COLS + ["前1小时", "前2小时", "前3小时", "yesterday_load"]


def pred_feature_extract(data_dict, time, default_load=600):
 """预测时刻 -> 特征 DataFrame（列名与列序必须与训练一致）"""
 # 1. 小时 one-hot：用 split 取后缀，避免切片下标写死导致长度不一致
 pred_hour = time[11:13].lstrip("0") or "0" # "09" -> "9"，"00" -> "0"
 hour_part = [1 if pred_hour == c.split("_")[1] else 0 for c in HOUR_COLS]
 # 2. 月份 one-hot
 pred_month = time[5:7].lstrip("0") or "0"
 month_part = [1 if pred_month == c.split("_")[1] else 0 for c in MONTH_COLS]
 # 3. 历史负荷：前 1/2/3 小时 + 昨日同时刻
 def get_load(delta):
 t = (pd.to_datetime(time) - pd.to_timedelta(delta)).strftime("%Y-%m-%d %H:%M:%S")
 return data_dict.get(t, default_load)

 his_part = [get_load("1h"), get_load("2h"), get_load("3h"), get_load("1d")]
 return pd.DataFrame([hour_part + month_part + his_part], columns=FEATURE_NAMES)

def rolling_predict(data_source, model, start_time, default_load=600):
 """从 start_time 起逐小时滚动预测，返回 [时间, 真实值, 预测值] 表"""

 pred_times = data_source[data_source["time"] >= start_time]["time"]
 evaluate_list = []
 for pred_time in pred_times:
 # 模拟真实场景：只保留预测时刻之前的数据
 data_his_dict = {k: v for k, v in data_dict.items if k < pred_time}
 feats = pred_feature_extract(data_his_dict, pred_time, default_load)
 pred_value = model.predict(feats)[0]
 evaluate_list.append([pred_time, data_dict.get(pred_time), pred_value])
 return pd.DataFrame(evaluate_list, columns=["时间", "真实值", "预测值"])

 plt.show()

 mae = mean_absolute_error(evaluate_df["真实值"], evaluate_df["预测值"])
 print("模型对新数据进行预测的平均绝对误差(MAE): %.4f" % mae)
 print("相对误差(MAE/真实均值): %.4f%%"
 % (100 * mae / evaluate_df["真实值"].mean()))

 prediction_plot(evaluate_df)
 # 结论：预测负荷曲线应紧密贴合真实负荷曲线，并复现出明显的日周期峰谷。
```

## 4. 常见坑

| # | 坑 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- | --- |
| 1 | 时序数据随机划分 | 离线 MAE 很漂亮，上线差 | 随机划分让测试点落在训练时间区间内部，评估偏乐观 | 按时间切分（前 70% 训练），CV 用 `TimeSeriesSplit` |
| 2 | 滑窗特征用了未来值 | 离线指标异常好（甚至完美） | 例如 `shift(-1)` 或对全量数据算滚动均值 | 滑窗只能用 `shift(+i)`（过去），预测时严格"掩盖未来" |
| 3 | 时间特征用序号不用 one-hot | 模型学到错误关系 | 小时 23 与 0 在序号上差 23，实际相邻 | 离散时间特征做 one-hot |
| 4 | 训练与预测的特征列名/列序不一致 | 预测结果离谱或 `feature_names mismatch` | 预测端手工组装特征容易漏列、错序 | 把特征清单定义为**常量**，训练/预测共用 |
| 5 | **用写死的切片下标从列名反查 one-hot 取值** | 部分时刻/月份的 one-hot 恒为全 0，精度静默下降 | `'hour_0'[5:7]=='0'` 但预测值是 `'00'`；`'month_9'[6:8]=='9'` 但预测值是 `'09'` | 用 `split('_')[1]` 取后缀 + `lstrip('0')`，不要写死下标 |
| 6 | 忘了 `dropna` | `Input contains NaN` | `shift(1..3)` 产生 3 行 NaN，昨日同时刻产生首日 NaN | 特征工程最后 `dropna(axis=0)` |
| 7 | 时间未统一格式化就切片 | 切出垃圾字符 | `str[11:13]` 依赖固定的 `%Y-%m-%d %H:%M:%S` 格式 | 预处理阶段先用 `pd.to_datetime.dt.strftime(...)` 统一 |
| 8 | 数据未排序就算 `shift` | 特征与时间错位 | `shift` 依赖行的物理顺序 | 预处理阶段 `sort_values('time')` |
| 9 | 重复时间戳没去重 | `to_dict` 时后值覆盖前值 | 字典键唯一 | `drop_duplicates` |
| 10 | `data_dict.get(key)` 返回 `None` | 预测时报类型错误 | 边界时间点在历史数据中不存在 | 给默认值（改进：用该小时历史均值而不是硬编码 600） |
| 11 | 直接拿 `XGBRegressor` 默认参数上线 | 效果不稳定 | 未调参 | 用 `GridSearchCV`（最优组合：150 棵树、深度 6、学习率 0.1） |
| 12 | 网格搜索太慢 | 训练时间过长 | 组合数是笛卡尔积 × CV 折数 | 先粗调后细调；用 `n_jobs=-1`；或改 `RandomizedSearchCV` |
| 13 | 只报告测试集 MAE 不看训练集 | 无法判断是否过拟合 | 缺少对照 | 同时输出训练集与测试集的 MSE/MAE，比较两者差距 |
| 14 | 用 MSE 解释业务误差 | 汇报单位不对 | MSE 量纲是负荷的平方 | 业务汇报用 **MAE**（与负荷同量纲）或 **MAPE**（百分比） |
| 15 | 对数或百分比指标出现除零 | `inf` / `nan` | MAPE 的分母是真实值，负荷可能为 0 | 加 `eps`、或改用 **sMAPE**、WAPE |
| 16 | 预测模块与训练模块代码重复 | 特征定义"两套实现"极易不一致 | 复制粘贴导致漂移 | 抽公共函数/常量，或把特征工程封装成可 pickle 的 transformer |
| 17 | 绘图中文乱码 | 图里全是方框 | matplotlib 默认字体不含中文 | `plt.rcParams['font.family'] = 'SimHei'` |
| 18 | 不处理样本不均衡 / 异常负荷 | 模型被极端峰值带偏 | 负荷存在异常高峰、停机等 | 先做异常检测；或对损失加权重、剔除明显异常段 |

## 5. 面试问答

<details><summary>Q1：时序预测有哪几类任务？本案例属于哪一类？实现方案是什么？</summary>

**参考答案**

**四类任务**：

| 任务 | 输入变量 | 预测步数 | 实现方案 |
| --- | --- | --- | --- |
| 单变量单步 | 1 个 | 1 个 | 直接建模（一个特征） |
| 单变量多步 | 1 个 | 多个 | 建模 + **滚动预测**（把预测值作为下一步的特征）；或不同时间步分别建模 |
| 多变量单步 | 多个 | 1 个 | 直接建模（多个特征） |
| 多变量多步 | 多个 | 多个 | 建模 + 滚动预测；或多步分别建模；或深度学习 seq2seq 直接建模 |

**本案例属于「多变量单步」**：
- 目标是预测**下一个小时**的负荷（1 步）；
- 输入使用了多个特征（小时 one-hot 24 列、月份 one-hot 12 列、前 1/2/3 小时负荷、昨日同时刻负荷，共 40 列）。

**实现方案**：把时序数据**处理成二维的结构化数据集**——每一行是一个时刻，列是各类特征，`power_load` 作为目标值，然后训练标准的回归模型（XGBoost）。预测时逐小时滚动，每个时刻只用**该时刻之前**的历史数据构造特征。

**注意**："单变量/多变量"说的是**输入中用了几个时序变量**，不是特征列数。本案例本质上只用到 `power_load` 一个时序变量的历史值（加上由时间戳派生的时间特征）。

**算法选型建议**：统计学方法（ARIMA 等）需要平稳性检验，准确性通常低于机器学习；传统机器学习（XGBoost/LightGBM）在中小规模表格数据上性价比最高；深度学习（LSTM/iTransformer）适合超长序列和丰富的外部变量，但需要更多数据和算力。
</details>

<details><summary>Q2：为什么时序数据的特征工程里，"小时"和"月份"要做 one-hot 而不是直接用数值？</summary>

**参考答案**

**如果直接用数值（0~23、1~12）会遇到什么问题**：

1. **引入虚假的距离关系**。数值编码隐含"23 与 0 相差 23"，但一天是循环的，23 点与 0 点实际上**相邻**。对基于距离的模型（KNN、SVM、线性模型的正则项）会严重误导；对树模型虽然影响小些，但树只能通过"多次分裂"来近似"23 或 0"这种条件，效率低、需要更多深度。
2. **引入虚假的大小关系**。模型会认为"12 月 > 1 月"，但月份之间没有序数意义（不像"学历"有高低）。
3. **周期不连续**。数值编码下"年末到年初"的跳变无法被模型平滑捕捉。

**one-hot 的好处**：
- 每个取值独立成一列，**不引入任何距离或大小假设**；
- 每个小时/月份都可以被模型分配独立的权重（如"19 点晚高峰"单独一个系数），表达能力强；
- 树模型可以只用一个分裂条件就选出"某些小时"，效率高。

**代价与替代方案**：
- 代价是维度增加（24 + 12 = 36 列），数据量小的时候可能过拟合；
- 替代方案：**周期编码（cyclical encoding）** 用 $\sin(2\pi h/24)$、$\cos(2\pi h/24)$ 两列表达"循环性"，维度低且保留邻近关系，适用于深度学习或对维度敏感的场景。

**工程折中**：在负荷预测中，因为"小时"本身具有强烈的高峰/低谷模式（的数据分析图正是用来验证这一点），one-hot 是合理且常用的选择。
</details>

<details><summary>Q3：为什么预测模块要把历史数据转成字典？为什么每个时刻都要重新过滤 `k < pred_time`？</summary>

**参考答案**

**为什么转字典**：

```python
self.data_dict = self.data_source.set_index('time')['power_load'].to_dict
```

预测时需要对**每个待预测时刻**查询 4 个具体时间点的负荷（前 1、2、3 小时 + 昨日同时刻）。如果每次都执行 `df[df['time'] == t]['power_load']` 这类条件筛选，pandas 每次都要扫描/建索引，在逐个时刻循环几百上千次时开销非常大。转成 `dict` 后查询是 **平均 $O(1)$**，性能提升显著。注释也指出实际开发中可以用 **Redis** 做缓存。

**为什么每个时刻都要 `{k: v for k, v in data_dict.items if k < pred_time}`**：

这是为了**模拟真实的线上场景，严格杜绝未来信息泄漏**。在真实生产中，预测 $t$ 时刻的负荷时，$t$、$t+1$、$t+2\dots$ 的负荷**根本还不存在**。如果直接用包含全量数据的字典去查，就可能（在设计上）用到尚未发生的数据。

虽然本案例中构造的特征（前 1/2/3 小时、昨日同时刻）在时序上确实只指向过去，理论上不会"取到未来值"，但这个过滤动作有三重意义：
1. **保证语义正确**：显式表达"我只知道 $t$ 之前的信息"，让代码意图与真实场景一致；
2. **防御未来改动**：如果以后增加了"未来窗口"特征（如前后各 3 小时），过滤器能立刻暴露泄漏问题；
3. **支撑真正的滚动预测**：如果改成"多步预测"（把模型预测值作为下一步的输入特征），就必须依赖这个"只保留历史"的字典，才能用**预测值**而不是**真实值**迭代下去。

**顺带指出的改进点**：
- 代码中 `data_his_dict` 每轮都重新构建整个字典，时间复杂度是 $O(n^2)$。更高效的做法是**按时间顺序推进**，逐个把新出现的真实负荷加入字典，这样是 $O(n)$；
- `data_dict.get(key, 600)` 中的 600 是硬编码经验值，更稳健的做法是用"该小时的历史平均负荷"或"最近可用值的前向填充"。
</details>

<details><summary>1. 什么是时间序列预测？四类任务场景分别是什么？</summary>

**时间序列预测**：根据历史时间序列数据来预测未来值的方法。

| 任务 | 时序变量数量 | 预测时间步 | 实现方案 |
| --- | --- | --- | --- |
| 单变量单步 | 1 个 | 1 个 | 直接建模预测（一个特征） |
| 单变量多步 | 1 个 | 多个 | 建模 + 滚动预测；或不同时间步分别建模 |
| 多变量单步 | 多个 | 1 个 | 直接建模预测（多个特征） |
| 多变量多步 | 多个 | 多个 | 建模 + 滚动预测；或多步分别建模；或深度学习 seq2seq |

核心结论：**不论传统机器学习还是深度学习，解决方案主要是把时序数据处理成二维的结构化数据集**，再训练模型预测。
</details>

<details><summary>2. 本案例的特征工程提取了哪三类特征？各多少列？分别捕捉什么规律？</summary>

| 特征类别 | 列数 | 列名示例 | 捕捉的规律 |
| --- | --- | --- | --- |
| 时间特征 – 小时 | 24 | `hour_00` … `hour_23` | **日内周期**（早高峰、晚高峰、夜间低谷） |
| 时间特征 – 月份 | 12 | `month_01` … `month_12` | **季节周期**（夏季空调用电、冬季取暖） |
| 相近时间窗口负荷 | 3 | `前1小时`、`前2小时`、`前3小时` | **短期惯性/自相关**（负荷变化是连续的） |
| 昨日同时刻负荷 | 1 | `yesterday_load` | **日周期**（同一时刻前一天的水平） |
| **合计** | **40** | —— | —— |

其中时间特征先由 `time.str[11:13]` / `str[5:7]` 提取，再经 `pd.get_dummies` 做 one-hot；滑窗特征用 `power_load.shift(i)` 构造；昨日同时刻用"时间→负荷字典 + `to_timedelta('1d')`"构造；最后 `dropna(axis=0)` 剔除因这两步产生的空值。
</details>

<details><summary>3. 网格搜索得到的最优超参数是什么？网格搜索一共训练了多少次模型？</summary>

**最优超参数**：`n_estimators=150`、`max_depth=6`、`learning_rate=0.1`。

**候选空间**：
- `n_estimators`：4 个候选（50/100/150/200）
- `max_depth`：3 个候选（3/6/9）
- `learning_rate`：2 个候选（0.1/0.01）
- `cv=5`（5 折交叉验证）

**训练次数** = $4\times3\times2\times5 = \mathbf{120}$ 次。

日志显示这段网格搜索耗时约 41 秒（15:38:26 → 15:39:07），符合小数据集 + XGBoost 的速度量级。
</details>

<details><summary>4. 预测模块的完整流程是什么？为什么说"滚动 + 掩盖未来"比随机划分评估更接近真实场景？</summary>

**预测流程 5 步**：
1. 导包、配置绘图字体（`plt.rcParams['font.family'] = 'SimHei'`）；
2. 定义 `PowerLoadPredict` 类：配置日志、获取数据源、**历史数据转字典**（避免频繁操作 DataFrame）；
3. 加载模型 `joblib.load('../model/xgb.pkl')`；
4. **滚动预测**：确定预测时间段（`>= 2015-08-01 00:00:00`）→ 逐个时刻过滤出 `k < pred_time` 的历史字典 → 解析出与训练一致的 40 列特征 → 预测 → 记录 `[时间, 真实值, 预测值]` → 循环结束转 DataFrame；
5. **结果评价**：计算 MAE，并画真实值/预测值折线图（`MultipleLocator(50)` 调横轴间隔，`rotation=45` 旋转标签）。

**为什么"滚动 + 掩盖未来"更接近真实场景**：
1. **时间顺序一致**：真实生产中模型只能按时间顺序一个个时刻预测，无法一次性看到整段测试期数据。滚动预测严格复现了这个顺序；
2. **信息集一致**：每个时刻只允许使用该时刻**之前**的历史，与线上可用信息完全一致；
3. **不存在"测试点在训练时间范围内"的乐观偏置**：随机划分时，测试集的时间点散布在训练时间区间内部，模型可以"借用"前后相邻时刻的信息（通过滑窗和昨日同时刻特征直接读到训练期的真实值），因此离线 MAE 会偏乐观。滚动预测从训练期**之后**的时段开始，才是真正的"对未来预测"；
4. **评价对象一致**：滚动预测的 MAE 是"逐小时上线预测的平均误差"，正是业务真正关心的那个数字。

**改进点**：预测期如果很长（如一个月），可以考虑让模型定期用新数据重新训练（在线学习/滚动重训），因为负荷模式会随季节、经济形势变化而漂移。
</details>

<details><summary>5. 提出了哪四个角度的改进方向？各举一个具体措施。</summary>

| 角度 | 具体措施 |
| --- | --- |
| **特征工程** | 优化时间窗口大小；提取更有效的历史负荷特征（多阶差分、滚动均值/方差、同比环比）；**扩展外部特征**（温度、湿度、风速、历史工业/居民用电量） |
| **算法** | ① 样本分群后分别建模（按地区分组，或先用**聚类**分群，再对不同分区分别训练模型）；② 换更优算法（**LightGBM**、RNN 类、**iTransformer**）；③ 算法组合（**bagging** 或 **stacking**） |
| **预测（推理）速度** | 预测时的特征工程中，历史负荷可**缓存到 Redis**，使用时直接查询（避免每次重建字典） |
| **扩展性** | 做**通用工具包**支持多种数据源（MySQL、PostgreSQL、Oracle、ES、Redis、Hive）；项目**打包成容器**适配各种服务器环境；**预测模块与项目解耦**，封装出接口接收 Web 参数后按参数取数并预测 |

**补充可加项**：特征层面还可以加"是否节假日/调休"（中国节假日对负荷影响极大）、"前 7 天同小时均值"；模型层面可以做**多步预测**（一次性预测未来 24 小时）；评估层面可以用 **MAPE/WAPE** 做跨区域可比。
</details>
