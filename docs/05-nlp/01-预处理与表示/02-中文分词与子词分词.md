# 中文分词与子词分词

> **一句话总结**：分词决定了模型看到的最小语义单元——中文从「找词边界」出发，子词（subword）从「拆词成碎片」出发，两者殊途同归地解决未登录词问题。
> **前置知识**：第 01 篇的文本预处理流水线、序列标注的基本概念、Python 正则与字典操作。

> 1. 说清 jieba 精确 / 全模式 / 搜索引擎三种模式的差别，并会用自定义词典修正领域专名。
> 2. 把分词与 NER、词性标注统一理解为「序列标注」问题，写出 B/M/E/S 标签序列。
> 3. 手写一个 BPE 合并流程，并解释 BPE、WordPiece、Unigram 三者目标函数的差异。

## 1. 核心概念

### 1.1 分词是什么，为什么中文特别难

分词（word segmentation）就是把连续的字序列，按一定规范重新组合成词序列。模型训练时能接受的最小单位通常是「词」，而词语是语义理解的基本单元，所以这一步绕不过去。

英文有天然空格作为词边界，中文没有。中文分词的难点集中在三处：

| 难点 | 说明 | 例子 |
|------|------|------|
| 切分歧义 | 同一串字有多种合法切法 | 「乒乓球拍卖完了」→「乒乓球/拍卖/完/了」或「乒乓球拍/卖/完/了」 |
| 未登录词（OOV） | 词典里没有的新词、专名、领域术语 | 新品牌名、网络新词、「心肌梗死」这类专业词 |
| 规范不统一 | 「算一个词还是几个词」取决于任务定义 | 「自然语言处理」/「自然 / 语言 / 处理」 |

前两个难点正是后面要讲的两条技术路线：**统计模型**（用概率消歧）与**子词方法**（用碎片兜住 OOV）。

### 1.2 jieba 的三种模式

jieba 的三种模式目标函数不同，输出粒度也不同：

| 模式 | API | 目标 | 粒度 | 典型用途 |
|------|-----|------|------|----------|
| 精确模式 | `jieba.lcut(s)` | 最精确地切开，无冗余 | 中 | 文本分析、分类、向量化（默认推荐） |
| 全模式 | `jieba.lcut(s, cut_all=True)` | 扫描出所有可能成词 | 细（含冗余） | 召回优先，后续用规则再筛 |
| 搜索引擎模式 | `jieba.lcut_for_search(s)` | 精确模式基础上对长词再切 | 中 + 细 | 搜索索引，提高长词的部分匹配召回 |

对同一句话「教育是一家上市公司，旗下有品牌」：

| 模式 | 输出（节选） | 观察 |
|------|--------------|------|
| 精确 | / 教育 / 是 / 一家 / 上市公司 / ，/ 旗下 / 有 / / 程序员 / 品牌 | 「上市公司」保留为长词 |
| 全模式 | 传 / 智 / 教育 / 是 / 一家 / 上市 / 上市公司 / 公司 / 旗下 / 下有 / / 程序 / 程序员 / 品牌 | 长词被拆开且与整体同时出现，标点也成词 |
| 搜索 | / 教育 / 是 / 一家 / 上市 / 公司 / 上市公司 / 旗下 / 有 / / 程序 / 程序员 / 品牌 | 在精确结果上补充子词，无冗余标点 |

一个常被忽略的能力：jieba 支持**中文繁体**分词，不需要额外转换（如「煩惱即是菩提，我暫且不提」→ 煩惱 / 即 / 是 / 菩提 / ，/ 我 / 暫且 / 不 / 提）。

### 1.3 自定义词典

专有名词是分词错误的重灾区。jieba 允许加载自定义词典，格式为：

```
词语 词频 词性
```

词频与词性都可省略。加载后 jieba 会优先考虑词典中的词。工程上有三种用法：

| 方式 | 代码 | 生效范围 |
|------|------|----------|
| 加载词典文件 | `jieba.load_userdict("userdict.txt")` | 全局，适合领域词表 |
| 动态加一个词 | `jieba.add_word("自然语言处理")` | 运行期临时补充 |
| 动态删一个词 | `jieba.del_word("的的")` | 去掉误切出来的词 |

### 1.4 分词 = 序列标注

把分词、词性标注（POS）、命名实体识别（NER）统一到「给每个 token 打标签」的框架下，就能复用同一套模型（见第 06 篇）：

| 任务 | 输入 | 输出标签 | 标签体系 |
|------|------|----------|----------|
| 分词 | 字序列 | 每个字是否词的边界 | B / M / E / S |
| 词性标注 | 词序列 | 每个词的词性 | n / v / a / r … |
| NER | 词或字序列 | 每个 token 的实体位置与类型 | B-PER / I-PER / O / B-LOC … |

B/M/E/S 含义：B = 词首（Begin）、M = 词中（Middle）、E = 词尾（End）、S = 单字成词（Single）。例如「我喜欢自然语言处理」的字级标签为：

```
我(B) 喜(B) 欢(E) 自(B) 然(M) 语(M) 言(M) 处(M) 理(E)
```

解码后得到「我 / 喜欢 / 自然语言处理」。**分词在数学上等价于序列标注**——这是把分词接入 BiLSTM-CRF 的关键洞察。

### 1.5 从「词」到「子词」

纯词表方案有一个根本矛盾：**词表要小**（否则 one-hot/softmax 维度过大、参数爆炸）与**覆盖率要高**（否则 OOV 泛滥）不可能同时满足。子词方法用一个折中破解：

| 粒度 | 词表规模 | OOV | 序列长度 | 代表 |
|------|----------|-----|----------|------|
| 字级（char） | 小（中文约 5k） | 几乎无 | 长 | BERT-base-chinese |
| 词级（word） | 大（十万以上） | 严重 | 短 | jieba + word2vec |
| 子词（subword） | 中（3 万–5 万） | 极少 | 中 | BPE、WordPiece、Unigram、SentencePiece |

子词的核心思想：**高频词整词保留，低频词拆成更小的、有统计意义的碎片**。这样词表可控，任何未见过的词也能用已知子词拼出来，最坏情况退化为字符级，永远不会出现 `<UNK>`。

主流子词算法：

| 算法 | 代表模型 | 自底向上/向下 | 合并或删减准则 |
|------|----------|--------------|----------------|
| BPE | GPT-2、RoBERTa | 自底向上 | 合并**频次最高**的相邻符号对 |
| WordPiece | BERT | 自底向上 | 合并能**最大提升语料似然**的符号对 |
| Unigram LM | ALBERT、XLNet（SentencePiece） | 自顶向下 | 从大词表出发，删掉**删除后似然损失最小**的子词 |
| SentencePiece | T5、LLaMA | — | 直接在原始文本（含空格）上做上述任一种，语言无关 |

## 2. 方法细节

### 2.1 jieba 的分词原理

jieba 走的是「词典 + 统计」的混合路线：

1. **构建前缀词典**（DAG）：基于词典把所有可能的成词路径建成有向无环图。
2. **动态规划求最大概率路径**：对 DAG 上每条路径计算 $\prod P(w_i)$，取概率最大的路径。词的概率来自语料统计，未登录词则回退到 HMM 识别。
3. **HMM 处理未登录词**：对 DAG 中无法切分的连续单字串，用 HMM（状态为 B/M/E/S）做维特比解码。

这解释了为什么自定义词典有效——它直接改变了 DAG 的边和路径概率。

### 2.2 BPE 算法流程

BPE（Byte Pair Encoding）原本是一种数据压缩算法，2016 年被引入 NLP。流程是「自底向上」的贪心合并：

1. **初始化**：把每个词拆成字符序列，并在词尾加结束符 `</w>`（用于区分词尾字符）。
2. **统计**：统计语料中所有**相邻符号对**的出现频次。
3. **合并**：把频次最高的符号对合并成一个新符号，加入词表，并在语料中替换。
4. **重复**：重复步骤 2–3，直到词表达到预设大小或没有可合并的符号对。

用一个迷你语料演示（词频作为权重）：

```
low: 5, lower: 2, newest: 6, widest: 3
```

初始（字符级，`·` 表示词尾）：

```
l o w·(5) l o w e r·(2) n e w e s t·(6) w i d e s t·(3)
```

| 轮次 | 最高频符号对 | 频次 | 合并后 |
|------|--------------|------|--------|
| 1 | `e` + `s` | 9（newest 6 + widest 3） | `es` |
| 2 | `es` + `t` | 9 | `est` |
| 3 | `est` + `·` | 9 | `est·` |
| 4 | `l` + `o` | 7（low 5 + lower 2） | `lo` |
| 5 | `lo` + `w` | 7 | `low` |
| 6 | `n` + `e` | 6 | `ne` |
| 7 | `ne` + `w` | 6 | `new` |
| 8 | `w` + `i` | 3 | `wi` |
| … | … | … | … |

合并规则按轮次记录成有序表，编码新词时**按记录顺序**依次套用即可。可见 `newest` → `new` + `est·`，`widest` → `wi` + `d` + `est·` —— 「est」这个共享后缀被单独学出来了。

BPE 的编码（encode）细节：对未见过的词，先拆字符，然后**反复找当前符号序列中在合并表里出现过的对，按合并优先级（轮次越早优先级越高）合并**，直到没有可合并的对。

### 2.3 WordPiece 与 BPE 的差异

WordPiece 表面流程与 BPE 一模一样（都是贪心合并相邻符号对），差异只在**选哪一对合并**：

$$
\text{score}(a,b) = \frac{\text{count}(ab)}{\text{count}(a)\times \text{count}(b)}
$$

即用**点互信息（PMI）式**的准则，而非纯频次。直觉：`e`+`s` 频次很高，但如果 `e` 和 `s` 本身就各自到处都是，它们的结合未必有信息量；WordPiece 更偏好「两者单独出现少、但一起出现多」的组合。BERT 用它训练出 30522 个 token 的英文词表，其中一个重要细节是**续接子词前缀 `##`**：`playing` → `play` + `##ing`，用 `##` 标记「这个词片段不是词首」。

### 2.4 Unigram LM 的删减思路

Unigram 走**自顶向下**路线，与 BPE 方向相反：

1. 初始化一个**过大**的候选子词表（例如所有字 + 高频 n-gram）。
2. 用当前词表，对语料中每个词计算所有可能切分的概率，取概率最大的切分（用维特比）。
3. 计算每个子词的**损失贡献**：假设把它从词表中删掉，语料总似然会下降多少。
4. 删掉损失贡献最小（最没用）的一批子词（例如删 10%–20%）。
5. 重复 2–4，直到词表降到目标大小。

最终保留的是一个带概率的子词表，编码时用维特比找**概率最大**的切分，而不是按顺序贪心合并。这类「子词有概率、切分可搜索」的特性，是 SentencePiece 的基础。

### 2.5 中文场景下的选型建议

| 场景 | 建议 | 理由 |
|------|------|------|
| 传统机器学习（TF-IDF + 树模型） | 字级或 jieba 词级 | 特征稀疏，字级词表更小、更稳；jieba 词级可解释性好 |
| FastText 分类 | jieba 词级 + char n-gram | FastText 自带 subword，词级提供语义单元，n-gram 补 OOV |
| BERT 等预训练模型 | 直接用模型自带 tokenizer | BERT-base-chinese 就是字级，强行分词反而破坏与预训练的一致性 |
| 多语言 / 含大量英文与符号 | SentencePiece（BPE 或 Unigram） | 语言无关，无需预分词，天然处理空格 |
| 领域术语密集（医疗、法律） | 自定义词典 + 字级兜底 | 词典保术语完整，字级保未知词 |

**最重要的一条**：使用预训练模型时，不要自己先分词再喂给 tokenizer。模型在预训练阶段看过的是特定粒度的文本，自己分词会造成训练与推理的分布不一致（train-test mismatch）。

### 3.2 字级 B/M/E/S 标注：把分词变成序列标注

```python
def word_to_bmes(words):
    """把分词结果转成 B/M/E/S 标签序列（字符级）"""
    labels = []
    for w in words:
        if len(w) == 1:
            labels.append("S")
        else:
            labels.append("B")
            labels.extend(["M"] * (len(w) - 2))
            labels.append("E")
            return labels

        def bmes_to_words(chars, labels):
            """从 B/M/E/S 标签还原分词结果，并顺带校验标签合法性"""
            words, buf = [], ""
            for ch, tag in zip(chars, labels):
                buf += ch
                if tag in ("E", "S"):
                    words.append(buf)
                    buf = ""
                    if buf: # 结尾残留说明标签序列不合法
                        words.append(buf)
                        return words

                    chars = list("我喜欢自然语言处理")
                    labels = word_to_bmes(["我", "喜欢", "自然语言处理"])
                    print("".join(chars))
                    print(labels)
                    print(bmes_to_words(chars, labels))
```

预期输出：`['B', 'B', 'E', 'B', 'M', 'M', 'M', 'M', 'E']`，还原得到 `['我', '喜欢', '自然语言处理']`。

### 3.3 纯 Python 实现 mini-BPE

```python
from collections import Counter

CORPUS = {"low": 5, "lower": 2, "newest": 6, "widest": 3}

def get_vocab(corpus):
    """把每个词拆成字符序列，词尾加 </w> 标记"""
    return {"".join(list(w)) + " </w>": c for w, c in corpus.items()}

def get_stats(vocab):
    """统计所有相邻符号对的频次（按词频加权）"""
    pairs = Counter
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[(symbols[i], symbols[i + 1])] += freq
            return pairs

        def merge_vocab(pair, vocab):
            """把 best pair 在所有词中合并成一个新符号"""
            merged, new_token = {}, "".join(pair)
            for word, freq in vocab.items():
                merged[word.replace("".join(pair), new_token)] = freq
                return merged

            def train_bpe(corpus, num_merges=8):
                vocab = get_vocab(corpus)
                merges = []
                for i in range(num_merges):
                    pairs = get_stats(vocab)
                    if not pairs:
                        break
                    best = max(pairs, key=pairs.get)
                    vocab = merge_vocab(best, vocab)
                    merges.append((best, pairs[best]))
                    print(f"第{i + 1}轮: 合并 {best} -> {''.join(best)!r} (频次 {pairs[best]})")
                    return merges, vocab

                def encode(word, merges):
                    """用学到的合并表编码新词：按轮次优先级反复合并"""
                    symbols = list(word) + ["</w>"]
                    for pair, _ in merges:
                        i = 0
                        while i < len(symbols) - 1:
                            if (symbols[i], symbols[i + 1]) == pair:
                                symbols[i:i + 2] = ["".join(pair)]
                            else:
                                i += 1
                                return symbols

                            merges, final_vocab = train_bpe(CORPUS, num_merges=8)
                            print("\n最终词表:", sorted(final_vocab))
                            for w in ["lowest", "newest", "slow"]:
                                print(f"编码 {w!r} -> {encode(w, merges)}")
```

预期现象：前几轮会依次合并 `('e','s')`、`('es','t')`、`('est','</w>')`、`('l','o')`、`('lo','w')` 等；`lowest` 能被切出已知子词，`slow` 这类未见词会退化成 `['s','low','</w>']` 之类的碎片组合——这正是子词方法「永不 OOV」的体现。

### 3.4 用 Hugging Face tokenizer 观察子词切分

```python
# 依赖: pip install transformers
from transformers import BertTokenizer, GPT2Tokenizer

bert = BertTokenizer.from_pretrained("bert-base-uncased")
print(bert.tokenize("playing unbelievable tokenization"))
# ['playing', 'un', '##bel', '##ie', '##vable', 'token', '##ization']
# 注意 ## 前缀 = 该片段不是词首

gpt2 = GPT2Tokenizer.from_pretrained("gpt2")
print(gpt2.tokenize("playing unbelievable tokenization"))
# GPT-2 用字节级 BPE，切分结果与 WordPiece 不同

zh = BertTokenizer.from_pretrained("bert-base-chinese")
print(zh.tokenize("自然语言处理"))
# ['自', '然', '语', '言', '处', '理'] —— 中文 BERT 是字级
```

对比这三种输出，可以直观看到「同一句话在不同子词算法下粒度完全不同」，这也是不能跨模型混用 tokenizer 的原因。

## 4. 常见坑

| 现象 | 原因 | 解决 |
|------|------|------|
| 领域专名被切碎（「」→「/程序员」） | 默认词典不含该词 | `jieba.load_userdict` 或 `add_word`；词典格式 `词 词频 词性` |
| 全模式输出里混入空串和标点 | 全模式穷举所有成词组合，标点也成词 | 常规任务用精确模式；用全模式时显式过滤 `\w` 之外的内容 |
| `jieba.cut` 拿到 `<generator object>` | `cut` 返回生成器，`lcut` 才返回 list | 需要列表用 `lcut`；需要流式处理（省内存）才用 `cut` |
| 自定义词典里写的是逗号分隔 | jieba 认为分隔符是**空格** | 严格用空格：` 100 n` |
| 先 jieba 分词再喂给 BERT，效果反而下降 | 破坏了预训练时的粒度一致性 | 预训练模型直接喂原始文本，交给它自带的 tokenizer |
| 新词表训练好了，但 `[UNK]` 仍然很多 | 词表里没有对应的子词碎片，覆盖不足 | 增大词表或改用字符级/字节级 BPE；检查语料是否与目标领域一致 |
| BPE 编码结果与训练时不一致 | 合并表是有序的，编码时必须**按轮次顺序**套用 | 保存 `merges` 列表而非只存最终词表 |
| 英文句子开头空一格导致多出一个子词 | 空格被当成普通字符参与 BPE | 用 SentencePiece 的 `▁` 标记空格，或先做 `strip` |
| 中文子词模型把常用词切得太碎 | BPE 不区分「字」与「词」，中文无空格，合并容易停在字级 | 中文可先用 jieba 分词再训 BPE，或直接用字级 + 更大词表 |

<details markdown="1">
<summary markdown="1">参考答案</summary>

英文有空格作为词边界，中文是连续字序列，词边界本身无标记，因此分词本质是**歧义消解 + 未登录词识别**问题。三类难点：① 切分歧义（「乒乓球拍卖完了」有两种合法切法）；② 未登录词（人名、品牌名、领域术语不在词典中）；③ 规范不统一（「自然语言处理」算一个词还是三个，取决于任务定义）。

jieba 三种模式的选型：

- **精确模式**（默认）适合绝大多数任务——分类、向量化、文本分析，因为它无冗余、歧义最少。
- **全模式**把所有成词可能都扫出来，速度快但无法消歧，还会把标点切出来，只适合「先广召回、再用规则筛」的场景。
- **搜索引擎模式**在精确结果上补充长词的子词（「人工智能」→「人工 / 智能 / 人工智能」），专为搜索索引设计，提升长词的部分匹配召回。

工程上还有一步不能省：加载自定义词典。领域专名不处理，后面的 TF-IDF 和词向量都会在错误粒度上学习。

</details>

**Q2. BPE 和 WordPiece 都是贪心合并，它们的本质区别是什么？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

流程完全一样（统计相邻符号对 → 选一对合并 → 重复到词表达标），区别只在**选择合并哪一对的准则**：

- **BPE** 选**频次最高**的对：$\arg\max \text{count}(ab)$。简单、快，偏向高频组合。
- **WordPiece** 选**提升语料似然最多**的对，等价于按
 $$\text{score}(a,b)=\frac{\text{count}(ab)}{\text{count}(a)\cdot\text{count}(b)}$$
 排序取最大。这是一个 PMI 式准则，偏好「各自单独出现少、但一起出现多」的组合。

直觉差异：`e` 和 `s` 频次极高，纯频次准则会优先合并它们；但如果 `e`、`s` 本身在语料里到处出现，它们的结合未必有信息量。WordPiece 用分母惩罚这种「本来就很常见」的符号，因此合并出的子词更有区分度。

另一个工程差异：BERT 的 WordPiece 用 `##` 前缀标记非词首子词（`playing` → `play` + `##ing`），而 GPT-2 的字节级 BPE 用 `Ġ` 之类的字节映射标记空格。

</details>

**Q3. 为什么子词（subword）方法能缓解 OOV？代价是什么？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

原理是**用「已知碎片的组合」覆盖任意未见词**。词表由统计学习得到，包含大量高频子词（词根、词缀、汉字）。遇到未见词时，编码器会把它切成若干已存在于词表中的子词；最坏情况退化为字符级（或字节级），因此理论上永远不会出现 `<UNK>`。同时词表规模保持可控（3 万–5 万），不像词级方案动辄十万以上。

副作用/代价：

1. **序列变长**：一个词变成多个子词，长文本更吃 `max_len` 和显存（attention 是 $O(L^2)$）。
2. **语义碎片化**：子词边界不与语义边界对齐，模型需要额外的注意力来「拼回」一个词；对低频专业术语尤为明显。
3. **与分词工具冲突**：自己先用 jieba 分词再喂给子词模型，会破坏预训练粒度一致性。
4. **中文场景的特殊问题**：中文无空格，BPE 容易停在字级，退化成「字级模型但词表更大」，收益不如英文显著。因此中文常直接用字级，或先分词再训子词。
5. **多粒度不一致**：不同模型的子词表互不兼容，不能跨模型复用 embedding。

</details>

## 6. 自测题

**1. 判断：「jieba 搜索模式的分词结果包含精确模式的全部结果。」为什么？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

对，但要注意方向。搜索模式的定义是「在精确模式的基础上，对长词再次切分」，所以它保留精确模式的每个词，并额外补充长词切出的子词，结果是**精确结果的超集**（按集合理解）。

不过顺序不同：精确模式输出的「上市公司」在搜索模式里被替换为「上市 / 公司 / 上市公司」三个词——整体词仍在，但位置发生了变化。所以严格说是「词集合的超集，序列顺序不同」。工程上搜索模式适合建倒排索引，不适合直接当分类模型输入（因为存在重叠 token）。

</details>

**2. 给定语料 `{"aaab": 2, "aaac": 1}`，写出 BPE 前两轮会合并的符号对。**

<details markdown="1">
<summary markdown="1">参考答案</summary>

初始（词尾加 `</w>`）：

```
a a a b </w> (2)
a a a c </w> (1)
```

第一轮统计相邻对：

| 对 | 频次 |
|----|------|
| (a, a) | 2 + 1 = 3（每个词里有两处 `aa`？实际 `aaab` 有 2 处、`aaac` 有 2 处，共 4） |
| (a, b) | 2 |
| (b, </w>) | 2 |
| (a, c) | 1 |
| (c, </w>) | 1 |

`aaab` 的三个相邻位置是 (a,a)、(a,a)、(a,b) —— 所以 (a,a) 出现 2 次；`aaac` 同理 2 次。合计 `(a,a)` 频次 = 4，最高，**第一轮合并 (a,a) → aa**。

第二轮语料变为：

```
aa a b </w> (2)
aa a c </w> (1)
```

相邻对频次：(aa,a) = 3、(a,b) = 2、(b,</w>) = 2、(a,c) = 1、(c,</w>) = 1。最高是 `(aa,a)`，**第二轮合并 (aa,a) → aaa**。

要点：统计的是**加权频次**（权重是词频），且每次合并后要重新统计，因为符号序列已变。

</details>

**3. 为什么预训练模型不能「先分词再输入」？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

因为预训练模型的 embedding 与位置编码都是在**特定粒度**的文本上训练出来的。以 BERT-base-chinese 为例，它按**字**切分，`自然语言处理` → `['自','然','语','言','处','理']`。如果你先用 jieba 切成 `['自然语言处理']`，tokenizer 看到的是一整串未知字符，会走 WordPiece 拆成子词或直接变成 `[UNK]`，导致：

1. **分布不一致**：推理时输入的子词序列从未在预训练阶段出现过，模型的统计规律失效（train-test mismatch）。
2. **位置编码错乱**：字级模型的位置编码粒度是字，按词输入会显著缩短序列，破坏位置语义。
3. **信息丢失**：`[UNK]` 直接丢掉了词的内容。

正确做法是：**原始文本直接交给模型自带的 tokenizer**，需要领域适配时通过继续预训练（continue pretraining）或添加领域词表后再微调来解决。

</details>

**4. 子词词表大小怎么选？太大会怎样、太小会怎样？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

词表大小是「序列长度」与「embedding 参数量」的权衡：

| 词表 | 序列长度 | 参数量 | 影响 |
|------|----------|--------|------|
| 太小（如 5k） | 长 | 小 | 词被切得很碎，语义碎片化；训练/推理变慢（$O(L^2)$），难学到词级语义 |
| 太大（如 50 万） | 短 | 大（$V\times d$ 常是最大的一块参数） | 显存吃紧，低频词 embedding 训练不充分（长尾），泛化变差 |

常见取值：英文 BPE 3 万–5 万；中文 BERT 字级约 2.1 万；多语言模型（mBERT、XLM-R）为覆盖上百种语言会取到 25 万。

判断是否合适的实用方法：看**平均每词的子词数**（英文理想约 1.2–1.5，中文字级约 1.0–1.5）。明显偏高说明词表偏小或语料不匹配；同时看**低频子词占比**，过多说明词表虚大。

</details>
