## 1. 核心概念

### 1.1 任务形态：相似度、匹配、检索

| 任务 | 输入 | 输出 | 例子 |
|------|------|------|------|
| 文本相似度 | 两个文本 | 一个分数（或相似等级） | 判断两条新闻是否重复 |
| 语义匹配 | query + 候选文档 | 相关性分数 | 搜索「怎么退烧」匹配到「发热处理方法」 |
| 语义检索 | 1 个 query + 海量库 | Top-K 结果 | 向量数据库的 ANN 检索 |
| 句子对分类 | 两个句子 | 类别标签 | 自然语言推理（蕴含/矛盾/中立）、BERT 的 NSP |

四个任务在建模上是相通的：**核心都是「把两段文本映射到可比较的表示，再算一个分数」**。

### 1.2 技术路线的分水岭：交互式 vs 表示式

这是本主题最重要的一个概念，面试几乎必问：

| 对比项 | 交互式 / 交叉编码器（Cross-Encoder） | 表示式 / 双塔（Bi-Encoder / Dual-Encoder） |
|--------|-------------------------------------|-------------------------------------------|
| 输入 | `[CLS] 句子A [SEP] 句子B [SEP]` 一起送入 | A、B **分别**送入同一个（或两个）编码器 |
| 交互发生位置 | 从第一层开始两段就在 self-attention 里互相看 | 只有最后算相似度时才有交互 |
| 输出 | 相关性分数（分类/回归） | 两个向量，相似度后算 |
| 效果 | **高**（能建模细粒度交互，如否定、指代、词序） | 较低（两段文本无法互相消歧） |
| 速度 | 慢：每对都要完整前向一次，$N$ 个候选要算 $N$ 次 | 快：文档向量可**离线预计算**，query 只需算 1 次 |
| 可索引 | 不能（每对都要现算） | 可以（建向量索引做 ANN 检索） |
| 典型用途 | 精排（rerank）、小规模高质量判定 | 召回（retrieval）、大规模去重、聚类 |

工业界的标准架构是**两阶段**：

```
query ──► 双塔召回（从百万候选中取 Top-100，毫秒级）
 │
 └──► Cross-Encoder 精排（对 100 个候选精算分数，几十毫秒）
 │
 └──► Top-10 返回
```

只在召回阶段用 Cross-Encoder 是不可行的——百万候选要跑百万次 BERT，延迟无法接受。只在精排用双塔也不够准——语义匹配的瓶颈往往在精排。

### 1.3 方法总览：从字面到语义

| 方法 | 依赖 | 语义能力 | 速度 | 适用 |
|------|------|----------|------|------|
| 编辑距离（Levenshtein） | 字符 | 无（纯字面） | $O(mn)$ | 拼写纠错、短字符串模糊匹配 |
| Jaccard / Dice | 词集合 | 无（字面重合） | 快 | 集合去重、标题相似度快速筛 |
| TF-IDF + 余弦 | 词袋 | 无同义（但 IDF 有判别力） | 快 | 强基线、关键词类检索 |
| BM25 | 词袋 + 长度归一 | 无同义 | 快 | 传统检索的经典基线，至今难被完全替代 |
| 词向量平均 / SIF | word2vec / FastText | 弱同义 | 快 | 快速近似，无上下文 |
| Sentence-BERT | BERT + 句对微调 | 强同义、句子级 | 中（可离线编码） | 双塔召回、语义去重、聚类 |
| CoSENT | BERT + 排序损失 | 强 | 中 | 中文句相似度（比 SBERT 更稳定） |
| SimCSE | BERT + 对比学习 | 强 | 中 | 无标注/少标注场景的句向量 |
| Cross-Encoder（BERT 句对） | BERT | 最强 | 慢 | 精排、最终判定 |

### 1.4 三种度量与「归一化」的关系

| 度量 | 公式 | 关注 | 对向量的要求 |
|------|------|------|-------------|
| 点积（Dot） | $\mathbf{a}\cdot\mathbf{b}=\sum_i a_i b_i$ | 方向 + 长度 | 无 |
| 余弦相似度（Cosine） | $\cos=\dfrac{\mathbf{a}\cdot\mathbf{b}}{\lVert\mathbf a\rVert\lVert\mathbf b\rVert}$ | 只关注方向 | 无（自动除模长） |
| 欧氏距离（L2） | $\lVert\mathbf a-\mathbf b\rVert_2$ | 绝对位置 | 需同量纲 |

三者之间的关键关系（工程上非常重要）：

$$
\lVert \mathbf a - \mathbf b\rVert^2 = \lVert\mathbf a\rVert^2 + \lVert\mathbf b\rVert^2 - 2\,\mathbf a\cdot\mathbf b
$$

当 $\lVert\mathbf a\rVert=\lVert\mathbf b\rVert=1$（向量已 L2 归一化）时：

$$
\lVert\mathbf a-\mathbf b\rVert^2 = 2 - 2\cos(\mathbf a,\mathbf b),\qquad \mathbf a\cdot\mathbf b=\cos(\mathbf a,\mathbf b)
$$

结论：**归一化之后，余弦相似度、内积、欧氏距离是等价的排序**。这就是为什么向量检索库（Faiss、Milvus、Elasticsearch 的 dense vector）普遍要求先把向量归一化，然后用内积（IP）做度量——这样做能把余弦计算简化为一次内积，速度更快且可直接用矩阵乘法。

## 2. 方法细节

### 2.1 经典字面方法

**编辑距离（Levenshtein distance）**：把字符串 $a$ 变成 $b$ 所需的最少单字符编辑（插入、删除、替换）次数。递推：

$$
D[i][j] =
\begin{cases}
j & i=0\\
i & j=0\\
D[i-1][j-1] & a_i = b_j\\
1 + \min\big(D[i-1][j],\ D[i][j-1],\ D[i-1][j-1]\big) & a_i \neq b_j
\end{cases}
$$

复杂度 $O(mn)$，空间可优化到 $O(\min(m,n))$。归一化相似度常用 $1 - \dfrac{D}{\max(m,n)}$。

**Jaccard 相似度**：$\dfrac{|A\cap B|}{|A\cup B|}$，其中 $A,B$ 是两个文本的**词集合**。它完全忽略词频与顺序，但极快，适合做大规模去重的第一层过滤。

### 2.2 TF-IDF 余弦与 BM25

**TF-IDF 余弦**：把两段文本各自的 TF-IDF 向量做 L2 归一化后取内积（见第 03 篇）。

**BM25** 是 TF-IDF 的改进版，也是「稀疏检索」至今的强基线：

$$
\text{score}(q, d)=\sum_{t \in q} \text{IDF}(t)\cdot
\frac{f(t,d)\cdot(k_1+1)}{f(t,d)+k_1\cdot\Big(1-b+b\cdot\frac{|d|}{\text{avgdl}}\Big)}
$$

各参数含义与作用：

| 符号 | 含义 | 影响 |
|------|------|------|
| $f(t,d)$ | 词 $t$ 在文档 $d$ 中的频次 | 频次越高分越高，但有饱和 |
| $k_1$（常取 1.2–2.0） | 词频饱和参数 | 越大越允许「多次出现持续加分」 |
| $b$（常取 0.75） | 文档长度归一化强度 | $b=1$ 完全归一化，$b=0$ 不归一化 |
| $\text{avgdl}$ | 平均文档长度 | 用于比较长短文档 |
| $\text{IDF}(t)$ | 逆文档频率 | 稀有词权重更高 |

BM25 相对 TF-IDF 的两个改进：① **词频饱和**——TF-IDF 中词出现 100 次的得分是出现 10 次的 10 倍，而 BM25 的 $\frac{f(k_1+1)}{f+k_1}$ 会随 $f$ 增大而趋于饱和，符合直觉（第 10 次出现的信息量远小于第 1 次）；② **文档长度归一化**——长文档天然词更多，$\frac{|d|}{\text{avgdl}}$ 项做了补偿。

### 2.3 词向量平均与平滑逆频率（SIF）

最简单的方法：把句子里所有词的向量取平均作为句向量。缺陷很明显：

1. **高频虚词主导**：the / 的 贡献了大量方向，稀释了实词。
2. **没有词序**：「猫追狗」和「狗追猫」平均后完全相同。

改进手段：

- **加权平均**：用 IDF 或 SIF 权重 $w=\dfrac{a}{a+p(w)}$（$a$ 常取 $10^{-3}$，$p(w)$ 是词频）加权，压掉高频词。
- **去主成分**：对句向量矩阵做 PCA，减去第一主成分（SIF 论文的做法），可显著提升相似度任务表现。

即便有这些改进，静态词向量平均仍然无法处理否定和语序，只能作为快速近似。

### 2.4 Sentence-BERT（SBERT）

**问题**：直接用 BERT 输出 `[CLS]` 或平均 `last_hidden_state` 做句向量，效果**很差**——因为 BERT 从未被训练成「让相似句子的向量靠近」。SBERT 论文的实测显示，原始 BERT 的句向量在 STS 任务上甚至不如 GloVe 平均。

**解法**：用**孪生网络（Siamese）**结构 + 句对监督做微调：

```
 句子A ──► BERT ──► pool ──► u ─┐
 ├──► 余弦相似度（或拼接后分类）
 句子B ──► BERT(共享权重) ──► pool ──► v ─┘
```

关键设计：

| 设计点 | 做法 | 原因 |
|--------|------|------|
| 权重共享 | A、B 用同一个 BERT | 保证两段文本映射到同一空间；参数量减半 |
| 池化策略 | 默认取 `[CLS]`；也可 mean-pooling / max-pooling | mean-pooling 在多数任务上更稳，`[CLS]` 需要专门训练过才好用 |
| 训练目标 | 分类目标（softmax 三分类：蕴含/中立/矛盾）或回归目标（余弦相似度 MSE）或 triplet 排序损失 | 分类目标适合 NLI 数据（SNLI/MNLI），回归/排序适合 STS 数据 |
| 推理 | 句子独立编码，向量可缓存 | 换来了可索引、可离线预计算的工程优势 |

**为什么效果能提升**：SBERT 把「相似度」变成了训练目标的一部分，模型被显式优化为「相似句靠近、不相似句远离」。这本质上是在做**度量学习（metric learning）**。

### 2.5 CoSENT：中文场景更稳定的排序损失

SBERT 常用的回归损失是 $\text{MSE}(\cos(u,v), \text{label})$，其中 label 是人工相似度分数（如 0–5）。这在中文数据集（LCQMC、BQ Corpus、STS-B 中文版）上有个问题：**不同标注者的相似度尺度不一致**，回归到绝对分数很困难，而且 MSE 损失会把大量算力花在「把 4.0 拟合到 4.2」这种无意义的边际上。

CoSENT（Cosine Sentence）把问题从「回归分数」改成「**排序**」：只要保证「标注分数更高的句子对，其余弦相似度也更高」即可。损失形式为

$$
\mathcal{L} = \log\Big(1 + \sum_{(i,j)\in\Omega,\ \text{label}_i > \text{label}_j}
\exp\big(\lambda(\cos_j - \cos_i)\big)\Big)
$$

其中 $\Omega$ 是一个 batch 内所有可比较的句子对，$\lambda$ 是缩放系数。直觉：只要 $\cos_i > \cos_j$（顺序正确），指数项就小于 1，损失趋近于 $\log 2$；一旦顺序反了，指数项迅速放大，产生大梯度。

CoSENT 在中文句相似度上通常比 SBERT 的 MSE 损失更稳定，因为它不依赖标注分数的绝对尺度，只依赖**相对顺序**——而相对顺序恰恰是人工标注最可靠的部分。

### 2.6 SimCSE：用 dropout 造正样本

**SimCSE（Simple Contrastive Learning of Sentence Embeddings）** 的洞察非常简洁：**同一个句子过两次 BERT，因为 dropout 的随机性会得到两个略有不同的向量，这两个向量就可以当作正样本对**。

| 设定 | 正样本来源 | 负样本来源 |
|------|-----------|-----------|
| 无监督 SimCSE | 同一句子 + 不同 dropout mask 的两次前向 | 同一个 batch 内的其他句子（in-batch negatives） |
| 有监督 SimCSE | NLI 数据中标注为蕴含的句对 | 标注为矛盾的句对 |

损失用 InfoNCE（对比学习）：

$$
\mathcal{L}_i = -\log\frac{\exp(\cos(u_i, u_i^+)/\tau)}{\sum_{j=1}^{N}\exp(\cos(u_i, u_j)/\tau)}
$$

其中 $\tau$ 是温度系数。工程上有个重要技巧：**去掉 dropout 反而会成为极强的基线**（论文称之为 `unsup-SimCSE` 的「dropout 作为最小数据增强」现象），这也说明 dropout 在句向量学习中起到了隐式正则的作用。

### 2.7 向量检索：为什么要 ANN

把 $N$ 个文档的句向量建成矩阵后，最朴素的检索是「query 向量与所有文档向量算内积再排序」，复杂度 $O(ND)$。$N=10^7$、$D=768$ 时，单次查询要算 76.8 亿次乘法，无法满足毫秒级延迟。

**ANN（Approximate Nearest Neighbor，近似最近邻）** 用「牺牲少量召回率换巨大速度提升」解决这个问题。主流索引类型：

| 索引 | 原理 | 特点 |
|------|------|------|
| IVF（倒排文件） | 先聚类，查询时只搜最近的几个簇 | 快、内存小；需要训练，召回率依赖 `nprobe` |
| HNSW（分层可导航小世界图） | 构建多层图，逐层贪心跳转 | 召回率与速度都很好，内存占用大，是当前主流 |
| PQ（乘积量化） | 把向量切成子段分别量化压缩 | 大幅省内存（可压到 1/16），有精度损失 |
| IVF+PQ | 两者结合 | Faiss 的经典高性价比组合 |

实践建议：中小规模（< 100 万）直接用 HNSW；超大规模（> 1 亿）用 IVF+PQ；对召回率要求极高时，ANN 取 Top-1000 再用 Cross-Encoder 精排。

## 3. 可运行示例

### 3.1 编辑距离、Jaccard、TF-IDF 余弦（纯 Python / numpy）

```python
# 依赖: pip install numpy
import numpy as np
from collections import Counter

def edit_distance(a: str, b: str) -> int:
    """Levenshtein 编辑距离，滚动数组优化空间到 O(min(m,n))"""
    if len(a) < len(b):
        a, b = b, a
        prev = list(range(len(b) + 1))
        for i, ca in enumerate(a, start=1):
            cur = [i] + [0] * len(b)
            for j, cb in enumerate(b, start=1):
                cost = 0 if ca == cb else 1
                cur[j] = min(prev[j] + 1, # 删除
                cur[j - 1] + 1, # 插入
                prev[j - 1] + cost) # 替换
                prev = cur
                return prev[-1]

            def jaccard(a: str, b: str) -> float:
                """按字符集合计算 Jaccard 相似度（中文可换成分词后的词集合）"""
                sa, sb = set(a), set(b)
                return len(sa & sb) / len(sa | sb) if (sa | sb) else 0.0

            def tfidf_cosine(docs):
                """手写 TF-IDF + 余弦相似度矩阵"""
                tokenized = [d.split for d in docs]
                vocab = sorted({w for d in tokenized for w in d})
                word2id = {w: i for i, w in enumerate(vocab)}
                N, V = len(docs), len(vocab)

                # 平滑 IDF
                df = Counter(w for d in tokenized for w in set(d))
                idf = np.array([np.log((1 + N) / (1 + df[w])) + 1 for w in vocab])

                M = np.zeros((N, V))
                for i, d in enumerate(tokenized):
                    tf = Counter(d)
                    for w, f in tf.items:
                        M[i, word2id[w]] = f * idf[word2id[w]]
                        # L2 归一化后，点积即为余弦相似度
                        n = np.linalg.norm(M[i])
                        if n > 0:
                            M[i] /= n
                            return M @ M.T

                        pairs = [("自然语言处理", "自然语言处理技术"),
                        ("自然语言处理", "计算机视觉"),
                        ("kitten", "sitting")]
                        for a, b in pairs:
                            print(f"{a!r:<12} vs {b!r:<14} 编辑距离={edit_distance(a, b):<3} "
                            f"Jaccard={jaccard(a, b):.3f}")

                            docs = ["自然 语言 处理 技术", "计算机 视觉 技术", "自然 语言 处理 与 人工智能"]
                            sim = tfidf_cosine(docs)
                            print("\nTF-IDF 余弦相似度矩阵:\n", np.round(sim, 4))
```

### 3.2 用 sentence-transformers 做双塔语义相似度

```python
# 依赖: pip install sentence-transformers
# 首次运行会联网下载模型；中文可用 'shibing624/text2vec-base-chinese'
# 或 'BAAI/bge-small-zh-v1.5'（检索任务通常需要在 query 前加指令前缀）
from sentence_transformers import SentenceTransformer, util

model = SentenceTransformer("BAAI/bge-small-zh-v1.5")

sentences = [
 "如何治疗感冒",
 "感冒了应该怎么办",
 "今天天气怎么样",
 "感冒药怎么吃",
]

# 注意：这些向量可以离线预计算并缓存，这是双塔的核心优势
embeddings = model.encode(sentences, normalize_embeddings=True) # 归一化！
print("向量形状:", embeddings.shape)

query = "发烧了吃什么药"
q_emb = model.encode(query, normalize_embeddings=True)

# 归一化后，点积等价于余弦相似度
scores = embeddings @ q_emb
for s, score in sorted(zip(sentences, scores), key=lambda x: -x[1]):
 print(f"{score:.4f} {s}")

# sentence-transformers 也提供了封装好的工具函数
print("\nTop-2:", util.semantic_search(q_emb, embeddings, top_k=2))
```

### 3.3 用 Cross-Encoder 做精排

```python
# 依赖: pip install transformers torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification
import torch

MODEL = "cross-encoder/ms-marco-MiniLM-L-6-v2" # 换中文可用 BAAI/bge-reranker-base
tok = AutoTokenizer.from_pretrained(MODEL)
model = AutoModelForSequenceClassification.from_pretrained(MODEL).eval

query = "如何治疗感冒"
candidates = ["感冒了应该怎么办", "感冒药怎么吃", "今天天气怎么样"]

# 关键：query 与每个候选拼成一个序列一起送入，这就是「交互式」
pairs = [[query, c] for c in candidates]
inputs = tok(pairs, padding=True, truncation=True, max_length=256, return_tensors="pt")

with torch.no_grad:
 scores = model(**inputs).logits.view(-1).float

for c, s in sorted(zip(candidates, scores.tolist), key=lambda x: -x[1]):
 print(f"{s:+.4f} {c}")
```

对比 3.2 与 3.3 的写法，能直观看出两种路线的工程差异：**3.2 的候选向量可离线算好、重复使用；3.3 每换一个 query 都必须把全部候选对重新前向一次**。

### 3.4 两阶段检索的最小实现

```python
# 依赖: pip install sentence-transformers
from sentence_transformers import SentenceTransformer, CrossEncoder
import numpy as np

bi = SentenceTransformer("BAAI/bge-small-zh-v1.5")
cross = CrossEncoder("BAAI/bge-reranker-base")

corpus = [
 "感冒了应该怎么办", "感冒药怎么吃", "今天天气怎么样",
 "发烧的处理方法", "如何预防流感", "什么是自然语言处理",
 "心血管疾病的常见症状", "高血压患者饮食注意",
]
corpus_emb = bi.encode(corpus, normalize_embeddings=True) # 离线预计算

query = "发烧了吃什么药"

# 阶段一：双塔召回 Top-4（毫秒级）
top_k = 4
scores = corpus_emb @ bi.encode(query, normalize_embeddings=True)
recall_idx = np.argsort(-scores)[:top_k]
recalled = [corpus[i] for i in recall_idx]

# 阶段二：Cross-Encoder 精排召回的候选
pairs = [[query, c] for c in recalled]
rerank_scores = cross.predict(pairs)

print("召回阶段（双塔）:")
for i in recall_idx:
 print(f" {scores[i]:.4f} {corpus[i]}")
print("\n精排阶段（Cross-Encoder）:")
for c, s in sorted(zip(recalled, rerank_scores), key=lambda x: -x[1]):
 print(f" {s:+.4f} {c}")
```

### 3.5 用 BERT 做句子对分类（贴合的中文句子关系案例）

```python
# 依赖: pip install transformers torch
import torch
import torch.nn as nn
from transformers import AutoTokenizer, AutoModel

MODEL = "bert-base-chinese"
tok = AutoTokenizer.from_pretrained(MODEL)
bert = AutoModel.from_pretrained(MODEL)
bert.eval

class SentencePairClassifier(nn.Module):
    """3 分类：蕴含 / 中立 / 矛盾（案例是 2 分类：是否下半句）"""

    def __init__(self, num_labels=2, hidden=768):
        super.__init__
        self.classifier = nn.Linear(hidden, num_labels)

        def forward(self, input_ids, token_type_ids, attention_mask):
            with torch.no_grad:
                out = bert(input_ids=input_ids, token_type_ids=token_type_ids,
                attention_mask=attention_mask)
                # 句对任务取 [CLS] 的表示（pooler_output）
                return self.classifier(out.pooler_output)

            model = SentencePairClassifier
            sent1 = "我想订一张明天去北京的机票"
            sent2 = "帮我查一下明天飞北京的航班"

            enc = tok(sent1, sent2, return_tensors="pt", truncation=True, max_length=128)
            print("input_ids :", enc["input_ids"].shape)
            print("token_type_ids :", enc["token_type_ids"].tolist[0][:20], "...（前段为0，后段为1）")
            print("attention_mask :", enc["attention_mask"].shape)

            with torch.no_grad:
                logits = model(enc["input_ids"], enc["token_type_ids"], enc["attention_mask"])
                print("logits:", logits.tolist)
```

注意 `token_type_ids` 的输出：句子 A 的部分是 0、句子 B 的部分是 1，这正是 Segment Embedding 的来源。

## 4. 常见坑

| 现象 | 原因 | 解决 |
|------|------|------|
| 直接用 BERT 的 `[CLS]` 或 mean-pooling 算句相似度，效果很差 | 原始 BERT 未被训练成「相似句向量靠近」 | 用 Sentence-BERT / CoSENT / SimCSE 微调过的句向量模型 |
| 余弦相似度都在 0.9 以上，无法区分 | 句向量的各维高度相关，向量集中在同一方向（各向异性） | 用对比学习训练过的模型（SimCSE/BGE）；或做白化（whitening）后再算 |
| 向量检索结果与暴力检索不一致 | ANN 是近似的，`nprobe` / `efSearch` 太小 | 调大检索参数；或先用 ANN 召回 Top-1000 再精排 |
| 换模型后所有相似度阈值全部失效 | 不同模型的相似度分布尺度不同 | 不要跨模型复用阈值；用验证集重新标定，或改用排序指标 |
| 用欧氏距离但向量未归一化，长短文本得分失衡 | 长文本向量模长更大 | 统一做 L2 归一化，之后余弦/内积/欧氏等价 |
| Cross-Encoder 上线后延迟过高 | 每个候选都要完整前向一次 | 改成两阶段：双塔召回 + Cross-Encoder 精排（候选 ≤ 100） |
| 用回归损失（MSE）训练中文句相似度，指标不稳定 | 中文标注的绝对相似度尺度不一致 | 改用排序损失（CoSENT）或对比损失（SimCSE） |
| 训练集里同一对句子同时作为相似与不相似出现 | 标注不一致或负样本采样有误 | 做数据清洗；正负样本构造时严格去重 |
| 检索时 query 与文档用不同前缀，效果掉点明显 | BGE / E5 这类模型训练时约定「query 加指令前缀、文档不加」 | 严格按模型卡说明加前缀，query 与 doc 的编码方式保持一致 |
| 把 SimCSE 的 `dropout` 关掉做推理，得到确定性向量但训练时不匹配 | 训练依赖 dropout 造正样本，推理时应当关闭（`eval`） | 训练用 `train`，推理用 `eval`，这是标准做法而非 bug |
| 中文句子关系任务直接用 `text[:22]` / `text[22:44]` 切分构造句子对 | 案例为演示目的用固定长度切分，实际句子边界会被切断 | 生产中用真实分句（按标点/换行切）构造句对，并保证正负样本比例均衡 |

## 5. 面试问答

**Q1. 双塔（Bi-Encoder）和交叉编码器（Cross-Encoder）该怎么选？为什么工业界常用两阶段？**

<details><summary>参考答案</summary>

**选择的本质是「效果」与「可索引性」的权衡**：

| | 双塔 | Cross-Encoder |
|---|---|---|
| 编码方式 | A、B 分别编码，最后才交互 | A、B 拼成一个序列，从第一层开始就在 self-attention 里交互 |
| 效果 | 较低（两段文本无法互相消歧） | 更高（能建模否定、指代、细粒度词序） |
| 复杂度 | 文档向量可**离线预计算**，查询时只需编码 query（1 次前向）+ 向量检索 | 每对 (query, doc) 都要完整前向一次 |
| 大规模检索 | 可行（建 ANN 索引） | 不可行（百万候选 = 百万次 BERT 前向） |

**为什么工业界用两阶段**：单用任何一方都不行。

- 只用双塔：召回率够但**精度不够**。双塔没有交互，无法区分「这个药有副作用」和「这个药没有副作用」——两者向量几乎相同。
- 只用 Cross-Encoder：精度够但**延迟爆炸**。100 万候选 × 每次 10ms = 10000 秒。

两阶段的做法是：双塔在全库上快速召回 Top-100（毫秒级，牺牲一点召回率可以接受）；Cross-Encoder 只对这 100 个精算分数（约 1 秒内）。这样把 Cross-Encoder 的 O(N) 成本降到了 O(K)（K=100），同时保住了最终排序质量。

工程上还有第三层：**多路召回**（BM25 稀疏召回 + 双塔稠密召回 + 规则召回）取并集后再精排。稀疏召回负责精确词匹配（人名、型号、专有名词），稠密召回负责语义泛化，两者互补。

</details>

**Q2. 为什么向量归一化之后，余弦相似度、内积、欧氏距离是等价的？**

<details><summary>参考答案</summary>

从余弦的定义出发：

$$\cos(\mathbf a,\mathbf b)=\frac{\mathbf a\cdot\mathbf b}{\lVert\mathbf a\rVert\lVert\mathbf b\rVert}$$

当 $\lVert\mathbf a\rVert=\lVert\mathbf b\rVert=1$ 时，分母为 1，所以**内积等于余弦相似度**，按内积排序与按余弦排序完全一致。

再看欧氏距离的展开式：

$$\lVert\mathbf a-\mathbf b\rVert^2=\lVert\mathbf a\rVert^2+\lVert\mathbf b\rVert^2-2\,\mathbf a\cdot\mathbf b$$

归一化后 $\lVert\mathbf a\rVert^2=\lVert\mathbf b\rVert^2=1$，于是

$$\lVert\mathbf a-\mathbf b\rVert^2=2-2\cos(\mathbf a,\mathbf b)$$

即欧氏距离是余弦的**严格单调递减函数**。距离越小 ⇔ 余弦越大 ⇔ 越相似。所以按欧氏距离排序与按余弦排序结果完全一致。

**工程价值**：

1. **速度**：内积可以直接用矩阵乘法（`embeddings @ q`）或 GPU 的 BLAS 加速，不需要每对都算两个模长。
2. **索引**：Faiss / Milvus 等库的 `IndexFlatIP`（内积索引）比余弦索引实现更简单、更快；很多库干脆只支持 IP/L2，让用户自己归一化。
3. **数值稳定**：归一化后所有向量落在单位球面上，数值范围可控，避免长文本因模长大而在点积上占据优势。

**实践注意**：

- 归一化是**必须显式做**的，多数模型（`sentence-transformers` 的 `encode`）默认不归一化，要传 `normalize_embeddings=True`。
- 反过来说，**如果模型本身用内积训练且向量模长携带了重要性信息**（如某些检索模型用模长编码「质量」），就不能盲目归一化，否则会丢信息。这时应用 IP 而不是余弦。

</details>

**Q3. 如果你要为一个百万级文档的问答系统做语义检索，会怎么设计？**

<details><summary>参考答案</summary>

分「离线」与「在线」两条管线设计。

**离线（可批量、可耗时）**：

1. **数据准备**：文档切块（chunking）。按语义边界（段落、标题层级）切，块大小 200–500 字，相邻块留 10%–20% 重叠，避免答案被切断。
2. **选模型**：中文检索用 BGE / text2vec / M3E 这类在检索任务上微调过的句向量模型，比通用 Sentence-BERT 明显更好。
3. **编码与归一化**：把所有块编码成 768 维（或更小）向量并 L2 归一化。**必须记下模型版本与前缀约定**（很多模型要求 query 加指令前缀、文档不加）。
4. **建索引**：用 Faiss/HNSW 建 ANN 索引；同时建一份 BM25 倒排索引用于稀疏召回。向量与元数据落库。
5. **缓存**：把文档向量持久化，模型升级时才重算。

**在线（要求低延迟）**：

1. **多路召回**：① 稠密召回——query 编码后 ANN 取 Top-100；② 稀疏召回——BM25 取 Top-100；③ （可选）规则召回——实体/关键词精确匹配。三路取并集去重。
2. **精排**：用 Cross-Encoder（bge-reranker 等）对并集打分，取 Top-10。候选数控制在 50–200。
3. **后处理**：分数阈值过滤（低于阈值不返回，避免"强行回答"）、按文档去重（同一文档的多个块只留最高分）、按业务规则加权（时效性、权威度）。
4. **组答案**：把 Top-K 块拼成上下文交给 LLM 生成答案（RAG），并要求引用出处。

**必须配套的评估与运维**：

| 环节 | 指标 | 做法 |
|------|------|------|
| 召回 | Recall@K | 人工标注 query→相关文档集合，看 Top-K 是否覆盖 |
| 精排 | NDCG@10 / MRR | 用带相关性等级的标注数据 |
| 端到端 | 答案准确率、幻觉率 | 人工评估或 LLM-as-judge |
| 性能 | P99 延迟、QPS | 压测；分档监控召回/精排/生成各自耗时 |
| 漂移 | 向量分布、分数分布 | 定期抽样，分布突变说明数据或模型出问题 |

常见取舍：**块越小召回越准但上下文越碎**；**精排候选越多效果越好但延迟越高**；**HNSW 内存换速度**。这些都要用真实流量数据调，不能拍脑袋。

</details>

## 6. 自测题

**1. 两个向量 $\mathbf a=(3,4)$、$\mathbf b=(1,0)$。分别求点积、余弦相似度、欧氏距离。归一化后点积是多少？**

<details><summary>参考答案</summary>

原始向量：

- **点积**：$\mathbf a\cdot\mathbf b = 3\times1+4\times0=3$
- **模长**：$\lVert\mathbf a\rVert=\sqrt{3^2+4^2}=5$，$\lVert\mathbf b\rVert=1$
- **余弦相似度**：$\dfrac{3}{5\times1}=0.6$
- **欧氏距离**：$\sqrt{(3-1)^2+(4-0)^2}=\sqrt{4+16}=\sqrt{20}\approx4.472$

归一化后：

- $\hat{\mathbf a}=(0.6,0.8)$，$\hat{\mathbf b}=(1,0)$
- **点积**：$0.6\times1+0.8\times0=0.6$ —— 正好等于原来的余弦相似度

验证欧氏距离与余弦的关系：$2-2\cos=2-1.2=0.8$，而 $\lVert\hat{\mathbf a}-\hat{\mathbf b}\rVert^2=(0.6-1)^2+0.8^2=0.16+0.64=0.8$ ✓

</details>

**2. BM25 相比 TF-IDF 的两个关键改进是什么？为什么这两个改进符合直觉？**

<details><summary>参考答案</summary>

**改进一：词频饱和（saturation）**。

TF-IDF 中词频是线性贡献的：某词出现 100 次，得分是出现 10 次的 10 倍。BM25 用

$$\frac{f(t,d)\cdot(k_1+1)}{f(t,d)+k_1}$$

这个因子随 $f$ 增大而**趋于上界** $(k_1+1)$。

直觉：一个词从出现 0 次到 1 次，信息量巨大；从 10 次到 11 次，几乎不增加新信息。重复堆砌同一个词（关键词堆砌 SEO）不应该持续加分，BM25 天然抑制了这种行为，TF-IDF 则会奖励它。

**改进二：文档长度归一化**。

$$\Big(1-b+b\cdot\frac{|d|}{\text{avgdl}}\Big)$$

长文档天然包含更多词，任何 query 词都更可能在其中出现。BM25 用文档长度与平均长度的比值做补偿，$b$ 控制归一化强度（常取 0.75）。

直觉：一篇 10000 字的文章出现「感冒」1 次，和一篇 50 字的标题出现「感冒」1 次，后者明显更相关。TF-IDF 若不归一化就区分不出这个差别。

两个改进合起来解释了为什么 BM25 至今仍是检索系统不可替代的基线——它用极低成本编码了「词频边际递减」和「文档长度偏差」这两个真实的语言统计规律。

</details>

**3. 为什么直接用 BERT 的 `[CLS]` 向量算句子相似度效果不好？SimCSE 是怎么解决的？**

<details><summary>参考答案</summary>

**原始 BERT 句向量效果差的原因**：

1. **训练目标不匹配**。BERT 的预训练任务是 MLM 和 NSP，从未被优化为「相似句子的向量靠近」。`[CLS]` 向量在分类任务上够用，但它的空间结构没有度量语义相似度的性质。SBERT 论文的实测显示：原始 BERT 的 `[CLS]` 在 STS 任务上的 Spearman 相关甚至低于 GloVe 平均句向量。
2. **各向异性（anisotropy）**。BERT 输出的向量集中在向量空间的一个狭窄锥形区域内，任意两个句向量的余弦相似度普遍偏高（常 > 0.8），区分度很低——相关和不相关的句子得分差距很小。
3. **没有度量学习**。要让「相似靠近、不相似远离」，必须有显式的正负样本对和对应的损失函数。

**SimCSE 的解法**：用对比学习（InfoNCE 损失）直接优化「正样本更近、负样本更远」这个目标。它最巧的地方在于**无监督版本的正样本构造**：

> 同一个句子分别前向两次，由于 dropout 的随机性（每层随机置零不同的神经元），得到两个略有差异的向量，把这两个当作正样本对；同一个 batch 内其他句子作为负样本。

$$\mathcal{L}_i=-\log\frac{\exp(\cos(u_i,u_i^+)/\tau)}{\sum_{j=1}^{N}\exp(\cos(u_i,u_j)/\tau)}$$

这个设计的精妙之处在于：它**不需要任何标注数据**就能构造正样本对，而且等价于「把 dropout 当作最小数据增强」。论文还发现了一个反直觉的现象：**把 dropout 全部去掉、只用同一句子两次前向得到的相同向量作正样本**，反而是个很强的基线——这进一步说明「让同一句子的表示稳定，同时把不同句子推开」这个目标本身就非常有效。

有监督版本则用 NLI 数据：蕴含句对作正样本，矛盾句对作负样本，效果比无监督版本更好。

</details>

**4. 检索系统上线后，用户反馈「明明库里有答案却搜不到」。你会从哪几个方向排查？**

<details><summary>参考答案</summary>

按「召回 → 精排 → 后处理」的顺序逐层定位，**先确认问题出在哪一层**：把该 query 的答案文档拿出来，看它在各层排名如何。

| 层 | 排查项 | 常见原因与修法 |
|----|--------|---------------|
| 数据与切块 | 答案是否真的进了索引？是否被切块切断？ | chunk 太小/边界不当导致答案跨块；增大块或加重叠；检查文档是否漏入库 |
| 编码 | query 与 doc 的编码方式是否一致？ | 漏了 query 指令前缀（BGE/E5 类模型）；归一化与否不一致；编码时截断了长文档 |
| 召回 | 在该 query 上，答案文档的召回排名是多少？ | 稠密召回漏掉 → 补一路 BM25 稀疏召回（专有名词、型号、人名靠字面匹配）；ANN 的 `nprobe`/`efSearch` 太小导致真近邻被漏 → 调大参数 |
| 模型能力 | 换更强的检索模型是否解决？ | 通用模型在垂直领域弱 → 用领域数据微调双塔（对比学习）；换用检索任务上训练过的模型 |
| 精排 | 答案进了候选但被精排打到很低？ | 精排模型领域不匹配；候选数太少（答案没进 Top-100）；阈值过滤误杀 |
| 后处理 | 是否被去重/时效性/权威度规则压掉？ | 同一文档多块去重时保留了低分块；硬规则过度加权 |
| 评测 | 有没有量化依据？ | 建一套人工标注的 query→相关文档集，测 Recall@100 / NDCG@10，避免只靠个案判断 |

**最容易被忽略的两点**：

1. **「搜不到」和「排序太靠后」是两类不同问题**。前者是召回层的 Recall 问题，后者是排序层的排序问题。混在一起排查会浪费大量时间——必须先把答案文档的最佳可能排名查出来。
2. **稀疏 + 稠密多路召回是性价比最高的修法**。大量真实 case 是「语义召回把精确匹配的词丢了」：查型号「WH-1000XM5」时稠密向量几乎无能为力，而 BM25 一击命中。补一路稀疏召回往往比换更大的模型见效更快。

</details>
