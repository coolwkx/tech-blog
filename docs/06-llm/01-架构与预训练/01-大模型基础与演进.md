> **一句话总结**：大语言模型（LLM）是「用海量文本 + 超大参数量 + 预训练/微调范式」训练出来的语言模型，它把语言建模从 N-gram 的计数统计一路推进到自回归生成，并带来了 SFT/RLHF 这套对齐训练流程。
> **前置知识**：概率论中的链式法则与条件概率、softmax、交叉熵、Python 基础（列表/字典/循环）。
> **学完能做到**：1. 说清语言模型四个技术阶段各自的假设、代表模型与失效原因；2. 手算 N-gram 概率与 PPL，并用代码算 BLEU/ROUGE；3. 解释「预训练 + 微调」和 SFT→RM→PPO 对齐流水线各自解决什么问题。

## 1. 核心概念

### 1.1 什么是语言模型

**语言模型（Language Model, LM）** 的目标是给「词序列」建模概率分布：给定词典 $V$ 和一个句子
$S=\{W_1,W_2,\dots,W_n\}$，语言模型要能算出 $P(S)$——$P(S)$ 越大，说明这个句子越像「人话」。

两种等价视角：

| 视角 | 定义 | 典型用法 |
|---|---|---|
| 打分视角 | 能计算 $P(W_1,W_2,\dots,W_n)$ 的模型 | 判断句子是否通顺、给候选译文排序 |
| 生成视角 | 给定前文，能预测（生成）下一个词 | 文本生成、对话、续写 |

两种视角通过**链式法则**打通（这也是自回归生成的数学基础）：

$$P(W_1,\dots,W_n)=\prod_{i=1}^{n}P(W_i \mid W_1,\dots,W_{i-1})$$

也就是说：只要能算「给定前文时下一个词的概率」，就能算整句话的概率；反过来，逐词采样就能生成句子。
**现代 LLM 的 next-token prediction 训练目标，本质上就是在上式两边做最大似然。**

### 1.2 语言模型技术的四个阶段

| 阶段 | 核心思路 | 代表模型/方法 | 关键局限 |
|---|---|---|---|
| ① 基于规则和统计 | 人工设计特征 + 统计计数（最大似然估计） | N-gram（unigram/bigram/trigram） | 数据稀疏、参数空间指数增长、泛化差 |
| ② 神经网络语言模型 | 用词向量 + 前馈网络预测下一个词 | NNLM（Bengio 等） | 长序列建模能力有限、梯度消失 |
| ③ 预训练语言模型 | Transformer + 大规模无监督预训练，再在下游微调 | BERT、GPT、T5 | 计算资源需求大、可解释性差 |
| ④ 大语言模型 | 参数与数据指数级扩张，走向对话/生成/多模态与人类对齐 | GPT-3、ChatGPT、GLM、BLOOM、LLaMA、Qwen | 算力成本高、可能生成有害或有偏见内容 |

把「大语言模型」定义为**参数量通常超过 10B（百亿）规模**的语言模型；2020 年 OpenAI 的 GPT-3（1750 亿参数）首次大规模展示了 LLM 的能力：**不调整权重，仅凭用户给出的任务示例就能完成具体任务**。此后各大厂商跟进，代表包括 Meta 的 LLaMA-13B、Google 的 PaLM-540B，国内有百度的文心一言 ERNIE 系列、清华团队的 GLM 系列等。

> 一句话理解四个阶段的递进关系：**N-gram 解决了「怎么算概率」，神经网络解决了「怎么泛化」，预训练解决了「怎么复用知识」，LLM 解决了「怎么零样本/少样本完成任务」。**

### 1.3 语言模型评估指标总览

| 指标 | 衡量什么 | 取值范围 | 方向 | 典型场景 |
|---|---|---|---|---|
| Accuracy（准确率） | 预测正确的样本占总样本比例 | [0,1] | 越大越好 | 分类 |
| Precision（精确率） | 被判为正类的样本中真正为正的比例 | [0,1] | 越大越好 | 检索、抽取 |
| Recall（召回率） | 所有正类样本中被识别出来的比例 | [0,1] | 越大越好 | 检索、抽取 |
| BLEU | 生成文本与参考文本的 **n-gram 精确率**（带长度惩罚） | [0,1] | 越大越好 | 机器翻译 |
| ROUGE | 生成文本对参考文本的 **n-gram 召回率** | [0,1] | 越大越好 | 摘要、问答生成 |
| PPL（困惑度） | 语言模型预测样本的「好坏程度」，越小越好 | $[1,+\infty)$ | 越小越好 | 语言模型本身的质量 |

## 2. 关键机制

### 2.1 N-gram：为什么要引入马尔可夫假设

直接用链式法则会遇到两个致命缺陷：

1. **参数空间过大**：$P(W_n \mid W_1,\dots,W_{n-1})$ 的组合数随 $n$ 指数增长，无法估算；
2. **数据稀疏严重**：很多词对组合在语料中从未出现，依最大似然估计得到概率为 0。

于是引入**马尔可夫假设**：一个词出现的概率只与它前面有限的 $N-1$ 个词有关。

| 名称 | 假设 | 说明 |
|---|---|---|
| unigram | 词与周围词独立 | 一元语言模型 |
| bigram | 只依赖前 1 个词 | 实践中常用 |
| trigram | 只依赖前 2 个词 | 实践中常用 |

bigram 概率用「计数相除」估计（$C(\cdot)$ 为语料中的计数）：

$$P(W_i \mid W_{i-1})=\frac{C(W_{i-1},W_i)}{C(W_{i-1})}$$

**计算示例**：先统计语料得到 $C(W_{i-1},W_i)$ 与 $C(W_{i-1})$，相除即得参数；例如算出 $P(\text{想}\mid\text{我})=0.38$，再把整句各位置概率连乘即可给句子打分。预测「我想去打【mask】」时，比较 $P(\text{篮球}\mid\text{打})$ 与 $P(\text{晚饭}\mid\text{打})$，取大者作为答案——这与人类语感一致。

N-gram 的优缺点：

| 优点 | 缺点 |
|---|---|
| 完全包含了前 $n-1$ 个词的全部信息 | 只能建模到前 $n-1$ 个词，无法捕捉更长依赖 |
| 可解释性强、直观易理解 | 数据稀疏导致 OOV（未登录词）问题 |
| 采用极大似然估计，参数易训练 | 随 $n$ 增大参数量指数增长，泛化能力差 |

### 2.2 神经网络语言模型：从计数到向量

用神经网络做语言模型的基本结构（语料中给出的 NNLM 三层设计）：

| 层 | 作用 | 细节 |
|---|---|---|
| 第一层（输入/查表） | 把前 $n-1$ 个词映射为词向量并拼接 | 得到 $(n-1)\times m$ 的向量 $x$ |
| 第二层（隐藏层） | 全连接 + `tanh` 激活 | 学习词间组合关系 |
| 第三层（输出层） | 全连接到 $V$ 个节点（$V$ 为词表大小），softmax 归一化 | 输出每个词作为下一个词的未归一化 logits 与概率 |

优点：相比 N-gram 有更好的泛化能力（词向量让相似词共享统计强度）；缺点：对长序列建模能力有限、可能出现梯度消失。
**这一阶段的真正遗产是「分布式词表示」——它直接通向 Transformer 的 embedding 层。**

### 2.3 预训练 + 微调：知识复用的两阶段范式

| 阶段 | 做什么 | 目的 |
|---|---|---|
| 预训练（Pre-training） | 在大规模通用文本上做自监督训练（如预测被 mask 的词、预测下一个词） | 学到通用语言表示与常识知识 |
| 微调（Fine-tuning） | 在具体下游任务数据上继续训练 | 把通用知识迁移到目标任务，获得更好的泛化效果 |

基于 Transformer 的预训练模型代表：GPT、BERT、T5。预训练模型的优点：更强大的泛化能力、丰富的语义表示、可有效防止过拟合；缺点：计算资源需求大、可解释性差。

大语言模型在此基础上再进一步：优点是与人类沟通能力更强、可使用插件做自动信息检索；缺点是参数量大、算力要求高、训练时间长，且可能生成有害或有偏见的内容。

### 2.4 对齐训练：SFT → 奖励模型 → RLHF

「预训练 + 微调」解决的是「会不会」，**对齐（alignment）**解决的是「听不听话、合不合人类偏好」。扩展（《大模型的强化学习》）把 RLHF 讲得很细，这里提炼最小必需框架。

RLHF-PPO 阶段同时要跑**四个模型**：

| 角色 | 作用 | 是否训练 | 初始化 |
|---|---|---|---|
| Actor | 要优化的目标语言模型，输出 token 即「动作」 | 训练 | 由 SFT 模型初始化 |
| Critic | 估计状态价值 $V(s)$，用于计算优势（advantage） | 训练 | 通常用 RM 或 SFT 初始化 |
| Reward Model | 给「prompt + response」打分，提供即时收益 $R_t$ | 冻结 | RW 阶段训练得到 |
| Reference Model | 用 KL 散度约束 Actor 不要偏离 SFT 分布太远 | 冻结 | 由 SFT 模型初始化 |

NLP 语境下的强化学习映射关系：**状态 = prompt + 已生成的前文，动作 = 下一个 token（动作空间即词表），收益 = 奖励模型给出的分数**。加入 Reference Model + KL 惩罚的动机是缓解 **reward hacking**（模型钻奖励模型的空子，输出看似高分实则跑偏的内容）。

工程代价：若训练 70B 模型，PPO 需要同时载入约 $70\times4=280$B 参数，其中约 $70\times2=140$B 需要训练——**这就是 PPO「非常耗卡」的根本原因**。后续一系列工作都在削减模型数量：

| 方法 | 保留的模型 | 关键思想 |
|---|---|---|
| PPO | Actor + Critic + RM + Ref（4 个） | 用 Critic 拟合基线以降低方差，加入 importance sampling 与 clip |
| GRPO | 去掉 Critic | 对同一 prompt 采样 G 个答案，用组内平均分作为 baseline；KL 惩罚整体加到最终 loss |
| ReMax | 去掉 Critic | 用 greedy 解码的奖励作基线（$r-r_{greedy}$） |
| DPO | Actor + Ref（2 个） | 不需要显式 RM，直接在偏好数据对（chosen/rejected）上做类监督式优化 |
| ORPO | 仅 Actor（1 个） | SFT Loss + Odds Ratio Loss 合二为一，直接在偏好数据上训练 |

SFT（监督微调）是整条链路的起点：它用「指令 → 高质量回答」的样本让模型学会遵循指令，之后才能谈偏好对齐。**记住这条主线：预训练（学知识）→ SFT（学听话）→ RM（学评分）→ PPO/DPO（学偏好）。**

### 2.5 BLEU / ROUGE / PPL 的计算要点

**BLEU**：分别统计 candidate 与 reference 的 n-gram（实践中 $N=1\sim4$），计算「匹配的 n-gram 个数 / candidate 中 n-gram 个数」，再对各阶 n-gram 做加权平均（几何平均 + 简短惩罚）。

以 `candidate: it is a nice day today`、`reference: today is a nice day` 为例：

| n-gram | 匹配情况 | 匹配度 |
|---|---|---|
| 1-gram | {today, is, a, nice, day} 匹配 | 5/6 |
| 2-gram | {is a, a nice, nice day} 匹配 | 3/5 |
| 3-gram | {is a nice, a nice day} 匹配 | 2/4 |
| 4-gram | {is a nice day} 匹配 | 1/3 |

**BLEU 的致命缺陷与修正**：极端例子 `candidate: the the the the`、`reference: the cat is standing on the ground`，若按 1-gram 朴素匹配匹配度为 1，显然不合理。修正办法是**截断（clip）**：先取该词在参考句中出现的最大次数 $s_k$，再与候选句中的出现次数 $c_k$ 取较小值。

**ROUGE**：与 BLEU 非常类似，**区别在于 ROUGE 基于召回率，BLEU 更看重准确率**。ROUGE-N 把生成结果与标准结果按 n-gram 拆分后计算召回率；同一例子中 ROUGE-1 匹配度为 5/5=1（生成内容覆盖了参考文本所有单词）。ROUGE 家族包括 ROUGE-N、ROUGE-L、ROUGE-W、ROUGE-S。

**PPL（困惑度）**：用来度量概率分布/概率模型预测样本的好坏程度，**句子概率越大，语言模型越好，困惑度越小**。

$$\mathrm{PPL} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N}\ln p(w_i)\right)$$

直觉理解：PPL 可以近似看成「模型在每个位置上平均要在多少个候选词里犹豫」。等价地，PPL = $2^{H}$（$H$ 为以 2 为底的交叉熵），所以**降低 PPL 本质上就是降低交叉熵**。

> 请注意一个常见混淆：BLEU/ROUGE 衡量的是「生成结果 vs 参考文本」的相似度（需要参考答案），PPL 衡量的是「模型对文本的预测能力」（**不需要**参考答案），三者用途不同，不能互相替代。

## 3. 可运行示例

### 3.1 用 nltk 计算 BLEU（含累计 BLEU）

```python
# 依赖：pip install nltk
from nltk.translate.bleu_score import sentence_bleu, cumulative_bleu

reference = [["today", "is", "a", "nice", "day"]] # 参考译文（列表的列表）
candidate = ["it", "is", "a", "nice", "day", "today"] # 候选译文

# 单阶 BLEU：nltk 的 weights 需要 4 元组，对应 1~4-gram 权重
bleu_1 = sentence_bleu(reference, candidate, weights=(1, 0, 0, 0))
bleu_2 = sentence_bleu(reference, candidate, weights=(0.5, 0.5, 0, 0))
bleu_3 = sentence_bleu(reference, candidate, weights=(0.33, 0.33, 0.33, 0))

# 累计 BLEU：对 1~4-gram 取几何平均并施加简短惩罚
c_bleu = cumulative_bleu(reference, candidate, weights=(0.25, 0.25, 0.25, 0.25))

print("BLEU-1:", round(bleu_1, 4))
print("BLEU-2:", round(bleu_2, 4))
print("BLEU-3:", round(bleu_3, 4))
print("cumulative BLEU:", round(c_bleu, 4))
```

> 注意函数名是 `cumulative_bleu`（语料里 OCR 成了 `cumulative_blue`）。另外 `sentence_bleu` 要求
> 参考译文是「列表的列表」，直接传 `[ref_sentence]` 会报维度错误。

### 3.2 手算 PPL，理解公式

```python
# 依赖：仅标准库
import math

# 一个极简 unigram 概率表（模拟语料统计结果，共 12 个词次）
unigram = {
"I": 1/12, "have": 1/12, "a": 3/12, "pen": 1/12,
"He": 1/12, "has": 1/12, "book": 1/12,
"She": 1/12, "cat": 1/12,
}

sentences = [
["I", "have", "a", "pen"],
["He", "has", "a", "book"],
["She", "has", "a", "cat"],
]

total_log_prob, total_tokens = 0.0, 0
for sentence in sentences:
    for word in sentence:
        total_log_prob += math.log(unigram[word]) # 累加对数概率
        total_tokens += 1

        # PPL = exp(-1/N * sum(log p))
        perplexity = math.exp(-total_log_prob / total_tokens)
        print("困惑度 PPL =", round(perplexity, 4))
```

要点：**先取对数再平均再取指数**，避免多词概率连乘下溢为 0；这也说明为什么训练时用
cross-entropy loss 与用 PPL 做评估是同一件事。

### 3.3 用 rouge 计算 ROUGE（并注意兼容性）

```python
# 依赖：pip install rouge
from rouge import Rouge

generated_text = "This is some generated text."
reference_texts = ["This is another generated reference text."]

rouge = Rouge
scores = rouge.get_scores(generated_text, reference_texts[0])[0]
# 注意：get_scores 返回的是列表，取 [0] 才是这一对文本的分数
print("ROUGE-1 precision:", scores["rouge-1"]["p"])
print("ROUGE-1 recall:", scores["rouge-1"]["r"])
print("ROUGE-1 f1:", scores["rouge-1"]["f"])
```

> 常见坑：`rouge` 包只按空格切词且不区分大小写，中文必须先分词（如 jieba）再以空格拼接；
> 该包在较新 Python 上可能有兼容问题，若安装失败可用 `rouge-chinese` 或自行实现 ROUGE-N 召回率。

## 4. 常见坑

| 坑 | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 把 N-gram 概率直接连乘 | 长句子概率下溢为 0 | 浮点数下溢 | 取对数后累加（log-prob），最后再取指数 |
| 用最大似然估计硬算未见组合 | 概率恒为 0 | 数据稀疏 | 平滑（Add-k、Kneser-Ney）或改用神经网络/预训练模型 |
| 混淆 BLEU 与 ROUGE 方向 | 指标解释反了 | BLEU 基于精确率、ROUGE 基于召回率 | 记住「BLEU 看生成得准不准，ROUGE 看覆盖全不全」 |
| 用朴素 1-gram 匹配算 BLEU | `the the the the` 得分虚高 | 未做截断计数 | 用 clip：`min(候选句计数, 参考句最大计数)` |
| 参考译文维度写错 | `sentence_bleu` 抛异常 | 参考需为「列表的列表」 | `reference = [tokens]`，多参考则 `[[t1],[t2]]` |
| 把 PPL 当越大越好 | 选模型时选反 | PPL 是「困惑度」，越小越好 | PPL 越小说明模型对测试集预测越准 |
| PPL 手算时先乘后取对数 | 结果溢出/为 0 | 连乘导致数值问题 | 全程用 log 概率：`exp(-mean(log_p))` |
| 认为 PPO 是唯一对齐方案 | 觉得 RLHF 必须 4 张模型 | 受早期实践影响 | 认识 GRPO/ReMax/DPO/ORPO 等省卡路线，按场景选择 |
| 把「大模型」等同于「参数多」 | 忽略对齐与数据 | 定义只看参数量 | LLM 能力 = 参数 × 数据 × 训练目标 × 对齐，缺一不可 |

## 5. 面试问答

**Q1：N-gram 语言模型的核心假设是什么？它为什么会被神经网络语言模型取代？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

核心假设是**马尔可夫假设**：一个词出现的概率只与它前面有限的 $N-1$ 个词有关，因此
$P(W_i\mid W_1..W_{i-1})\approx P(W_i\mid W_{i-N+1}..W_{i-1})$，参数可用语料计数做最大似然估计。

被取代的原因有三点：
1. **数据稀疏**：大量词组合未在语料出现，概率为 0，泛化差且存在 OOV 问题；
2. **参数空间爆炸**：参数量随 $n$ 指数增长，$n$ 稍大就无法存储与训练；
3. **表达能力受限**：只能建模 $n-1$ 个词的历史，无法捕捉长距离依赖。

神经网络语言模型用**词向量**表示词、用**网络**拟合条件概率，相似词共享统计强度，泛化能力显著变强；
再往后 Transformer + 预训练范式彻底解决了长距离依赖与知识复用问题，最终演进为大语言模型。

</details>

**Q2：BLEU 和 ROUGE 有什么区别？为什么 BLEU 需要做截断（clip）计数？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

相同点：都用 n-gram 重叠度衡量生成文本与参考文本的相似度。

区别：**BLEU 基于精确率**（生成文本中有多少 n-gram 出现在参考文本里），主要用于机器翻译；
**ROUGE 基于召回率**（参考文本中有多少 n-gram 被生成文本覆盖），主要用于摘要与问答生成。

BLEU 需截断的原因：若只统计「候选句的 n-gram 是否在参考句中出现」，则
`candidate: the the the the` 对 `reference: the cat is standing on the ground` 的 1-gram 匹配度会是 1，
明显不合理。截断计数取 $\min(c_k, s_k)$（$c_k$ 为词在候选句中的出现次数，$s_k$ 为它在参考句中出现的最大次数），
把重复词的有效匹配限制在参考句允许的范围内，从而惩罚这种「刷词」行为。

补充：BLEU 还需配合简短惩罚（brevity penalty），否则极短译文会因分母小而拿高分。

</details>

**Q3：RLHF 中为什么要引入 Reference Model 和 KL 惩罚？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

RLHF 的目标是让 Actor 生成符合人类偏好的回答，但**奖励模型只是人类偏好的近似**。
如果只最大化奖励模型的分数，Actor 会迅速找到奖励模型的漏洞（reward hacking），输出分数虚高、
实际质量崩坏的文本，同时输出分布会偏离 SFT 模型越来越远，出现语言退化、重复、乱码等现象。

Reference Model 由 SFT 模型初始化且参数冻结，为每个 token 提供「原分布」的参考概率；
在奖励中加入 $\mathrm{KL}(\pi_{actor}\|\pi_{ref})$ 惩罚项，等于给优化加了一个「不要离 SFT 太远」的软约束，
使模型在提升偏好得分的同时保持语言能力与输出多样性。这也是 PPO 需要同时载入 4 个模型、
进而「非常耗卡」的原因，后续 GRPO/DPO 等工作正是围绕削减这部分开销展开的。

</details>

## 6. 自测题

**1. 写出语言模型的链式法则表达式，并说明它为什么能同时支撑「打分」和「生成」两种用法。**

<details markdown="1">
<summary markdown="1">参考答案</summary>

$P(W_1,\dots,W_n)=\prod_{i=1}^{n}P(W_i\mid W_1,\dots,W_{i-1})$。

打分：把每个位置的条件概率相乘（实际用 log 相加）即得整句概率；
生成：从 $P(W_1)$ 采样得到第一个词，再把已生成内容作为条件反复采样下一个词，即可逐步生成整句。
LLM 的 next-token prediction 训练目标正是在最大化该式的似然。

</details>

**2. 一个测试集句子「我 爱 自然 语言 处理」，模型给出的条件概率依次为 0.5、0.4、0.2、0.25、0.1，求 PPL。**

<details markdown="1">
<summary markdown="1">参考答案</summary>

$-\frac{1}{5}\left(\ln 0.5+\ln 0.4+\ln 0.2+\ln 0.25+\ln 0.1\right)
= -\frac{1}{5}(-0.693-0.916-1.609-1.386-2.303)=\frac{6.907}{5}=1.3814$

$\mathrm{PPL}=e^{1.3814}\approx 3.98$。即模型平均在约 4 个候选词之间犹豫。

</details>

**3. 为什么说 N-gram 的「参数空间随 n 指数增长」？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

$n$ 元模型需要为每个长度为 $n$ 的词组合存一个参数，组合数为 $|V|^n$（$V$ 为词表）。
词表 5 万、$n=3$ 时约 $1.25\times10^{14}$ 个参数，$n=4$ 时再乘 5 万，完全无法存储与充分估计，
而绝大多数组合在语料中出现次数为 0。

</details>

**4. BLEU 与 PPL 能否互相替代？为什么？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

不能。BLEU 需要参考答案（reference），衡量生成文本与参考文本的 n-gram 重叠，属于「有参考答案的生成质量评估」；
PPL 不需要参考答案，衡量模型对文本身的预测概率，属于「语言模型内在质量评估」。
一个模型 PPL 很低但 BLEU 可能不高（例如过于保守、输出通用模板），反之亦然。做 RAG/摘要等任务评估时，
二者通常搭配任务指标（如忠实度、命中率）一起使用。

</details>

**5. SFT、RM、PPO 三个环节各自解决什么问题？**

<details markdown="1">
<summary markdown="1">参考答案</summary>

- **SFT（监督微调）**：用「指令 → 高质量回答」的样本让模型学会遵循指令、输出符合对话格式的内容，提供对齐的起点模型。
- **RM（奖励模型）**：用人类偏好比较数据训练一个打分器，把「人类喜好」量化成一个可优化的标量奖励，替代昂贵的人工实时标注。
- **PPO（近端策略优化）**：以 RM 的分数为奖励、以 Reference Model 的 KL 惩罚为约束，用强化学习更新 Actor，
 让模型在保持语言能力的前提下提升符合人类偏好的程度。

</details>
