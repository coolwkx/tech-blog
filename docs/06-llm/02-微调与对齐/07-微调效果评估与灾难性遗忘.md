# -微调效果评估与灾难性遗忘


> **一句话总结**：微调评估不能只看目标任务的 F1，必须同时盯住**通用能力保持**、**格式合规率**与**过拟合信号**；其中最有价值、也最常被忽略的一项就是通用能力回测——它衡量的是 **catastrophic forgetting（灾难性遗忘）**，而灾难性遗忘的本质是参数为适配新分布发生的漂移，可以用低秩更新、回放、正则约束、数据混合、只训部分层这几类手段来缓解。
> **前置知识**：监督微调（SFT）的基本流程、LoRA 等参数高效微调方法、分类与生成的常用指标（acc / P / R / F1 / ROUGE / 通过率）、训练集-验证集切分与交叉验证。
> **学完能做到**：1. 为一个微调任务设计四维度评估方案，并给出「未微调 + 好提示词」这条必设基线；2. 用通用基准回测量化灾难性遗忘，并给出遗忘率数字；3. 写出一份能同时输出任务指标、格式合规率与遗忘度量的评估脚本骨架。

## 1. 核心概念

### 1.1 为什么「微调评估」比「模型评估」更容易翻车

微调评估的困难不在指标计算，而在**指标之外的东西会一起变**。一次微调同时动了四件事：

| 变了什么 | 表现 | 只看目标任务指标会怎样 |
|---|---|---|
| 目标任务的决策边界 | 目标任务指标上升 | 能看到 |
| 模型的整体分布 | 通用能力下降、语言风格漂移 | **完全看不到** |
| 输出格式习惯 | 该输出 JSON 的地方输出了解释性文字 | 只有在严格解析时才暴露 |
| 与训练集的亲近程度 | 复述训练样本、模板化回答 | 只有在换一批测试数据时才暴露 |

所以微调评估的第一原则是：**目标指标只是四个维度中的一个**。

### 1.2 四个评估维度

| 维度 | 回答什么问题 | 典型指标 | 采集方式 |
|---|---|---|---|
| ① 目标任务指标 | 该做的任务做对了吗 | Accuracy / P / R / F1 / EM / ROUGE-L / 人工通过率 | 留出测试集，同分布 |
| ② 通用能力保持 | 别的能力被破坏了吗 | 通用基准分（常识、推理、阅读理解）相对基线的**保持率** | 通用基准回测 |
| ③ 格式合规率 | 输出能不能被程序消费 | JSON 可解析率、schema 通过率、必填字段齐全率 | 解析器批量跑，统计失败率 |
| ④ 过拟合检查 | 是学到了规律还是背下了数据 | 训练/验证 loss 曲线、泛化 gap、扰动测试、复述率 | 训练日志 + 扰动集 |

**维度③经常是真正的上线阻塞项。** 一个 F1 从 0.62 涨到 0.71、但 JSON 可解析率从 99% 掉到 78% 的模型，在生产上是一次严重的回归——因为解析失败会直接触发兜底逻辑或报错。所以格式合规率必须和 F1 一起看，且要有绝对下限（例如 ≥ 99%）。

### 1.3 基线：必须是「未微调 + 好提示词」

这是最容易被跳过、也最容易得出错误结论的一步。

**错误做法**：拿微调后的模型和「未微调的裸模型」比，赢了就汇报。

**正确做法**：基线是**同一个基座模型 + 精心设计的提示词 + few-shot 示例**。原因很直接：如果提示词工程能让指标从 0.45 涨到 0.70，而微调只涨到 0.72，那么这次微调的边际收益是 0.02，而成本是训练数据、GPU 小时和一套需要长期维护的训练流水线——这个决策结论和「0.45 → 0.72」是完全相反的。

一个合格的对比实验至少要有四行：

| 组别 | 说明 |
|---|---|
| A. 零样本 | 只给任务指令，不给示例 |
| B. few-shot | 好提示词 + 3~5 个示例（**这是主基线**） |
| C. 微调 | 全参或 LoRA，报告参数量与训练成本 |
| D. 微调 + few-shot | 微调后再加示例，看两者是互补还是互相覆盖 |

补充两条实验纪律：

- **同分布的测试集**：A/B/C/D 必须用同一批测试样本，且测试集从未参与任何一组的构造；
- **多次运行取均值**：生成式任务的方差很大，至少要跑 3 个随机种子，报告均值 ± 标准差，否则 0.02 的差异完全没有意义。

### 1.4 灾难性遗忘（catastrophic forgetting）

**定义**：模型在学习新任务的过程中，丢失了预训练阶段（或此前微调阶段）已经获得的知识与能力。

**典型表现**（按出现频率排序）：

| 表现 | 例子 |
|---|---|
| 通用知识与常识下降 | 问答基准分掉 10+ 分；日期、常识、数学计算出错增多 |
| 语言能力退化 | 中文表达变得生硬、出现英文夹杂、重复句式 |
| 指令遵循能力下降 | 不再遵守「不要解释」「只输出 JSON」这类格式指令 |
| 拒答与安全行为削弱 | 对敏感问题的拒绝率下降 |
| 多语言能力下降 | 用中文数据微调后，英文能力明显退化 |

**根本原因：参数漂移。** 预训练得到的权重编码了一整套「语言 + 世界知识」的表示，微调时用一批高度同质、领域集中的数据去做梯度更新，会把权重推离原位置。偏差积累到一定程度，原本依赖这些权重才能完成的任务就失败了。具体机制上有几条常见的解释：

1. **分布偏移 + 灾难性干扰**：新任务的梯度方向与旧任务的最优方向冲突，参数更新沿着新任务的方向走，旧任务的解被覆盖；
2. **表示坍缩**：低资源、窄领域的数据会让模型的表示空间收缩到该领域的子空间，通用表示被挤压；
3. **过拟合到表层模式**：模型学到的是「这个训练集的模板」，而不是任务本身，于是遇到别的任务就用这个模板回应；
4. **输出分布改变**：SFT 让模型输出的概率分布整体偏移（比如变得更啰嗦或更简短），连带改变了其他任务的输出质量。

**为什么参数高效微调天然更抗遗忘**：全参微调让所有参数都有机会移动，旧任务的解没有任何「锚点」；而 LoRA 把更新限制在一个低秩子空间里、只训部分层冻结其余部分，等于给优化过程加了一个强约束——**可表达的变化本身就有限**。这也是「PEFT 在低数据环境下优于全参微调」这一常见结论的部分原因：不是 PEFT 更强，而是全参在小数据上更容易跑偏。

不过要明确一点：**LoRA 不是遗忘免疫**。当秩很大、epoch 很多、学习率很高、领域数据极度同质时，LoRA 同样会出现明显的通用能力退化。它降低的是遗忘的概率与幅度，不是消除。

### 1.5 灾难性遗忘与「学不会」的区别

这两个现象容易混淆，但处理方式完全相反：

| 维度 | 学不会（欠拟合） | 灾难性遗忘 |
|---|---|---|
| 训练 loss | 降不下去或降得很少 | 正常下降到很低 |
| 目标任务指标 | 低，且提升缓慢 | 通常达标甚至很好 |
| 通用基准 | 基本不变 | **明显下降** |
| 输出风格 | 还是原来的风格，只是答不准 | 风格被新数据「带跑」 |
| 修复方向 | 加容量（r、target_modules）、加数据、加 epoch | 加回放、降容量、降学习率、减 epoch |

**判断方法**：同时跑目标任务评测和通用基准回测。目标任务达标 + 通用基准下降 = 遗忘；两者都不达标 = 欠拟合。只有先分清是哪一种，后续动作才不会是反的——给遗忘的模型「加 r 提升效果」是最常见的反向操作。

### 1.6 度量方式

灾难性遗忘不能靠感觉，必须有数字。标准做法是**通用基准回测**：

```
遗忘率 = (微调前分数 - 微调后分数) / 微调前分数 × 100%
```

实操要点：

1. **选定一个基准集合**，覆盖你想保住的每个能力维度。通用选择如 MMLU（知识）、C-Eval（中文知识）、GSM8K（数学推理）、HellaSwag（常识推理）、以及一个自建的中文指令遵循小集；
2. **用同一套评测代码、同一套提示词、同一解码参数**跑微调前后的模型。评测配置不一致导致的「遗忘」比真实遗忘还多；
3. **优先看相对下降，而不是绝对值**。不同基准的绝对分差很大，只有相对下降率可横向比较；
4. **单样本对比比总分更有诊断价值**：微调前对、微调后错的样本（regression set）必须逐条看，它们通常比总分揭示更多问题；
5. **成本优化**：全量跑基准很贵，工程上常用 200~500 条的分层抽样子集做「遗忘哨兵集」，只有哨兵报警时才跑全量。

**基准集合怎么搭配**（一个可直接抄的组合）：

| 能力维度 | 建议基准 | 规模 | 为什么选它 |
|---|---|---|---|
| 百科知识 | MMLU / C-Eval | 各 200 题抽样 | 最容易被领域微调破坏的维度 |
| 数学推理 | GSM8K | 100~200 题 | 对参数漂移极敏感，是很好的「矿井里的金丝雀」 |
| 常识推理 | HellaSwag / 自建 | 200 题 | 检测语言建模能力是否退化 |
| 指令遵循 | 自建 50~100 条 | —— | 检测格式指令、拒答、长度约束是否还遵守 |
| 目标语言能力 | 自建中文写作/改写任务 | 50 条 | 检测中英夹杂、句式僵化 |

经验阈值（仅供参考）：

| 相对下降 | 判读 | 建议动作 |
|---|---|---|
| < 2% | 正常波动 | 通过，继续观察 |
| 2% ~ 5% | 轻度遗忘 | 记录；检查数据配比与学习率 |
| 5% ~ 15% | 中度遗忘 | 引入回放数据或降低 LoRA 秩/学习率后重跑 |
| > 15% | 严重遗忘 | 停止上线；重做数据混合，或改用更保守的微调策略 |

**一个常被忽略的细节：评测的方差**。生成式基准在 temperature > 0 时的单次运行方差可达 1~3 个点，直接比较两次运行的分数会得出错误结论。做法是固定 temperature=0（贪心解码），或者跑 3 次取均值并报告标准差。

### 1.7 过拟合的识别信号

过拟合是遗忘的「近亲」，但它的信号更早、更便宜就能发现：

| 信号 | 具体表现 | 采集方式 |
|---|---|---|
| 泛化 gap | 验证 loss 开始上升而训练 loss 继续下降 | 训练日志按步记录两条曲线 |
| 指标回落 | 验证指标在某个 epoch 达到峰值后持续下降 | 记录 best_epoch 与 best 之后的步数 |
| 复述训练样本 | 输出中直接出现训练集的长片段 | n-gram 重合率统计（如 13-gram） |
| 对措辞过度敏感 | 同义改写的提问，模型就答不对了 | 扰动集测试（换词、换语序、加错别字） |
| 输出长度坍缩 | 回答长度分布明显变窄 | 统计输出 token 数的分布 |

**早停的正确姿势**：不要用「最后一个 epoch 的模型」，而是记录验证指标最好时的 checkpoint。如果 best_epoch 明显早于训练结束（例如 10 个 epoch 里最好的是第 3 个），说明后面的训练只是在过拟合，应当直接缩短训练轮数。

## 2. 缓解手段对比

五类主流手段，各自的代价与适用场景如下：

| 手段 | 原理 | 可训练参数 | 遗忘抑制强度 | 代价 | 适用场景 |
|---|---|---|---|---|---|
| **LoRA / 低秩更新** | 冻结主干，只在旁路注入低秩矩阵 `BA`，把参数更新限制在低秩子空间 | 0.1% ~ 3% | 中（秩越小越保守） | 秩/α 需要调参；推理需合并或额外延迟 | 大多数领域微调，默认首选 |
| **回放（replay）** | 训练时混入一部分通用/旧任务数据，让旧分布持续参与梯度 | 视主干而定 | 强 | 需要准备并维护通用数据；占用训练预算 | 领域数据高度同质、遗忘明显时 |
| **正则约束（KL / L2-SP）** | 在损失里加惩罚项，限制新参数偏离旧参数或旧输出分布 | 视主干而定 | 中 | 需要权重系数调参；KL 需要旧模型前向 | 有旧模型权重、追求平滑过渡 |
| **数据混合比例** | 用任务数据 : 通用指令数据的配比控制分布偏移 | 视主干而定 | 中到强 | 配比本身就是超参，需要扫 | 通用指令微调、指令数据很窄时 |
| **只训部分层** | 只解冻后几层 / 只训 embedding / 只训 attention 的 Q、V | 数个百分点 | 中 | 可能不够拟合新任务 | 任务与预训练接近、数据量小 |

**按「投入产出比」排序的实际选择**：

```
数据回放  >  降低 LoRA 秩 / 学习率  >  只训部分层  >  KL 正则  >  L2-SP
（最根本）      （最省事）            （结构手段）    （需旧模型前向） （最便宜但最弱）
```

几点工程判断：

- **KL 正则**的核心是把「微调前的模型输出分布」当作锚点，在同一批输入上约束新模型不要偏离太远：

  ```python
  loss = ce_loss + beta * kl_div(new_logits, old_logits.detach())
  ```

  `beta` 典型从 0.1 起扫；太大则目标任务学不动，太小则等于没加。缺点是每次前向都要跑一遍旧模型（可以用小号旧模型或缓存 logits 降低成本）。

- **L2-SP** 的做法是惩罚「新参数与预训练参数之差的 L2 范数」：

  ```python
  loss = ce_loss + lam * sum(((p - p0) ** 2).sum() for p, p0 in zip(model.parameters(), pretrained_params))
  ```

  它比 KL 便宜（不需要旧模型前向），但约束的是参数空间而非函数空间，效果一般弱于 KL。

- **回放的数据配比**是最有效也最容易被忽略的手段。常见起点是「任务数据 : 通用指令数据 = 1 : 1 到 4 : 1」，在同质化严重的领域数据上可以放宽到 1 : 2。回放数据的来源可以是公开指令集、业务侧的历史通用对话，或用基座模型对通用 prompt 自我生成（需过滤质量）。

- **LoRA 的秩 r 本身就是一个遗忘旋钮**：r 越小，可表达的参数更新空间越小，对新任务拟合能力越弱、对旧能力破坏也越小。这和「调 r 提升效果」是同一枚硬币的两面。

> **说明**：KL 正则、L2-SP、replay 的机制和配比经验基于公开资料与通用工程实践整理。

## 3. 怎么设计微调对比实验

### 3.1 实验设计模板

| 项 | 要求 |
|---|---|
| 固定变量 | 基座模型版本、tokenizer、最大序列长度、评测代码、解码参数（temperature/top_p/max_new_tokens）、评测集划分 |
| 自变量 | 每组只改一个：是否微调、微调方法、LoRA 的 r/α、数据配比、学习率 |
| 因变量 | 四维指标 + 训练成本（GPU 小时、峰值显存）+ 推理成本（延迟、显存） |
| 重复次数 | ≥ 3 个随机种子，报告均值 ± 标准差 |
| 显著性 | 对分类任务用配对检验；对生成任务用 bootstrap 置信区间 |
| 记录 | 数据版本哈希、代码 commit、随机种子、超参全量 |

### 3.2 最容易做错的五件事

1. **基线太弱**（见 1.3）。这是最常见的问题，直接导致「微调收益被高估」。
2. **测试集泄漏到训练集**。尤其是领域内自建测试集，往往和训练集同源。切分必须按外部键分组（按用户、按商品、按时间）。
3. **只报最好的一次**。既然要跑多个种子，就要防止挑种子（seed fishing）。所有种子的结果都要报，包括难看的。
4. **忽略推理成本**。LoRA 合并后无额外延迟，但如果不合并、或用了 Adapter 结构，推理会变慢。这个成本必须进报告。
5. **不做消融**。「数据 + 方法 + 超参」一起改，最后不知道是哪个起作用了。至少要做「只改数据」「只改方法」两组消融。

### 3.3 评估脚本骨架

下面这份脚本骨架覆盖：任务指标、格式合规率、通用能力保持（遗忘度量）、过拟合检查四件事。

```python
# -*- coding: utf-8 -*-
"""微调评估脚本骨架：任务指标 + 格式合规率 + 遗忘度量 + 过拟合检查。

依赖：标准库；可选 scikit-learn（分类指标）、torch/transformers（真实推理）。
本脚本用可注入的 predict_fn 解耦模型，便于在无 GPU 环境下做逻辑自测。
"""
import json
import math
import re
from collections import Counter
from typing import Callable, Dict, List, Optional

# ---------------------------------------------------------------- 指标工具


def accuracy(preds: List[str], golds: List[str]) -> float:
    assert len(preds) == len(golds) and preds, "预测与标签长度必须一致且非空"
    return sum(p == g for p, g in zip(preds, golds)) / len(golds)


def macro_f1(preds: List[str], golds: List[str]) -> float:
    """不依赖 sklearn 的宏平均 F1，便于在最小环境里跑。"""
    labels = sorted(set(golds) | set(preds))
    f1s = []
    for lb in labels:
        tp = sum(p == lb and g == lb for p, g in zip(preds, golds))
        fp = sum(p == lb and g != lb for p, g in zip(preds, golds))
        fn = sum(p != lb and g == lb for p, g in zip(preds, golds))
        precision = tp / (tp + fp) if tp + fp else 0.0
        recall = tp / (tp + fn) if tp + fn else 0.0
        f1s.append(0.0 if precision + recall == 0
                   else 2 * precision * recall / (precision + recall))
    return sum(f1s) / len(f1s) if f1s else 0.0


def bleu_like(pred: str, gold: str, n: int = 2) -> float:
    """简化的 n-gram 精确率，用于生成任务的快速对比（不要当作 BLEU 汇报）。"""
    def grams(s, k):
        t = re.sub(r"\s+", "", s)
        return Counter(t[i:i + k] for i in range(max(len(t) - k + 1, 0)))
    pred_g, gold_g = grams(pred, n), grams(gold, n)
    if not pred_g or not gold_g:
        return 0.0
    overlap = sum((pred_g & gold_g).values())
    return overlap / max(sum(pred_g.values()), 1)


# ---------------------------------------------------------------- 格式合规


def json_compliance(outputs: List[str], required_keys: Optional[List[str]] = None) -> Dict:
    """统计 JSON 可解析率与必填字段齐全率，并返回失败样本下标。"""
    required_keys = required_keys or []
    ok, bad = 0, []
    for i, o in enumerate(outputs):
        try:
            obj = json.loads(o)
        except (json.JSONDecodeError, TypeError):
            bad.append(i)
            continue
        if required_keys and not all(k in obj for k in required_keys):
            bad.append(i)
            continue
        ok += 1
    return {
        "json_parse_rate": ok / len(outputs) if outputs else 0.0,
        "failed_indices": bad,
        "n_failed": len(bad),
    }


# ---------------------------------------------------------------- 遗忘度量


def forgetting_report(before: Dict[str, float], after: Dict[str, float]) -> Dict:
    """通用基准回测：给出每个基准的相对下降率与总体遗忘度量。

    before / after: {"mmlu": 0.612, "gsm8k": 0.341, ...}
    """
    assert before.keys() == after.keys(), "两次评测必须使用同一组基准"
    per_bench, drops = {}, []
    for name, b in before.items():
        a = after[name]
        if b == 0:
            per_bench[name] = {"before": b, "after": a, "relative_drop": None}
            continue
        rel = (b - a) / b
        per_bench[name] = {"before": b, "after": a, "relative_drop": round(rel, 4)}
        drops.append(rel)
    return {
        "per_benchmark": per_bench,
        "mean_relative_drop": round(sum(drops) / len(drops), 4) if drops else None,
        "max_relative_drop": round(max(drops), 4) if drops else None,
    }


def retention_score(before: Dict[str, float], after: Dict[str, float]) -> float:
    """综合保持率：几何平均，避免某一项崩掉被平均数掩盖。"""
    ratios = [max(a, 1e-6) / max(b, 1e-6) for b, a in zip(before.values(), after.values())]
    return math.exp(sum(math.log(r) for r in ratios) / len(ratios))


# ---------------------------------------------------------------- 过拟合检查


def overfit_signals(train_loss: List[float], eval_loss: List[float],
                    eval_metric: List[float]) -> Dict:
    """从训练曲线里提取过拟合信号（按 epoch 或固定步长采样）。"""
    assert len(train_loss) == len(eval_loss) == len(eval_metric), "三条曲线长度必须一致"
    best_epoch = max(range(len(eval_metric)), key=lambda i: eval_metric[i])
    gap = [e - t for t, e in zip(train_loss, eval_loss)]
    return {
        "best_epoch": best_epoch,
        "epochs_after_best": len(eval_metric) - 1 - best_epoch,
        "final_gap": round(gap[-1], 4),
        "min_gap": round(min(gap), 4),
        "eval_degraded": eval_metric[-1] < eval_metric[best_epoch],
        "verdict": ("疑似过拟合：验证指标在达到峰值后回落（下降 %.4f）"
                    % (eval_metric[best_epoch] - eval_metric[-1]))
        if eval_metric[-1] < eval_metric[best_epoch] * 0.995 else "未见明显过拟合",
    }


def verbatim_rate(outputs: List[str], train_texts: List[str], n: int = 13) -> float:
    """复述率：输出中是否存在与任一训练样本共享长度 n 的 n-gram。"""
    train_grams = set()
    for t in train_texts:
        t = re.sub(r"\s+", "", t)
        train_grams.update(t[i:i + n] for i in range(max(len(t) - n + 1, 0)))
    if not train_grams:
        return 0.0
    hit = 0
    for o in outputs:
        o = re.sub(r"\s+", "", o)
        if any(o[i:i + n] in train_grams for i in range(max(len(o) - n + 1, 0))):
            hit += 1
    return hit / len(outputs) if outputs else 0.0


# ---------------------------------------------------------------- 统一入口

def evaluate_all(predict_fn: Callable[[List[str]], List[str]],
                 task: Dict,
                 general_before: Optional[Dict[str, float]] = None,
                 general_after: Optional[Dict[str, float]] = None,
                 train_texts: Optional[List[str]] = None,
                 required_keys: Optional[List[str]] = None) -> Dict:
    """task: {"inputs": [...], "golds": [...], "kind": "classification" | "generation"}"""
    outputs = predict_fn(task["inputs"])
    report = {"n_samples": len(outputs)}

    if task["kind"] == "classification":
        report["task"] = {"accuracy": round(accuracy(outputs, task["golds"]), 4),
                          "macro_f1": round(macro_f1(outputs, task["golds"]), 4)}
    else:
        scores = [bleu_like(o, g) for o, g in zip(outputs, task["golds"])]
        report["task"] = {"overlap": round(sum(scores) / len(scores), 4)}

    report["format"] = json_compliance(outputs, required_keys)

    if general_before and general_after:
        report["forgetting"] = forgetting_report(general_before, general_after)
        report["retention"] = round(retention_score(general_before, general_after), 4)

    if train_texts:
        report["verbatim_rate"] = round(verbatim_rate(outputs, train_texts), 4)

    return report


if __name__ == "__main__":
    demo_task = {"inputs": ["a", "b", "c"],
                 "golds": ["x", "y", "x"],
                 "kind": "classification"}
    user_reply = {"a": '{"label": "x"}', "b": "y", "c": "不是 JSON"}

    def fake_predict_fn(inputs):
        return [user_reply[i] for i in inputs]

    print(json.dumps(evaluate_all(fake_predict_fn, demo_task,
                                  required_keys=["label"]),
                     ensure_ascii=False, indent=2))
```

> **说明**：`retention_score` 用几何平均是为了避免「某一项崩溃被其他项的提升掩盖」；`verbatim_rate` 用长度 13 的 n-gram 是为了降低偶然重合率（长文本可放宽到 20）。以上实现基于通用工程实践整理，未在本机实测运行（本机无 GPU / `transformers`）。

## 4. 常见坑表

| 坑 | 表现 | 定位方法 | 修复 |
|---|---|---|---|
| 只报目标指标 | 目标 F1 上涨，上线后通用问答明显变笨 | 补做通用基准回测 | 把「保持率」写进验收标准，与 F1 并列 |
| 验证集泄漏 | 训练 loss 与验证指标同步上涨，线上暴跌 | 文本指纹交集检查 + 按 item_id/user_id/时间分组切分 | 按外部键分组切分；评测集来自独立采集批次 |
| 用训练 loss 判断效果 | loss 降到 0.01 就认为模型很好 | 训练/验证 loss 曲线并排看 | 以验证集指标为唯一选模型依据；训练 loss 只用于诊断是否收敛 |
| 忽略格式失败率 | JSON 解析失败率 20%，F1 看起来还很漂亮 | 用解析器批量跑并统计失败率 | 格式合规率设绝对下限（如 ≥99%）；把格式失败样本单独归因 |
| 基线是裸模型 | 微调收益被高估 20+ 个百分点 | 重跑「未微调 + 好提示词 + few-shot」 | 四行对比实验（见 1.3），并跑多随机种子 |
| 挑随机种子 | 只汇报最好一次；换研究者复现不出来 | 记录全部种子结果并报告均值 ± 标准差 | 实验从一开始就固定种子列表，禁止事后筛选 |
| 评测配置不一致 | 微调前后的分数差异其实是解码参数不同造成的 | 对比评测脚本、提示词、max_new_tokens、temperature | 评测代码纳入版本控制，两次评测用同一份配置 |
| 遗忘被「平均分掩盖」 | 总分只掉 3%，但数学推理掉了 30% | 用几何平均保持率，并逐基准查看 | 对关键能力设定单项下限，而非只看总分 |
| 拿训练集测「是否学会」 | 训练集准确率 1.0，误以为任务解决了 | 只看留出集 | 训练集指标仅用于过拟合诊断 |
| 复述训练数据未被发现 | 上线后被用户发现「背答案」 | 统计 `verbatim_rate`（n-gram 重合） | 增加改写比例、降低 epoch、提高数据多样性 |

## 5. 自测

<details markdown="1">
<summary markdown="1">参考答案</summary>

**Q1. 为什么基线必须是「未微调 + 好提示词 + few-shot」，而不是未微调的裸模型？**

因为决策要回答的是「微调相对于最便宜的可用方案收益多少」。提示词工程成本近乎为零，如果它能拿到 0.70 而微调只做到 0.72，那么这 0.02 的收益要换来数据标注、GPU 训练和维护一套训练流水线的成本，结论很可能是「不值得做」。用裸模型作基线会把这个差距夸大成 0.45 → 0.72，从而做出错误的投入决策。补充一句：这不只是学术严谨性问题，它是工程上最常见的返工原因。

**Q2. 灾难性遗忘的度量为什么优先看相对下降率而不是绝对分？**

因为不同基准的绝对分差距很大（例如常识推理可能 0.85，数学推理可能 0.30），绝对下降 1 分在一个基准上是 1.2% 的退化，在另一个基准上是 3.3%。只有换算成相对下降率，才能横向比较、才能设一个统一的阈值（如 >5% 报警）。此外，绝对分还受评测实现细节影响（提示词、few-shot 数量、解码参数），相对下降做差分可以消掉一部分系统性偏差。

**Q3. LoRA 的秩 r 和遗忘程度之间是什么关系？**

r 决定了 `BA` 这个低秩更新能表达多大的参数变化空间。r 越小，可表达的变化越受限，模型越难彻底偏离预训练权重，因而对旧能力的破坏更小；r 越大，拟合新任务的能力越强，遗忘风险也越高。所以「调大 r 提升效果」和「调小 r 抑制遗忘」是同一个旋钮的两端，正确做法是在任务指标与保持率之间找平衡点，而不是无脑取大。

**Q4. 格式合规率为什么必须单列，它不能并入任务指标吗？**

不能。任务指标衡量的是「答案对不对」，格式合规率衡量的是「答案能不能被程序消费」。这两件事的失败模式和对业务的影响完全不同：F1 低意味着模型判断力不够，需要更多数据或更好的方法；JSON 解析失败意味着下游系统会报错或走兜底逻辑，是可用性问题，通常用格式约束训练数据、收紧生成参数、加输出校验与重试就能解决。把两者混在一个指标里，就丧失了归因能力。

**Q5. 除了通用基准回测，还有哪些低成本的遗忘检测手段？**

三种：① **regression set**：把微调前答对、微调后答错的样本挑出来逐条看，这比总分更有诊断价值；② **扰动测试**：给同一问题换措辞、换语序、加错别字，看性能下降幅度是否比微调前更大（鲁棒性退化往往先于能力退化出现）；③ **输出风格统计**：平均输出长度、重复率、中英夹杂比例的分布漂移，能捕捉到语言能力退化的早期信号。

**Q6. KL 正则和 L2-SP 有什么本质区别？**

KL 正则约束的是**函数空间**：让新模型在同一批输入上的输出概率分布不偏离旧模型太远，它需要旧模型的前向计算（或缓存的 logits），代价高但更贴近「能力保持」这个目标。L2-SP 约束的是**参数空间**：惩罚新参数与预训练参数之差的范数，实现简单、无需旧模型，但参数接近并不保证函数接近——尤其在低秩微调或只训部分层时，参数空间的约束会失效。
