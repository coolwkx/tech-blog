## 本章要回答的问题

**5.1 为什么 Agent 评测比 LLM 评测难**
- 从「单次输出 vs 多步轨迹」「静态对错 vs 过程与结果」「确定性 vs 环境不确定性」三个维度讲清 LLM 评测与 Agent 评测的差异。
- 用结果层 / 过程层 / 系统层三层框架拆解任意一个 Agent 评测需求，并指出只看结果层的具体风险。
- 识别数据污染、判题器偏差、reward hacking 三类评测失效，并说明各自的检测手段。

**5.2 评测指标设计**
- 为一个 Agent 项目设计出覆盖结果、过程、系统、安全四类的指标组，并说明每一类为什么必须存在。
- 正确计算任务成功率、部分完成度、工具调用准确率、P95 延迟与每次成功成本，并指出各自的口径陷阱。
- 从「任务成功率下降」出发，沿着归因链定位到具体环节（模型 / 工具 / 环境 / 超时）。

**5.3 评测方法-单元测试与 LLM 即裁判**
- 把一项 Agent 能力拆成「输入与环境 + 允许工具 + 终态/序列/产物断言」的可执行用例，并写成一个可复用的评测 harness。
- 设计一份带行为锚点的评分 rubric，识别并缓解 Judge 的位置偏差、长度偏差与自我偏好偏差。
- 用 Cohen's Kappa 验证 Judge 与人工的一致性，用 McNemar 精确检验与配对 Bootstrap 判断 A/B 差异是否显著。

**5.4 评测基准全景**
- 说出主流 Agent 基准各自考察什么能力、任务形态、评测方式与已知局限，并判断哪一个与自己的项目对齐。
- 从环境层、工具层、预算层、判题层四个维度诊断「为什么榜单分数不能代表生产可用性」。
- 按分层抽样与契约冻结的规范，为自己的项目建一套可维护的评测集。

**5.5 RAG 与多轮对话评测**
- 用四要素框架（上下文相关性 / 忠实度 / 答案相关性 / 上下文召回率）拆解一个 RAG 系统的评测需求。
- 手算 Recall@k、Precision@k、Hit Rate@k、MRR 与 nDCG@k，并说明 Recall@k 与 MRR 为什么必须一起看。
- 用整轨判分评测多轮对话的指代消解、上下文一致性与任务完成度，并把 RAG 指标接进 Agent 轨迹。
