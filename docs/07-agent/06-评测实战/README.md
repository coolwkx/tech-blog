## 本章要回答的问题

**6.1 项目复盘-AgentEvalLab**
- 画出这条工具链的六段流水线，并说明每一段拒绝了什么样的错误输入。
- 用「方案 / 优点 / 代价 / 为何这样选」四列表复述该项目的核心设计取舍，并判断哪些取舍适合搬进自己的项目。
- 说清一个评测工具的能力边界——它能证明什么、不能证明什么，以及为什么「不接 LLM-as-a-Judge」本身就是一个设计决策。

**6.2 用 Manifest 保证评测可复现**
- 列出导致评测不可复现的 8 类漂移来源，并说明每一类在 Manifest 里对应哪个字段。
- 独立设计一份 Manifest，并用可运行代码算出提示词哈希与数据集哈希（含规范化规则的取舍）。
- 用 `taskId + repeatId + seed` 做幂等键，把评测产物写成可断点续跑、可去重、可严格配对的形状。

**6.3 失败归因与显著性检验实战**
- 用自己的话说清九种 `violation` 的判定逻辑，并解释为什么违规的**追加顺序**就是归因优先级。
- 构造 2×2 配对表、手算并用代码验证 McNemar exact p-value，判断"62% → 71%"这类提升是否显著。
- 实现以 `taskId` 聚类的 Bootstrap 置信区间，并演示"重采样单位选错会得出相反上线结论"。

**6.4 给一个真实 Agent 补评测**
- 画出一个多源抓价 + 状态机 + 推送 + 落盘 + 看板的 Agent 链路，并列出每一段的失效面。
- 写出 15 条带「期望产物 / 断言 / 证据要求」的评测用例，并解释为什么每条断言都必须有证据支撑。
- 用一份可直接运行的评测脚本跑出基线报告、定位失败类型，并把回归门槛接进 CI。
