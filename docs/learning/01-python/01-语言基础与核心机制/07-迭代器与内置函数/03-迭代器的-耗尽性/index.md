# 迭代器的"耗尽性"

> **学习目标**：能够解释「迭代器的"耗尽性"」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：序列与字典（01 篇）、函数作为参数与 lambda（02 篇）、`yield` 生成器（06 篇）。
>
> **所属主题**：迭代器与内置函数 · 核心概念

## 本次只学这一点

迭代器持有**游标状态**：
```python
gen = (x for x in range(3))
print(sum(gen), sum(gen)) # 3 0 ← 第二次已经耗尽
```
| 写法 | 能否重复遍历 | 原因 |
| --- | --- | --- |
| `for` 遍历 list / dict / str | ✅ | 每次 `iter` 返回一个**新的**迭代器 |
| `for` 遍历生成器 / map / zip / filter | ❌ | 它们本身就是迭代器，返回 `self` |
| 自定义类 `__iter__` 返回 `self` | ❌ | 游标是对象自己的状态 |
| 自定义类 `__iter__` 里 `yield` | ✅ | 每次调用都产生一个**新的**生成器 |

**设计建议**：想让自己写的类可以反复遍历，应该把"可迭代对象"和"迭代器"分开 —— 可迭代对象的 `__iter__` 每次都返回一个**新的**迭代器（或直接用 `yield` 写成生成器方法）；想表达"一次性数据流"（如读文件、读 socket），才让 `__iter__` 返回 `self`。
