# GIL：它到底是什么

## 本次只学这一点

**GIL（Global Interpreter Lock，全局解释器锁）** 是 CPython 解释器里的一把互斥锁，保证**同一时刻只有一个线程在执行 Python 字节码**。

| 问题 | 答案 |
| --- | --- |
| GIL 保护什么？ | 解释器内部状态（引用计数、对象分配等），让实现变简单 |
| 多线程能并行算 CPU 吗？ | ❌ 不能。4 个 CPU 密集线程 ≈ 1 个线程的总算力 |
| 那多线程有什么用？ | ✅ I/O 等待时 GIL 会被**释放**（如 `time.sleep`、`socket.recv`、文件读写），其他线程可以跑 |
| 多进程受 GIL 影响吗？ | ❌ 不受，每个进程有自己的解释器和 GIL |
| GIL 会被移除吗？ | CPython 3.13 起提供实验性的 free-threaded 构建（PEP 703），但生态与性能仍在演进，现阶段主流仍是带 GIL 的 CPython |

**GIL 不等于"线程安全"**：GIL 只在"字节码之间"切换，一条语句可能对应多条字节码，切换可能发生在中间。所以"看起来原子"的 `x += 1`（`LOAD` → `ADD` → `STORE`）依然可能被中途打断 —— 这就是竞态条件的根源。
