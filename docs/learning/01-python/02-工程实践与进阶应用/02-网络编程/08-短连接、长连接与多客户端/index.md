# 短连接、长连接与多客户端

> **学习目标**：能够解释「短连接、长连接与多客户端」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：函数与异常（02、04 篇）、`with` 与文件读写（04 篇）、多线程（08 篇，用于多客户端）。
>
> **所属主题**：网络编程 · 核心概念

## 本次只学这一点

| 模式 | 说明 | 适用 |
| --- | --- | --- |
| 短连接 | 一次请求-响应后就关闭 socket | HTTP/1.0、简单查询 |
| 长连接 | 一个连接上多次交互，自行决定何时关闭 | 数据库连接、聊天、推送 |

**多客户端**：`accept` 循环一次只能服务一个客户端，且处理期间无法接受新连接。解决方案：

| 方案 | 说明 |
| --- | --- |
| 多线程（`threading.Thread`） | 每个 `conn` 起一个线程处理，简单直接（做法） |
| 多进程（`multiprocessing`） | 隔离性好，开销大 |
| `socketserver` / `asyncio` | 标准库封装好的服务端框架 |

**判断客户端下线**：`conn.recv` 返回 `b''`（长度为 0）就说明对端调用了 `close`。这是明确点出的注意点，也是写"在线用户列表"的基础。
