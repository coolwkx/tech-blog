# 顺序表 vs 链表

> **学习目标**：能够解释「顺序表 vs 链表」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：列表与字典的复杂度直觉（01 篇）、函数与递归（02 篇）、类与对象（03 篇）。
>
> **所属主题**：数据结构与算法基础 · 核心概念

## 本次只学这一点

| 维度 | 顺序表（数组 / list） | 链表 |
| --- | --- | --- |
| 存储空间 | **连续** | **非连续**，靠链接串起存储块 |
| 随机访问 | `O(1)`（首地址 + 下标偏移） | `O(n)`（必须从头遍历） |
| 头部插入/删除 | `O(n)`（后续元素整体搬家） | `O(1)`（改指针） |
| 尾部插入 | 平摊 `O(1)` | 单链表 `O(n)`（要走到尾） |
| 扩容 | 需连续空间，可能整体搬迁 | 无需扩容，按需申请结点 |
| 额外开销 / 缓存 | 无额外指针；内存连续、缓存友好 | 每结点多指针域；内存跳跃、缓存不友好 |

**顺序表的两种存储方式**：

| 方式 | 结构 | 扩容 |
| --- | --- | --- |
| 一体式 | 信息区 + 数据区**连续**存放 | 只能**整体搬迁** |
| 分离式 | 信息区存"容量 + 数据区地址"，数据区另行分配 | 只更换数据区，**更新链接即可** |

**扩容策略**：每次增加固定数目（如 +10）→ 省空间但扩充频繁、次数多；每次**容量加倍** → 扩充次数少、平摊 `O(1)`，但可能浪费空间（**推荐**，空间换时间）。Python 的 `list` 正是"分离式 + 容量倍增（约 1.125 倍）"，所以 `append` 平摊 `O(1)`，而 `insert(0, x)` 是 `O(n)`。

**顺序表增删元素的复杂度**：尾端增删 `O(1)`；非保序增删（把末尾元素挪到被删位置）`O(1)`；保序增删（中间插入/删除，后续元素整体移动）`O(n)`。
