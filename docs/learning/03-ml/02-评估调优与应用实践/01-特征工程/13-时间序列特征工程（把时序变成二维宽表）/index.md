## 本次只学这一点

这是 [10-数据挖掘案例-电力负荷预测](../../../../../03-ml/06-案例与面试/10-数据挖掘案例-电力负荷预测.md) 的核心工作。原始数据只有 `time` 和 `power_load` 两列，需要展开成宽表：

| 特征类别 | 具体特征 | 构造方法 |
| --- | --- | --- |
| **时间特征（短期）** | `hour` 的 24 个 one-hot 列 | `df['time'].str[11:13]` + `pd.get_dummies` |
| **时间特征（长期）** | `month` 的 12 个 one-hot 列 | `df['time'].str[5:7]` + `pd.get_dummies` |
| **滑窗历史负荷** | 前 1 / 前 2 / 前 3 小时负荷 | `df['power_load'].shift(i)` |
| **同期历史** | 昨日同时刻负荷 | 时间字典 + `pd.to_timedelta('1d')` |
| **外部特征（扩展）** | 温度、湿度、风速、历史工业/居民用电量 | 需要外部数据源 |

**工程要点**：

| 要点 | 说明 |
| --- | --- |
| 时间格式化统一 | `pd.to_datetime(x).dt.strftime('%Y-%m-%d %H:%M:%S')`，字符串切片才不会错位 |
| 排序与去重 | `sort_values('time')` + `drop_duplicates`，保证 `shift` 语义正确 |
| 空值处理 | `shift` 与"昨日同时刻"会引入 NaN，需 `dropna(axis=0)` |
| 训练/预测特征列必须一致 | 预测时要"手工解析"出与训练时**完全相同的列名与列序** |
| 离散时间特征用 one-hot 而非序号 | 小时 23 和 0 在序号上差 23，但实际相邻；one-hot 避免引入虚假距离 |
| 禁止未来信息泄漏 | 构造滑窗时只能用**当前时刻之前**的负荷 |
