# 设计决策：为什么 Tensor 与 Function 分离

> **学习目标**：能够解释「设计决策：为什么 Tensor 与 Function 分离」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：偏导数与梯度、单变量链式法则、矩阵乘法与转置、Python 闭包与递归。
>
> **所属主题**：反向传播与计算图 · 核心思想

## 本次只学这一点

框架里 `Tensor`（数据、梯度、图指针）与 `Function`/`Node`（算子与局部反向规则）是两类对象。

| 好处 | 说明 |
| --- | --- |
| 算子可复用 | 一个 `mm` 的反向规则对所有形状/dtype 通用，不必为每张图重新生成代码 |
| 缓存可托管 | 只有 Function 知道反向需要哪个输入或输出，所以 saved tensors 由它负责 |
| 图可及时释放 | 反向走完，Function 节点连同缓存一起回收，不必等整张图的生命周期结束 |
| 易扩展与优化 | 新增算子 = 一个 `forward` + 一个 `backward`；图是显式的，才能做融合、重计算、并行调度 |

一句话：**Tensor 管「是什么值」，Function 管「值怎么来的、反向怎么算」，引擎管「按什么顺序调度」。**
