# BPE 完整算法

> **学习目标**：能够解释「BPE 完整算法」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：Python 字符串与 `re` 模块；正则表达式；神经网络需要整数 id（embedding 查表）；Transformer 的 `attention_mask` 概念。
>
> **所属主题**：文本预处理与分词全流程 · 深入机制

## 本次只学这一点

BPE 原本是 1994 年的**数据压缩**算法（Gage），Sennrich 等人 2016 年把它搬到 NMT 上做子词切分。

**训练**：预分词、统计词频，每个词表示成字符序列 + 词尾标记 → 统计所有相邻符号对频次 → 取最高频的一对合并成新符号，并把 `(a, b)` 追加到 merges → 回到统计，重复 `k` 次。**编码**：把新词拆成字符，**按 merges 的顺序**逐条套用合并规则。复杂度上，朴素实现每轮合并后重扫全部语料为 O(k · N)；`tokenizers` 用优先队列 + 并查集把每轮降到接近 O(N log N)，并支持并行。

工程要点：**`k` 决定词表大小**（`vocab_size = 初始符号数 + k`，GPT-2 是 50257，BERT 是 30522，Llama-3 是 128256）；**byte-level BPE** 把文本先切成 UTF-8 字节、初始符号固定为 256 个字节，因此永远不会 OOV，emoji 与罕见汉字都能用字节表示，代价是中文一个汉字可能占 2~3 个 token；**预分词很关键**，GPT-2 用正则把 `'s`、`'t` 等缩写单独切块，避免 BPE 跨词合并出短语级符号；**推理切分不唯一**，训练出的 merges 只给出一种确定切分，这正是 Unigram 想解决的问题。
