# 技术路线的分水岭：交互式 vs 表示式

> **学习目标**：能够解释「技术路线的分水岭：交互式 vs 表示式」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：第 03 篇的 TF-IDF 与余弦相似度、第 04 篇的词向量、第 08 篇的 attention、第 09 篇的 BERT 与句对任务。
>
> **所属主题**：文本相似度与语义匹配 · 核心概念

## 本次只学这一点

这是本主题最重要的一个概念，面试几乎必问：

| 对比项 | 交互式 / 交叉编码器（Cross-Encoder） | 表示式 / 双塔（Bi-Encoder / Dual-Encoder） |
|--------|-------------------------------------|-------------------------------------------|
| 输入 | `[CLS] 句子A [SEP] 句子B [SEP]` 一起送入 | A、B **分别**送入同一个（或两个）编码器 |
| 交互发生位置 | 从第一层开始两段就在 self-attention 里互相看 | 只有最后算相似度时才有交互 |
| 输出 | 相关性分数（分类/回归） | 两个向量，相似度后算 |
| 效果 | **高**（能建模细粒度交互，如否定、指代、词序） | 较低（两段文本无法互相消歧） |
| 速度 | 慢：每对都要完整前向一次，$N$ 个候选要算 $N$ 次 | 快：文档向量可**离线预计算**，query 只需算 1 次 |
| 可索引 | 不能（每对都要现算） | 可以（建向量索引做 ANN 检索） |
| 典型用途 | 精排（rerank）、小规模高质量判定 | 召回（retrieval）、大规模去重、聚类 |

工业界的标准架构是**两阶段**：

```
query ──► 双塔召回（从百万候选中取 Top-100，毫秒级）
 │
 └──► Cross-Encoder 精排（对 100 个候选精算分数，几十毫秒）
 │
 └──► Top-10 返回
```

只在召回阶段用 Cross-Encoder 是不可行的——百万候选要跑百万次 BERT，延迟无法接受。只在精排用双塔也不够准——语义匹配的瓶颈往往在精排。
