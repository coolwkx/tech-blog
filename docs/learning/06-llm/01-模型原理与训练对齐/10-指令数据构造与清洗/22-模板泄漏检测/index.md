# 模板泄漏检测

> **学习目标**：能够解释「模板泄漏检测」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：BERT/MLM 预训练目标、Tokenizer 与词表（vocab）、`[MASK]` token 与 MLM Head、交叉熵损失、基本的分类任务指标（acc / P / R / F1）。
>
> **所属主题**：-指令数据构造与清洗 · 数据清洗清单

## 本次只学这一点

这是 PET 场景最**致命**的一类事故：模板字符串出现在验证集/测试集里，导致指标虚高，线上暴跌。检测手段是「用从 `prompt.txt` 解析出的字面量片段（去掉插槽）去同时匹配训练集与评测集，两边都命中即视为泄漏」，实现见 5.7 的 `find_template_leak`。

更隐蔽的变体是**「同一用户/同一商品的评论同时出现在训练集与验证集」**。这类泄漏不会体现在文本相似度上，必须靠外部键（user_id / item_id / 时间戳）做分组切分：

```
错误做法：random_split(all_data)          → 同一商品的相似评论两边都有 → 指标虚高
正确做法：GroupShuffleSplit(groups=item_id) 或 按时间切分（用过去预测未来）
```

**模板泄漏与样本泄漏的区别**：模板泄漏是「模板字符串本身被写进了数据文件」——比如有人图省事，把已经拼好的 `这是一条[MASK]评论：...` 连同模板一起写进 `train.txt`，验证集文本也就带上了模板字面量；检测靠文本片段匹配。样本泄漏是「同源数据同时出现在两侧」；检测靠外部键分组切分。前者更直白、后者更隐蔽，但两者都会让指标虚高。
