# 度量方式

> **学习目标**：能够解释「度量方式」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：监督微调（SFT）的基本流程、LoRA 等参数高效微调方法、分类与生成的常用指标（acc / P / R / F1 / ROUGE / 通过率）、训练集-验证集切分与交叉验证。
>
> **所属主题**：-微调效果评估与灾难性遗忘 · 核心概念

## 本次只学这一点

灾难性遗忘不能靠感觉，必须有数字。标准做法是**通用基准回测**：

```
遗忘率 = (微调前分数 - 微调后分数) / 微调前分数 × 100%
```

实操要点：

1. **选定一个基准集合**，覆盖你想保住的每个能力维度。通用选择如 MMLU（知识）、C-Eval（中文知识）、GSM8K（数学推理）、HellaSwag（常识推理）、以及一个自建的中文指令遵循小集；
2. **用同一套评测代码、同一套提示词、同一解码参数**跑微调前后的模型。评测配置不一致导致的「遗忘」比真实遗忘还多；
3. **优先看相对下降，而不是绝对值**。不同基准的绝对分差很大，只有相对下降率可横向比较；
4. **单样本对比比总分更有诊断价值**：微调前对、微调后错的样本（regression set）必须逐条看，它们通常比总分揭示更多问题；
5. **成本优化**：全量跑基准很贵，工程上常用 200~500 条的分层抽样子集做「遗忘哨兵集」，只有哨兵报警时才跑全量。

**基准集合怎么搭配**（一个可直接抄的组合）：

| 能力维度 | 建议基准 | 规模 | 为什么选它 |
|---|---|---|---|
| 百科知识 | MMLU / C-Eval | 各 200 题抽样 | 最容易被领域微调破坏的维度 |
| 数学推理 | GSM8K | 100~200 题 | 对参数漂移极敏感，是很好的「矿井里的金丝雀」 |
| 常识推理 | HellaSwag / 自建 | 200 题 | 检测语言建模能力是否退化 |
| 指令遵循 | 自建 50~100 条 | —— | 检测格式指令、拒答、长度约束是否还遵守 |
| 目标语言能力 | 自建中文写作/改写任务 | 50 条 | 检测中英夹杂、句式僵化 |

经验阈值（仅供参考）：

| 相对下降 | 判读 | 建议动作 |
|---|---|---|
| < 2% | 正常波动 | 通过，继续观察 |
| 2% ~ 5% | 轻度遗忘 | 记录；检查数据配比与学习率 |
| 5% ~ 15% | 中度遗忘 | 引入回放数据或降低 LoRA 秩/学习率后重跑 |
| > 15% | 严重遗忘 | 停止上线；重做数据混合，或改用更保守的微调策略 |

**一个常被忽略的细节：评测的方差**。生成式基准在 temperature > 0 时的单次运行方差可达 1~3 个点，直接比较两次运行的分数会得出错误结论。做法是固定 temperature=0（贪心解码），或者跑 3 次取均值并报告标准差。
