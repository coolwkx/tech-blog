# Q1. 微调到底在做什么？它和预训练、RAG、提示词工程分别解决什么问题？

> **学习目标**：能够解释「Q1. 微调到底在做什么？它和预训练、RAG、提示词工程分别解决什么问题？」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：Transformer 基本结构、SFT 流程、LoRA/QLoRA 的原理、显存构成（权重/梯度/优化器状态/激活/KV cache）、常用评测指标。
>
> **所属主题**：-微调面试专题 · 第一组：概念与决策

## 本次只学这一点

<details markdown="1">
<summary markdown="1">参考答案</summary>

**30 秒版**：预训练是学语言与通用知识，微调是用少量监督数据把模型的**输出分布与行为**调整到特定任务上；提示词工程不改参数、只改上下文；RAG 是为模型补上它**不知道的、会过期的**外部知识。三者解决的是不同问题，经常组合使用。

**展开版**：

- **预训练**：在海量无标注语料上做自监督学习，获得语言能力与压缩在参数里的世界知识。它决定的是模型的**能力上限**。
- **微调（SFT）**：用指令-回答对继续训练，改变的是模型的**条件输出分布**——即「面对这类输入，应该输出什么形式和风格」。它擅长教格式、风格、领域语言、任务范式，不太擅长注入大量新事实。
- **提示词工程**：不改参数，靠指令、示例、格式约束引导模型。成本最低、迭代最快，但受限于基座模型已有能力，且无法保证输出格式的绝对稳定。
- **RAG**：把外部文档检索后塞进上下文。适合知识频繁更新、需要引用出处、知识量远超参数容量的场景。

**选型判断**：

| 需求 | 首选 |
|---|---|
| 模型不知道这个知识 | RAG |
| 模型知道但输出格式/风格不对 | 提示词工程 → 不够则 SFT |
| 需要固定格式、低延迟、可离线部署 | SFT（通常配 LoRA） |
| 需要引用出处、知识每天变 | RAG |
| 需要改变模型的行为偏好（更有礼貌、更少幻觉） | 偏好对齐（DPO/RLHF），不单是 SFT |

**追问预判**：
- *「SFT 能不能教新知识？」* —— 能，但效率很低。知识密集型内容更适合 RAG；SFT 教知识容易变成「背下来」，泛化差，还容易诱发幻觉。
- *「RAG 和微调能不能只用一种？」* —— 能，但要看瓶颈在哪。如果检索已经给出正确上下文而模型仍然答错，那是模型能力/格式问题，该微调；如果检索根本没召回正确文档，微调救不了。
