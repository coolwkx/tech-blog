# Q2. 什么时候必须全参微调，什么时候 LoRA 就够了？

> **学习目标**：能够解释「Q2. 什么时候必须全参微调，什么时候 LoRA 就够了？」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：Transformer 基本结构、SFT 流程、LoRA/QLoRA 的原理、显存构成（权重/梯度/优化器状态/激活/KV cache）、常用评测指标。
>

## 本次只学这一点

<details markdown="1">
<summary markdown="1">参考答案</summary>

**30 秒版**：默认用 LoRA；只有在「数据量足够大（十万级+）、任务与预训练分布差异很大、且 LoRA 已经调到极限仍不达标」时才考虑全参。全参的优势是上限高，代价是显存、存储（每份权重几十 GB）和灾难性遗忘风险都更高。

**展开版**——判断维度有四个：

| 维度 | 倾向 LoRA | 倾向全参 |
|---|---|---|
| 数据量 | < 5 万条 | > 10 万条且质量高 |
| 任务与基座差距 | 同语言同领域，学格式/风格 | 跨语言、跨模态、全新任务范式 |
| 算力预算 | 单卡 / 消费级显卡 | 多卡且允许长时间训练 |
| 部署 | 需要多任务热切换（LoRA 可插拔） | 只服务一个任务，可接受独立权重 |

**LoRA 不够用的典型信号**：

1. 训练 loss 正常下降但验证指标长期卡在平台，加大 r、加长训练都不动；
2. 任务需要模型建立全新的词汇/符号体系（例如自定义的领域标记语言）；
3. 需要同时改变很多层的表示（不只是注意力的投影矩阵）。

**工程上的折中**：先做 LoRA 基线，同时用同一批数据跑一个「只训最后 N 层」的全参对照。如果两者差距在 1 个点以内，就用 LoRA 上线——省下的存储与运维成本是实打实的。

**追问预判**：
- *「LoRA 和全参的效果差距一般有多大？」* —— 在常见领域微调任务上通常在 0~2 个点以内，很多场景 LoRA 甚至更好（因为正则化效应更抑制过拟合）。差距大的场景通常是数据量大、任务差异大。
- *「LoRA 能合并进基座吗？」* —— 可以，`W' = W + (alpha/r) * BA`，合并后推理零额外延迟。代价是失去「一个基座挂多个 LoRA」的灵活性。
