# Q5. LoRA 的 alpha 和 r 该怎么调？

> **学习目标**：能够解释「Q5. LoRA 的 alpha 和 r 该怎么调？」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：Transformer 基本结构、SFT 流程、LoRA/QLoRA 的原理、显存构成（权重/梯度/优化器状态/激活/KV cache）、常用评测指标。
>
> **所属主题**：-微调面试专题 · 第二组：方法与参数

## 本次只学这一点

<details markdown="1">
<summary markdown="1">参考答案</summary>

**30 秒版**：`r` 控制表达力（低秩子空间维度），`alpha` 只控制缩放幅度 `alpha/r`。常用做法是固定 `alpha = 2r`，只扫 `r ∈ {4, 8, 16, 32, 64}`；数据少、任务简单取小 r，任务复杂、数据多取大 r。经验默认起点是 `r=8`、`alpha=16`。

**展开版**：

| r | 可训练参数 | 适用场景 | 风险 |
|---|---|---|---|
| 4 | 极少 | 风格/格式微调、数据 < 5k | 欠拟合，任务学不动 |
| 8 | 少 | **默认起点** | 平衡最好 |
| 16 ~ 32 | 中 | 领域知识密集型任务、数据 1 万~10 万 | 遗忘风险上升 |
| 64 ~ 128 | 较多 | 接近全参的场景、数据 10 万+ | 过拟合、遗忘、成本上升 |

调参顺序建议：

```
① 先固定 r=8、alpha=16，把学习率、epoch、数据配比调好
② 再扫 r（每次只改 r，并把 alpha 设为 2r 保持缩放不变）
③ 如果指标对 r 完全不敏感 → 瓶颈不在容量，而在数据或任务定义
④ 如果 r 越大越好且还没收敛 → 说明任务确实需要更多容量，考虑全参
```

**容易踩的坑**：

- **只调 r 不调 alpha**：`alpha/r` 变了，有效学习率也变了，你其实是在同时改两个变量，实验结论不可解释；
- **忘了 target_modules**：只加 `q_proj` 和加全部线性层，参数量差好几倍，效果差异可能比 r 的影响还大；
- **忘了 dropout**：LoRA 层通常配 `lora_dropout=0.05 ~ 0.1`，小数据集上对稳定性帮助明显。

**追问预判**：
- *「alpha 调大有什么代价？」* —— 放大 `BA` 的贡献，等效于提高有效学习率。太大会不稳定甚至发散，太小则学不动。它不能替代学习率来调。
- *「r 越大越容易遗忘吗？」* —— 是。r 越大，可表达的参数更新空间越大，越容易偏离预训练权重。这是一个明确的容量-保持权衡。
