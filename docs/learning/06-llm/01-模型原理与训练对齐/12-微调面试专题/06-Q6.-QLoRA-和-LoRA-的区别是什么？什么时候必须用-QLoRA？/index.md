# Q6. QLoRA 和 LoRA 的区别是什么？什么时候必须用 QLoRA？

> **学习目标**：能够解释「Q6. QLoRA 和 LoRA 的区别是什么？什么时候必须用 QLoRA？」的机制或步骤，并用本节材料验证理解。
>

## 本次只学这一点

<details markdown="1">
<summary markdown="1">参考答案</summary>

**30 秒版**：QLoRA = 4-bit 量化基座 + LoRA。基座权重压到 4-bit（NF4）且冻结，LoRA 旁路仍用 FP16/BF16 训练；显存大幅下降，效果接近 16-bit LoRA。当显存不够、或想在单张消费级显卡上微调 7B/13B 模型时用它。

**展开版**——QLoRA 的三个关键技术：

| 技术 | 作用 |
|---|---|
| **NF4**（4-bit NormalFloat） | 一种对正态分布权重信息论最优的 4-bit 数据类型，比普通 INT4 精度损失更小 |
| **双重量化**（double quantization） | 对量化常数本身再做一次量化，每参数再省约 0.37 bit |
| **Paged Optimizer** | 优化器状态在显存吃紧时换出到 CPU 内存，避免 OOM 峰值 |

**LoRA vs QLoRA 对比**：

| 维度 | LoRA | QLoRA |
|---|---|---|
| 基座精度 | FP16/BF16 | 4-bit NF4（冻结） |
| 可训练部分 | FP16/BF16 | FP16/BF16（计算时反量化） |
| 7B 模型训练显存 | 约 16~20 GB | 约 6~10 GB |
| 训练速度 | 快 | 慢 20%~40%（反量化开销） |
| 效果 | 基线 | 与 LoRA 接近，通常差 0~1 个点 |
| 推理 | 合并后无额外开销 | 需反量化或合并；也可用 4-bit 推理省显存 |

**什么时候必须用**：

- 单卡 24 GB 想训 13B 以上；
- 单卡 16 GB 想训 7B；
- 显存受限但可以接受更长训练时间。

**追问预判**：
- *「QLoRA 训练慢为什么还能接受？」* —— 因为它把「能不能训」变成了「多久训完」。对于算力受限的团队，可训练性优先于速度。
- *「QLoRA 的 4-bit 量化会影响最终效果吗？」* —— 通常影响很小，因为梯度只作用在 LoRA 上，量化误差主要体现在前向计算中。但极端小样本任务上可能更敏感，值得实测。
- *「能用 INT8 吗？」* —— 可以（`load_in_8bit`），显存收益小于 4-bit，但精度损失更小，是一个中等保守的选择。
