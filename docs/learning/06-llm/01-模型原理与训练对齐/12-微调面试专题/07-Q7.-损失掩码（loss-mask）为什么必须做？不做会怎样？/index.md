# Q7. 损失掩码（loss mask）为什么必须做？不做会怎样？

## 本次只学这一点

<details markdown="1">
<summary markdown="1">参考答案</summary>

**30 秒版**：因为不是所有 token 都是「要模型学会生成的」。多轮对话里 system prompt 和 user 输入是上下文，不是监督目标；只在 assistant 的回复上算 loss，模型才会专注学「怎么回答」而不是「怎么复述提问」。不做掩码会带来三个问题：学到复述用户、对训练轮次过拟合、loss 数值被稀释。

**展开版**——三类必须掩码的位置：

| 位置 | 该不该算 loss | 不掩码的后果 |
|---|---|---|
| system prompt | 否 | 模型可能学着生成 system 内容 |
| user 输入 | 否 | 模型学会复述问题，甚至自问自答 |
| assistant 回复 | **是** | —— |
| padding token | 否 | loss 被大量无意义位置稀释，梯度被拉偏 |
| 多轮中较早的轮次 | 通常保留（因果注意力下不应看到未来） | 视角不同，见下 |

**实现要点**：

```python
# labels 中把不计算 loss 的位置置为 -100（PyTorch CrossEntropyLoss 的 ignore_index）
labels = input_ids.clone()
labels[~assistant_token_mask] = -100

# 也可以按「轮次级」掩码：只保留最后一轮 assistant
```

**为什么不是「越多监督越好」**：让模型预测 user 的输入，等价于在训练一个「对话续写器」，它会把大量算力花在建模用户的语言习惯上，而不是学回答。在数据量小的时候，这种监督噪声的杀伤力非常明显——表现为模型开始模仿用户的错别字和口语风格。

**追问预判**：
- *「如果我把 user 也算了 loss，指标一定是变差吗？」* —— 不一定立刻变差，但会浪费容量、并让模型更倾向于「续写」而不是「回答」，在多轮场景里尤其容易出现自问自答。
- *「多轮对话该只训最后一轮，还是所有 assistant 轮次都训？」* —— 推荐所有 assistant 轮次都训（信息利用率高），但要用因果注意力保证不看未来。只训最后一轮适合「最后一轮才是目标任务」的场景，样本效率低。
