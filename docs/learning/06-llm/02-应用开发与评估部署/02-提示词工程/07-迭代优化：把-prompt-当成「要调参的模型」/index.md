# 迭代优化：把 prompt 当成「要调参的模型」

> **学习目标**：能够解释「迭代优化：把 prompt 当成「要调参的模型」」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：大模型基本概念、In-context learning（见《01-大模型基础与演进》）、Python 字符串格式化与 JSON 解析。
>
> **所属主题**：-提示词工程 · 关键机制

## 本次只学这一点

Prompt 的一次成功率可能较高，但仍**需要通过多次迭代找到最适合应用的形式**；设计高效 prompt 也需要多版本试错。

| 步骤 | 动作 |
|---|---|
| 1. 初步想法 | 编写初版 prompt（满足「清晰」与「给足思考时间」两条原则） |
| 2. 输入模型 | 把它交给模型执行 |
| 3. 结果检查 | 分析输出问题，定位 prompt 缺陷 |
| 4. 循环迭代 | 改进 prompt，重复直到「适合应用」 |

**完整案例：椅子产品说明书 → 电商营销文案**

| 轮次 | 发现的问题 | 解决方案（改 prompt） | 结果 |
|---|---|---|---|
| 初始 | 输出内容过长，不适合做简明电商广告语 | 在 prompt 中加长度限制：「使用最多 50 个词」 | 文案明显缩短 |
| 第 1 次迭代 | 文案偏重风格与氛围，技术细节少，**与目标受众关注点不符** | 明确受众与侧重：「该描述面向家具零售商，应具有技术性质，并侧重于产品的材料构造」，并要求末尾附 7 字符产品 ID | 内容转向材质、工艺、结构 |
| 第 2 次迭代 | 需要抽取尺寸信息并直接可用于网页 | 要求提取尺寸组织成表格，指定表名「产品尺寸」、列含义（名称 / 英寸测量值），并**格式化为 HTML 放在 `<div>` 中** | 直接产出可贴进网页的结构 |

**长度限制的一个工程细节**：设置长度要求时模型输出**不总能精确符合**，但基本能控制在可接受误差范围内。
原因是语言模型计算文本长度依赖分词器，而分词器在字符统计上不具备完美精度。
**实践建议**：不要依赖 prompt 做硬性长度控制（例如"最多 30 个汉字"）；
需要严格限制时应**在代码侧截断或校验重试**。
