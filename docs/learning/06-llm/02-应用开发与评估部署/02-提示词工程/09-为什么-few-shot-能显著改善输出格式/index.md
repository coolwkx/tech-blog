# 为什么 few-shot 能显著改善输出格式

> **学习目标**：能够解释「为什么 few-shot 能显著改善输出格式」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：大模型基本概念、In-context learning（见《01-大模型基础与演进》）、Python 字符串格式化与 JSON 解析。
>
> **所属主题**：-提示词工程 · 关键机制

## 本次只学这一点

| 层面 | zero-shot 的问题 | few-shot 提供的信息 |
|---|---|---|
| 任务定义 | 模型可能误解「分类」「抽取」的具体含义 | 用一个完整样例演示「输入形态 → 输出形态」 |
| 输出格式 | 格式漂移，句子里带解释文字 | 示例直接锚定输出词表与结构（如只回答「是/不是」） |
| 类别边界 | 相似类别容易混淆（公司公告 vs 财务公告） | 每类给一个样例，用实例划清边界 |
| 语言风格 | 语气不受控 | 示例起到「风格样板」作用 |

**成本视角**：few-shot 会增加输入 token 数（更长 prompt、更高费用与延迟），但**换来的是免训练**——
不需要标注数据、不需要训练、不需要维护多套权重，改 prompt 就能换任务。这是提示工程在业务侧最大的价值。
