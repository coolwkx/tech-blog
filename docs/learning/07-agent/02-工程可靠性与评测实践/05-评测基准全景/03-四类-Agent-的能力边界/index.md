# 四类 Agent 的能力边界

> **学习目标**：能够解释「四类 Agent 的能力边界」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：[01-为什么Agent评测比LLM评测难](../../../../../07-agent/05-评测/01-为什么Agent评测比LLM评测难.md) 的环境契约、[03-评测方法-单元测试与LLM即裁判](../../../../../07-agent/05-评测/03-评测方法-单元测试与LLM即裁判.md) 的判题分层与显著性检验。
>
> **所属主题**：-评测基准全景 · 核心概念

## 本次只学这一点

| 类型 | 核心能力 | 典型基准 | 主要失败模式 | 为什么不能迁移到另一类 |
| --- | --- | --- | --- | --- |
| 编码 Agent | 代码理解、跨文件编辑、遵循仓库约定、跑测试 | SWE-bench / Verified | 环境装不上依赖；改动破坏既有行为；只改测试 | 代码任务有**可执行的验证器**，其他领域没有；浏览器/桌面任务的核心难点（视觉定位、页面漂移）在代码里不存在 |
| 浏览器 Agent | 视觉/结构定位、表单填写、跨页状态跟踪 | WebArena / Mind2Web / WebVoyager | 页面改版导致选择器失效；长流程中途丢失目标 | 依赖 DOM/视觉，无法处理命令行的文件系统操作；对无界面的 API 任务收益为零 |
| 桌面操作 Agent | GUI 操作、多应用协同、窗口管理 | OSWorld / AndroidWorld | 截图误判；单步失败即整链崩溃 | 步骤成本极高（每次点击都要截图推理），不适合高吞吐的文本/代码任务 |
| 通用助手 | 多工具编排、信息整合、长程规划 | GAIA / τ-bench / AgentBench | 中途放弃；把工具结果误用；忽略成本 | 通用性以「每项都不精」为代价，专项任务的准确率远低于专用 Agent |

结论：**「Agent 能力」不是一个标量。** 一个在 SWE-bench 上 70% 的模型，在 WebArena 上可能只有 20%——不是因为它「更笨」，而是因为两类任务调用的能力几乎不重叠。
