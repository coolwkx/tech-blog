# benchmark 分数的四层前提

> **学习目标**：能够解释「benchmark 分数的四层前提」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：[01-为什么Agent评测比LLM评测难](../../../../../07-agent/05-评测/01-为什么Agent评测比LLM评测难.md) 的环境契约、[03-评测方法-单元测试与LLM即裁判](../../../../../07-agent/05-评测/03-评测方法-单元测试与LLM即裁判.md) 的判题分层与显著性检验。
>
> **所属主题**：-评测基准全景 · 关键机制

## 本次只学这一点

```text
分数 = f(模型能力, 环境层, 工具层, 预算层, 判题层)

环境层：镜像版本 / 依赖与数据快照 / 网络可达性 / 沙箱重置策略
工具层：可用工具集与版本（有无浏览器、有无 shell、shell 权限范围、有无代码执行）
预算层：max_steps / 超时 / 是否允许重试 / 是否允许多次采样取最优
判题层：判题器实现与版本 / 判题器是否对被测系统可见 / 部分完成的计分方式
```

逐项解释为什么它们都会让分数不可比：

| 层 | 变化示例 | 对分数的影响方向 |
| --- | --- | --- |
| 环境层 | 依赖版本升级让某些任务自动就能通过 | 分数上升，但能力没变 |
| 环境层 | 网络被限制导致搜索类任务失败 | 分数下降，像是能力退化 |
| 工具层 | 从「只能读文件」放开到「能执行代码」 | 分数大幅上升，掩盖了模型本身的推理能力 |
| 工具层 | shell 权限从只读改成可写 | 分数上升，但引入了越权风险（判题层未必能发现） |
| 预算层 | `max_steps` 从 30 提到 100 | 分数上升，成本与延迟同时上升 |
| 预算层 | 允许 k 次采样取最优 | 分数变成 `pass@k`，不能与单次结果比较 |
| 判题层 | 判题器从严格匹配改成语义等价 | 分数上升，可能掩盖格式遵从问题 |
| 判题层 | 判题器/测试文件对被测系统可见 | 分数被 reward hacking 抬高 |
