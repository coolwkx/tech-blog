## 本次只学这一点

项目自述的生态位是三件套中的「可信评测」：

```text
browser-agent-runtime-lite   →  提供可审计的执行闭环（证据门控、有限恢复）
agent-eval-lab               →  接收轨迹，区分进程/动作/目标完成，输出归因与统计   ← 本项目
open-source-research-agent   →  具体应用案例，产出真实业务轨迹
```

这个切分很干净：**执行侧只负责"把事做出来并留下可核验的痕迹"，评测侧只负责"判断痕迹是否构成完成"。** 两侧通过轨迹格式解耦，所以评测器可以在 Agent 完全不改的情况下先接进来——这一点对"给一个已经在跑的 Agent 补评测"（见 [04 篇](../../../../../07-agent/06-评测实战/04-给一个真实Agent补评测.md)）至关重要。
