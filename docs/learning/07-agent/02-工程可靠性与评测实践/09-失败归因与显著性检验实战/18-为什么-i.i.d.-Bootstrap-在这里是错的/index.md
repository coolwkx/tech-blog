# 为什么 i.i.d. Bootstrap 在这里是错的

> **学习目标**：能够解释「为什么 i.i.d. Bootstrap 在这里是错的」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：[01 篇](../../../../../07-agent/06-评测实战/01-项目复盘-AgentEvalLab.md) 的评测器判定顺序与证据信任链、[02 篇](../../../../../07-agent/06-评测实战/02-用Manifest保证评测可复现.md) 的 `taskId + repeatId + seed` 配对主键、二项分布与 Bootstrap 重采样的基础。
>
> **所属主题**：-失败归因与显著性检验实战 · 聚类 Bootstrap CI：重采样单位必须是 taskId

## 本次只学这一点

Bootstrap 的合法性建立在"样本可交换"（exchangeable）的假设上。假设每个观测都是从同一个总体独立抽取的，那么有放回地重采样观测就能模拟"重新做一次实验"。

但在 Agent 评测里，**同一个任务的多次 `repeat`/`seed` 根本不独立**：它们共享同一套页面结构、同一条目标描述、同一种失败模式。一个难任务很可能 5 次重复全失败，一个易任务很可能 5 次全成功——簇内相关性接近 1。

i.i.d. Bootstrap 把"50 个任务 × 2 次重复"当成 100 个独立样本，于是：

```text
有效样本量被虚增约 2 倍
标准误被低估约 √2 倍
置信区间宽度被低估约 30%
```

后果是**假阳性**：一个不显著的提升会被包装成显著的。
