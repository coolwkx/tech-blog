# 业务问题示例

> **学习目标**：能够解释「业务问题示例」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：Python 基础、向量检索的基本概念（Embedding / 相似度 / Top-K）、`pip` 环境管理、Streamlit 的最简用法。
>
> **所属主题**：项目实战笔记 05：企业内部制度问答助手 · 项目目标与业务背景

## 本次只学这一点

知识库内容（`员工手册.pdf`）：

```text
公司名称：示例科技有限公司 总部：北京市 制度范围：员工手册与合规制度
考勤管理：
员工编号：
入职日期：
所属部门：市场部
试用期结束日期：
打卡方式：指纹打卡
直属上级：部门负责人
办公地点：北京
常驻城市：上海
年假天数： 天
报销制度：
报销类型：差旅费
住宿标准：一线城市 元/晚
审批人：部门负责人
报销时限：费用发生后 天内提交
到账时间： 个工作日
```

用户的自然语言问题：

```text
我的年假有多少天？报销多久能到账？
```

这个问题**跨越了两个语义段落**（"年假天数"在考勤段，"到账时间"在紧邻行），是典型的"需要多块信息拼接"的查询。它恰好能暴露 RAG 的一个核心难点：**单块检索能否覆盖跨段的复合问题**。
