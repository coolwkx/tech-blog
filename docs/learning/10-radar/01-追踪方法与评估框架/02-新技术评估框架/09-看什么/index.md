# 看什么

> **学习目标**：能够解释「看什么」的机制或步骤，并用本节材料验证理解。
>
> **前置知识**：先了解本主题的基本术语；示例环境与背景见综合原文。
>
> **所属主题**：新技术评估框架 · D4 工程可用性（20%）

## 本次只学这一点

| 检查项 | 低代价特征 | 高代价特征 |
| --- | --- | --- |
| 依赖 | 一个 HTTP 接口或一个 SDK | 需要专用硬件、专用运行时或私有协议 |
| 部署形态 | 云 API 与本地权重都有 | 只有云 API，且数据不能出境 |
| 学习曲线 | 概念少、可类比已有工具 | 需要先理解一套新术语与新模式 |
| 文档与错误处理 | 有 schema、有限流与重试说明 | 文档只有营销页 |
| 可回退性 | 能按请求灰度、可随时切回原方案 | 一旦接入就难以拆出 |

## 验证理解

- 合上正文，用自己的话解释本知识点解决的问题及适用边界。
- 若本节含代码、公式或流程，先预测结果，再运行、推导或逐步追踪；项目片段需要沿用原文的依赖与数据。
- 如果缺少变量、术语或完整代码，请查阅[综合原文](../../../../../10-radar/01-追踪方法/02-新技术评估框架.md)；代码片段不等同于独立可运行项目。
