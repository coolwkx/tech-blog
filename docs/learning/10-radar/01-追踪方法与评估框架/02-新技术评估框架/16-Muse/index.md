## 本次只学这一点

| 维度 | 分数 | 打分理由 |
| --- | --- | --- |
| D1 技术机制 | 4 | 机制增量不在模型，而在外部：每用户独立持久化执行环境 + 与用户资产隔离的安全区 + 外部审批组件 + 凭据代持；模型侧为面向 Agent 训练的原生多模态模型 |
| D2 能力变化 | 3 | 单项能力（浏览、工具调用、订票、发邮件）此前已有产品展示过；变化主要来自权限与执行环境的架构，加上应用层整合带来的完成度 |
| D3 成熟度 | 3 | 已公开上线但仅限两个国家，连接器生态刚起步，上线两周内即出现平台封禁与权限争议 |
| D4 工程可用性 | 2 | 作为消费级产品无法自主接入；其底层模型与架构思路可借鉴，但整套运行时不可复用 |
| D5 对我们的影响 | 4 | 权限分层、凭据代持、敏感操作二次确认、执行环境隔离，都能直接映射到我们的 Agent 安全设计 |
| **综合** | **3.15** | **C 持续观察** |

计算过程：`4×0.25 + 3×0.25 + 3×0.20 + 2×0.20 + 4×0.10 = 1.00 + 0.75 + 0.60 + 0.40 + 0.40 = 3.15`。

> 说明：公式结果 **3.15 / C 级**。但它**已写成条目**——因为 C 级只约束「投入多少工程资源」，不约束「是否值得记录」。D1 与 D5 的机制价值独立于它当前是否可用。这正是不把等级当作收录门槛的原因。
