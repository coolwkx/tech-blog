## 本次只学这一点

| 编号 | 待验证内容 | 为什么存疑 | 需要什么材料才能解决 |
| --- | --- | --- | --- |
| V1 | **待验证**：准确率是否真的与前沿生成模型「大致持平」 | 官方未公布准确率对比；独立测试样本量只有 24 份文档，作者自己也承认在统计上无差别 | 更大样本、多语种的独立评测；官方公开评测数据集与评测脚本 |
| V2 | **待验证**：概率校准是否在全域成立 | 独立测试发现校准方向正确，但另有第三方项目专门测试校准并给出「饱和分裂」等更细的结论，说明校准可能只在部分区间成立 | 公开的可靠性图与 ECE，覆盖多个任务类型与概率区间 |
| V3 | **待验证**：模型架构、参数量、训练细节 | 官方未公开 RLCD 的奖励函数、网络架构与校准方法 | 官方技术报告或论文 |
| V4 | **待验证**：低延迟在高并发下能否维持 | 「输出免费 + 极低输入价」的定价与非标准形态，被质疑依赖融资补贴；无高并发数据 | 官方限流说明与第三方压测结果 |
| V5 | **待验证**：官方性能倍数（约 193.6 倍 / 444.6 倍）的可复现性 | 官方自认是「实际收益的上限」，评测工作流由公司内部团队编写，参考答案由两个大模型取平均 | 按官方公开的四个工作流自行复算 |
| V6 | **待验证**：中文长文本下的精度与有效输入长度 | 官方称擅长英语、其他语言准确率不一；第三方测试发现某非英语语种每 Token 字符数偏低，导致标称状态上限能容纳的有效内容大幅缩水，中文情况未测 | 在中文任务上做同题对比，并实测不同长度下的精度衰减曲线 |
| V7 | **待验证**：第三方复现究竟验证了什么 | 复现方明确表示是「基于公开文档的输入范式与评估逻辑」做的分析，并非对原始实现的还原；它验证的是接口行为与工程可行性，不是原始模型能力 | 官方与复现方都公开对比数据 |
| V8 | **待验证**：定价与开放状态 | 处于早期访问、需申请，服务在单一区域；「输出免费」是阶段性政策还是长期定价 | 官方定价页的正式条款 |
